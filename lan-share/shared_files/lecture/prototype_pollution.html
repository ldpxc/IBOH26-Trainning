Prototype Pollution

Đặc thù JavaScript/Node.js: khi app "trộn" (merge) object từ input người dùng vào object nội bộ không cẩn thận, bạn có thể thêm 1 thuộc tính đặc biệt tên __proto__ — không chỉ sửa 1 object, mà sửa khuôn mẫu chung mà MỌI object cùng loại trong chương trình kế thừa theo.

Prototype Pollution là gì, để làm gì?

Trong JavaScript, mọi object (trừ trường hợp đặc biệt) đều có 1 "khuôn mẫu cha" chung tên Object.prototype — mọi thuộc tính thêm vào khuôn mẫu này sẽ tự động xuất hiện trên MỌI object khác trong toàn bộ chương trình, kể cả object được tạo ra SAU đó, ở chỗ code hoàn toàn khác. Nếu app dùng hàm "merge object sâu" (deep merge) không cẩn thận với input người dùng, bạn gửi key đặc biệt __proto__ để "chui" vào tận khuôn mẫu gốc này, thêm thuộc tính (vd isAdmin: true) ảnh hưởng tới MỌI object {} trong toàn chương trình, dù chưa từng tồn tại lúc bạn gửi request.

Nếu chỉ nhớ một điều Khác Mass Assignment (chỉ ảnh hưởng 1 object/bản ghi cụ thể), Prototype Pollution ảnh hưởng TOÀN BỘ chương trình — mọi object trống {} được tạo SAU thời điểm bạn ô nhiễm cũng tự nhiên "thừa kế" field độc đó, kể cả ở phần code hoàn toàn không liên quan tới nơi bạn gửi payload.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Prototype (khuôn mẫu) — trong JavaScript, mỗi object có 1 "object cha" nó tự động tham chiếu tới để tìm thuộc tính/hàm khi không tìm thấy trên chính nó. Mặc định, mọi object literal ({}) đều có cha chung là Object.prototype.
__proto__ — thuộc tính đặc biệt (accessor) cho phép truy cập/SỬA trực tiếp vào prototype của 1 object — đây chính là "cửa sau" bị lợi dụng: viết vào obj.__proto__.x = 1 tương đương sửa Object.prototype.x = 1, ảnh hưởng MỌI object.
Deep merge — hàm trộn 2 object đệ quy (merge cả các object lồng bên trong, không chỉ cấp ngoài cùng) — các thư viện phổ biến: _.merge() (lodash), deepmerge, hoặc code tự viết đệ quy. Nếu hàm này không chặn key __proto__, nó sẽ đệ quy luôn cả vào prototype thật.

Code hay viết (deep merge tự viết, thiếu chặn key nguy hiểm):

// Node.js
function merge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object') {
      target[key] = target[key] || {};
      merge(target[key], source[key]);   // !! không check key === '__proto__'
    } else {
      target[key] = source[key];
    }
  }
}
merge({}, req.body);   // req.body = {"__proto__": {"isAdmin": true}} -> ô nhiễm!
02 / VÌ SAO LỖ HỔNG TỒN TẠI

JavaScript không phân biệt "key dữ liệu thường" với "key điều khiển ngôn ngữ"

Với hầu hết key ("name", "age"), vòng lặp for...in chỉ đơn giản đọc/ ghi giá trị như dữ liệu thường. Nhưng __proto__ và constructor.prototype là key đặc biệt có ý nghĩa với chính ngôn ngữ JavaScript — viết vào chúng không tạo ra 1 "field dữ liệu tên __proto__" như mong đợi, mà thực sự thay đổi cơ chế kế thừa object. Hàm merge đệ quy tự viết (hoặc thư viện cũ chưa vá) coi mọi key như nhau, không có bước lọc ra những key "đặc biệt" này trước khi gán.

Client-side Prototype Pollution (biến thể khác, trong trình duyệt)

Tương tự nhưng xảy ra ở JavaScript phía client (code chạy trong trình duyệt), qua URL params hoặc JSON parse không an toàn — ô nhiễm prototype rồi tìm "gadget" (đoạn code sẵn có dùng property bị ô nhiễm) để dẫn tới DOM XSS. Phức tạp hơn, cần phân tích code JS phía client cụ thể của từng app để tìm gadget phù hợp — không có công thức chung.
