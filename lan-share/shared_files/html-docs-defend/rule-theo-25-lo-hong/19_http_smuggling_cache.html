Mẫu Luật Phòng Thủ: HTTP Request Smuggling & Cache Poisoning

  • Nguồn tham chiếu: attack/http_smuggling_cache.html
  • Nhóm OWASP CRS liên quan: attack-protocol (920xxx / 921xxx)
  • Dải Rule ID: 25900–25999 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Cao đối với CL.TE / TE.CL / TE.TE obfuscation, trùng header Content-Length, CRLF injection và unkeyed cache poisoning headers.

1. Dấu hiệu tấn công chính cần chặn

  • HTTP Request Smuggling: Gửi đồng thời cả Content-Length và Transfer-Encoding; gửi 2 header Content-Length trở lên; biến thể Transfer-Encoding bị obfuscate (vd Transfer-Encoding: xchunked, khoảng trắng lạ).
  • Web Cache Poisoning: Chèn các header unkeyed thường bị app phản chiếu vào link/HTML: X-Forwarded-Host, X-Forwarded-Scheme, X-Host, X-Forwarded-Server, Forwarded.
  • HTTP Response Splitting / CRLF: Chèn %0d%0a (\r\n) vào tham số hoặc header để tiêm thêm header HTTP.

2. Bộ luật ModSecurity v3 mẫu

# [25901] Chặn request gửi đồng thời cả Content-Length và Transfer-Encoding (CL.TE / TE.CL)
SecRule &REQUEST_HEADERS:Content-Length "@ge 1" \
    "id:25901,phase:1,pass,log,t:none,chain,msg:'Smuggling: Both Content-Length and Transfer-Encoding present',tag:'http-smuggling'"
    SecRule &REQUEST_HEADERS:Transfer-Encoding "@ge 1" "t:none"

# [25902] Chặn trùng lặp nhiều hơn 1 header Content-Length hoặc Transfer-Encoding
SecRule &REQUEST_HEADERS:Content-Length|&REQUEST_HEADERS:Transfer-Encoding "@gt 1" \
    "id:25902,phase:1,pass,log,t:none,msg:'Smuggling: Duplicate CL or TE header',tag:'http-smuggling'"

# [25903] Chặn biến thể Transfer-Encoding obfuscated (không đúng chuẩn chunked/gzip/deflate)
SecRule REQUEST_HEADERS:Transfer-Encoding "!@rx (?i)^(?:chunked|gzip|deflate|compress|br)(?:\s*,\s*(?:chunked|gzip|deflate|compress|br))*\z" \
    "id:25903,phase:1,pass,log,t:none,msg:'Smuggling: Obfuscated Transfer-Encoding value',tag:'http-smuggling',logdata:'TE=%{MATCHED_VAR}'"

# [25904] Chặn header hay dùng cho Cache Poisoning (kiểm tra kỹ xem proxy BTC có gắn X-Forwarded-Host không!)
SecRule REQUEST_HEADERS_NAMES "@rx (?i)^(?:X-Host|X-Forwarded-Server|X-Forwarded-Scheme|X-HTTP-Host-Override)\z" \
    "id:25904,phase:1,pass,log,t:none,msg:'CachePoison: Suspicious unkeyed host/scheme header',tag:'cache-poisoning',logdata:'%{MATCHED_VAR}'"

# [25905] Chặn CRLF injection (\r\n) trong URI và header đầu vào
SecRule REQUEST_URI|ARGS "@rx (?:%0[da]|%250[da])" \
    "id:25905,phase:2,pass,log,t:none,msg:'CRLF: Encoded CR/LF sequence detected',tag:'crlf',logdata:'%{MATCHED_VAR_NAME}'"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
25901 &REQUEST_HEADERS:Content-Length + &REQUEST_HEADERS:Transfer-Encoding Chặn request vi phạm RFC 7230 khi gửi đồng thời cả Content-Length và Transfer-Encoding — gốc rễ của CL.TE và TE.CL Smuggling. Rất cao
25902 &REQUEST_HEADERS:Content-Length\|&REQUEST_HEADERS:Transfer-Encoding Chặn request gửi 2 header Content-Length hoặc 2 header Transfer-Encoding trở lên (chống CL.CL và TE.TE). Rất cao
25903 REQUEST_HEADERS:Transfer-Encoding Chặn giá trị Transfer-Encoding bị bóp méo (xchunked, chunked;q=1, khoảng trắng lạ) chỉ cho phép đúng tên encoding chuẩn. Rất cao
25904 REQUEST_HEADERS_NAMES Chặn các header unkeyed thường dùng để đầu độc cache (X-Host, X-Forwarded-Server, X-Forwarded-Scheme, X-HTTP-Host-Override). Rất cao
25905 REQUEST_URI\|ARGS Chặn chuỗi CRLF mã hóa (%0d, %0a, %250d, %250a) dùng cho HTTP Response Splitting và tiêm header giả. Trung bình (tránh FP trên textarea)

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Bot SVC gửi form bình luận nhiều dòng chứa %0d%0a bị 25905 chặn nhầm

Form application/x-www-form-urlencoded khi có dấu xuống dòng trong <textarea> sẽ mã hóa thành %0d%0a. - Cách sửa 25905: Chỉ soi CRLF trên REQUEST_URI và các tham số ngắn hay bị đưa vào HTTP header (next, redirect, lang, filename), không soi toàn bộ ARGS:

# Bản sửa thực tế từ [25905] chỉ chặn CRLF trên URI và các tham số đưa vào header
SecRule REQUEST_URI|ARGS:next|ARGS:redirect|ARGS:lang|ARGS:filename "@rx (?:%0[da]|%250[da])" \
    "id:25905,phase:2,deny,status:403,log,t:none,msg:'CRLF: Encoded CR/LF in URI or header param',tag:'crlf',logdata:'%{MATCHED_VAR_NAME}'"

Ví dụ 2: App bị Cache Poisoning qua header X-Forwarded-Host mà proxy BTC KHÔNG tự gắn

Kiểm tra Traffic log ở request sạch của bot SVC: nếu không thấy header X-Forwarded-Host xuất hiện, bạn có thể thêm |X-Forwarded-Host vào 25904 để chặn triệt để.

5. Lưu ý tránh False Positive (SVC)

  • Cố ý không đưa X-Forwarded-Host hoặc X-Forwarded-For vào 25904 mặc định vì reverse proxy của BTC có thể tự chèn các header này.
  • Với 25901, 25902, 25903, nên bật deny,status:400,log sớm vì request HTTP hợp lệ không bao giờ vi phạm 3 quy tắc này.
