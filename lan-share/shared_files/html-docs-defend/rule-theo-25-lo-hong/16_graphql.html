Mẫu Luật Phòng Thủ: GraphQL Attacks

  • Nguồn tham chiếu: attack/graphql.html
  • Nhóm OWASP CRS liên quan: Không có rule chuyên sâu cho GraphQL (cần viết riêng).
  • Dải Rule ID: 25600–25699 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Cao (chặn Introspection, query batching dạng mảng, alias overloading và giới hạn độ sâu lồng nhau).

1. Dấu hiệu tấn công chính cần chặn

  • Introspection: Truy vấn __schema, __type, __typename để lộ toàn bộ schema/field ẩn (dùng graphql-cop / clairvoyance).
  • Batching Attack: Gửi mảng JSON [{"query":...}, {"query":...}, ...] để brute-force OTP/password trong 1 HTTP request.
  • Alias Overloading / DoS: Lặp hàng chục alias (a1:login(...) a2:login(...)) trong cùng 1 query.
  • GET Query CSRF / Bypass: Gửi mutation qua GET /graphql?query=mutation{...}.

2. Bộ luật ModSecurity v3 mẫu

# [25601] Chặn GraphQL Introspection (__schema / __type) trên endpoint GraphQL
SecRule REQUEST_FILENAME "@rx (?i)^/(?:api/)?(?:graphql|gql)/?$" \
    "id:25601,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'GraphQL: Introspection query blocked',tag:'graphql',logdata:'%{MATCHED_VAR}'"
    SecRule REQUEST_BODY|ARGS "@rx (?i)\b__(?:schema|type)\b" "t:none,t:urlDecodeUni"

# [25602] Chặn GraphQL Query Batching (body JSON bắt đầu bằng mảng [)
SecRule REQUEST_FILENAME "@rx (?i)^/(?:api/)?(?:graphql|gql)/?$" \
    "id:25602,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'GraphQL: Array query batching blocked',tag:'graphql'"
    SecRule REQUEST_BODY "@rx ^\s*\[" "t:none"

# [25603] Chặn gửi GraphQL mutation qua phương thức GET (chống CSRF/bypass)
SecRule REQUEST_FILENAME "@rx (?i)^/(?:api/)?(?:graphql|gql)/?$" \
    "id:25603,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'GraphQL: Mutation via GET disallowed',tag:'graphql'"
    SecRule REQUEST_METHOD "@streq GET" "t:none,chain"
    SecRule QUERY_STRING "@rx (?i)\bmutation\b" "t:none,t:urlDecodeUni"

# [25604] Chặn GraphQL lồng nhau quá sâu (> 6 cặp dấu {) chống DoS / circular query
SecRule REQUEST_FILENAME "@rx (?i)^/(?:api/)?(?:graphql|gql)/?$" \
    "id:25604,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'GraphQL: Excessive nesting depth',tag:'graphql'"
    SecRule REQUEST_BODY "@rx (?:\{[^{}]{0,120}){7,}" "t:none"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
25601 REQUEST_FILENAME + REQUEST_BODY\|ARGS Chặn truy vấn Introspection (__schema, __type) trên /graphql hoặc /api/graphql để đối thủ không đọc được danh sách field/mutation ẩn (chặn graphql-cop, clairvoyance). Rất cao
25602 REQUEST_FILENAME + REQUEST_BODY Chặn Query Batching dạng mảng JSON ([{...}, {...}]) dùng để brute-force mật khẩu/OTP trong 1 request. Cao (kiểm tra frontend có batch không)
25603 REQUEST_FILENAME + REQUEST_METHOD + QUERY_STRING Chặn gửi mutation qua HTTP GET (chống CSRF và bypass kiểm tra POST body). Rất cao
25604 REQUEST_FILENAME + REQUEST_BODY Chặn query lồng nhau từ 7 cấp dấu { trở lên để chống tấn công vòng lặp (Circular Query DoS) làm treo app/mất SVC. Cao

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Endpoint GraphQL nằm ở đường dẫn khác (/v2/query)

Trên Traffic log thấy app gọi POST /v2/query thay vì /graphql. - Cách sửa: Đổi regex route ở dòng đầu của 25601–25604 từ ^/(?:api/)?(?:graphql|gql)/?$ thành ^/v2/query/?$.

Ví dụ 2: Đối thủ dùng Alias Overloading để brute-force đăng nhập (a1:login(...) a2:login(...) ...)

Nếu thấy trong Traffic log đối thủ gửi 1 request chứa nhiều lời gọi login( lặp lại bằng alias trong cùng 1 query:

# Rule bổ sung chặn gọi lặp nhiều mutation login/verify trong 1 query GraphQL
SecRule REQUEST_FILENAME "@rx (?i)^/(?:api/)?(?:graphql|gql)/?$" \
    "id:25610,phase:2,deny,status:403,log,t:none,t:normalizePath,chain,msg:'GraphQL: Alias overloading on auth mutation',tag:'graphql'"
    SecRule REQUEST_BODY "@rx (?i)(?:login|verifyOtp|resetPassword)\s*\([^)]{0,120}\)(?:[\s\S]{0,120}(?:login|verifyOtp|resetPassword)\s*\(){2,}" "t:none"

5. Lưu ý tránh False Positive (SVC)

  • Kiểm tra Traffic log xem frontend/bot có dùng __typename (Apollo Client hay tự thêm) không — vì vậy 25601 cố ý chỉ chặn __schema và __type, không chặn __typename.
  • Nếu app hợp lệ có query lồng 7–8 cấp, tăng ngưỡng {7,} ở 25604 lên {10,}.
