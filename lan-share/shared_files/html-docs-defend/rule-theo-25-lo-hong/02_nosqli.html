Mẫu Luật Phòng Thủ: NoSQL Injection (NoSQLi)

  • Nguồn tham chiếu: attack/nosqli.html
  • Nhóm OWASP CRS liên quan: attack-injection-generic / attack-sqli (942xxx)
  • Dải Rule ID: 24200–24299 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Rất cao (chặn trực tiếp toán tử $ của MongoDB và ép kiểu chuỗi).

1. Dấu hiệu tấn công chính cần chặn

  • Chèn toán tử MongoDB ($ne, $gt, $gte, $lt, $lte, $regex, $where, $in, $nin, $exists, $or, $and, $expr, $function) qua JSON body hoặc query bracket (username[$ne]=).
  • Biến trường chuỗi đơn (username, password) thành object/array trong JSON ({"password":{"$ne":""}}) khiến ModSecurity parse thành ARGS:json.password.$ne.

2. Bộ luật ModSecurity v3 mẫu

# [24201] Chặn tên tham số chứa toán tử NoSQL ($ne, $gt, $regex, $where...)
SecRule ARGS_NAMES "@rx (?i)(?:^|\.|\[)\$(?:ne|eq|gt|gte|lt|lte|in|nin|regex|where|exists|or|and|nor|not|expr|function|accumulator|options|elemMatch|jsonSchema)(?:\]|$|\.)" \
    "id:24201,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'NoSQLi: Operator in parameter name',tag:'nosqli',logdata:'%{MATCHED_VAR_NAME}'"

# [24202] Chặn JSON body thô chứa key bắt đầu bằng $ (bắt cả JSON lồng nhau)
SecRule REQUEST_HEADERS:Content-Type "@contains application/json" \
    "id:24202,phase:2,pass,log,t:none,t:lowercase,chain,msg:'NoSQLi: Mongo operator key in JSON body',tag:'nosqli',logdata:'%{MATCHED_VAR}'"
    SecRule REQUEST_BODY "@rx \"\$(?:ne|eq|gt|gte|lt|lte|in|nin|regex|where|exists|or|and|nor|not|expr|function|options)\"\s*:" "t:none"

# [24203] Chặn truyền mảng/object vào các trường đăng nhập phải là chuỗi phẳng
SecRule REQUEST_FILENAME "@rx (?i)^/api/(?:login|auth|signin)/?$" \
    "id:24203,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'NoSQLi: Nested object/array on login field',tag:'nosqli',logdata:'%{MATCHED_VAR_NAME}'"
    SecRule ARGS_NAMES "@rx ^json\.(?:username|user|email|password|pass)\." "t:none"

# [24204] Chặn biểu thức JS injection trong $where / mapReduce
SecRule ARGS "@rx (?i)(?:this\.(?:password|passwd|secret|flag)|sleep\s*\(\s*\d|function\s*\(\s*\)\s*\{)" \
    "id:24204,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'NoSQLi: JS expression probe',tag:'nosqli',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
24201 ARGS_NAMES (t:urlDecodeUni) Kiểm tra tên tham số (không phải giá trị) xem có chứa toán tử MongoDB ($ne, $gt, $regex, $where...) dạng password[$ne] hoặc json.password.$ne. Rất cao
24202 REQUEST_HEADERS:Content-Type + REQUEST_BODY Bổ sung lớp soi body JSON thô để bắt các key "$ne":, "$regex": ngay cả khi lồng sâu nhiều tầng trong mảng/object. Rất cao
24203 REQUEST_FILENAME + ARGS_NAMES Chặn mọi trường hợp biến username/password từ chuỗi phẳng thành object lồng (json.password.xxx) trên route đăng nhập. Cao (cần đúng route login)
24204 ARGS (t:urlDecodeUni) Chặn biểu thức JavaScript chèn vào $where / mapReduce như this.password, sleep(5000), function(){...}. Cao

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Route đăng nhập là /auth/v2/signin và dùng trường account + passwd

Trên Traffic log, đối thủ gửi POST /auth/v2/signin với JSON {"account": "admin", "passwd": {"$regex": "^a"}}. - Cách sửa 24203: Cập nhật route và tên field trong regex:

# Bản sửa thực tế từ [24203] cho route /auth/v2/signin
SecRule REQUEST_FILENAME "@rx (?i)^/auth/v2/signin/?$" \
    "id:24203,phase:2,deny,status:403,log,t:none,t:normalizePath,chain,msg:'NoSQLi: Nested object on signin',tag:'nosqli',logdata:'%{MATCHED_VAR_NAME}'"
    SecRule ARGS_NAMES "@rx ^json\.(?:account|passwd)\." "t:none"

Ví dụ 2: App dùng form URL-encoded có bracket (filter[status]=active)

Nếu đối thủ tấn công qua ?filter[price][$gt]=0, 24201 vẫn bắt chuẩn [$gt] mà không chặn nhầm filter[status]=active (vì chỉ khớp khi có dấu $ trước tên toán tử).

Ví dụ 3: App có chức năng tìm kiếm truyền thẳng object lọc JSON

Nếu đối thủ gửi {"search": {"$where": "1==1"}} trên /api/items/search, bạn không cần sửa 24201/24202 vì cả hai đã tự động chặn mọi toán tử $where trên toàn site.

5. Lưu ý tránh False Positive (SVC)

  • Rule 24201 và 24202 chỉ nhắm vào tên key chứa $operator của MongoDB nên gần như không bao giờ đụng traffic hợp lệ.
  • Kiểm tra Traffic log với modsec.tag:nosqli trước khi đổi pass,log sang deny,status:403,log.
