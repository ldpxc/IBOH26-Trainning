FHACKER 2026 — Regex Copy-Safe (ModSecurity v3 / PCRE)

Vì sao có file này: Trong bảng Markdown, ký tự | phải viết thành \|. Nếu copy nguyên regex từ bảng vào ModSecurity, \| là literal pipe, không phải phép OR → regex sai và rule không bắt được gì. File này chứa toàn bộ regex trong code fence, copy trực tiếp là dùng được.

Quy ước chung: - Luôn bắt đầu action bằng t:none. - Chống double-encode: t:urlDecodeUni,t:urlDecodeUni. - Chống HTML/JS encode: thêm t:htmlEntityDecode,t:jsDecode. - So với chữ thường: thêm t:lowercase ở cuối. - Test regex bằng Python (Mục 4) trước khi dán vào WAF. - Không dùng regex lặp lồng nhau kiểu (a+)+, (.*a){10} — dễ ReDoS, rớt SVC.

1. Allowlist patterns (dùng với !@rx)

# Số nguyên dương 1-10 chữ số (id, page, limit)
^[0-9]{1,10}$

# Số nguyên có thể rỗng (tham số tùy chọn)
^[0-9]{0,10}$

# UUID 36 ký tự (KHÔNG kiểm tra version)
^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$

# Username / slug đơn giản
^[A-Za-z0-9_.-]{1,64}$

# Ngày YYYY-MM-DD
^\d{4}-\d{2}-\d{2}$

# Danh sách cố định (sort/order/status)
^(?:id|name|price|created_at|asc|desc)$

# Danh sách cố định nhưng cho phép rỗng
^(?:id|name|price|created_at|asc|desc)?$

# Tên file an toàn (không có / hoặc \)
^[A-Za-z0-9._-]{1,64}\.(?:pdf|png|jpe?g|gif|txt|csv)$

# Đường dẫn nội bộ chống open redirect (không bắt đầu bằng //)
^/(?!/)[A-Za-z0-9._~!$&'()*+,;=:@%/?-]*$

# Đường dẫn nội bộ chặt hơn: không cho ..
^/(?!/)(?!.*\.\.)[A-Za-z0-9._~!$&'()*+,;=:@%/?-]*$

# Hostname hoặc IPv4 (dùng cho ping/allowlist host)
^(?:[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?\.)*[A-Za-z0-9](?:[A-Za-z0-9-]{0,61}[A-Za-z0-9])?$|^(?:\d{1,3}\.){3}\d{1,3}$

# IPv4 đúng dải 0-255 (chặt hơn)
^(?:(?:25[0-5]|2[0-4]\d|1?\d?\d)\.){3}(?:25[0-5]|2[0-4]\d|1?\d?\d)$

# Chuỗi hex 64 ký tự (SHA-256/token)
^[0-9a-fA-F]{64}$

# Email đơn giản
^[A-Za-z0-9._%+-]{1,64}@[A-Za-z0-9.-]{1,253}\.[A-Za-z]{2,24}$

# JWT dạng JWS: 3 phần, cho phép signature rỗng
^[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]*$

# JWT chặt: bắt buộc CÓ phần chữ ký (chặn header.payload. rỗng)
^[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+$

# Base64 chuẩn
^[A-Za-z0-9+/]+={0,2}$

# Base64URL (JWT)
^[A-Za-z0-9_-]+={0,2}$

# MongoDB ObjectId (24 ký tự hex — hay gặp ở app Node.js/MongoDB)
^[0-9a-fA-F]{24}$

# Boolean / cờ bật tắt
^(?:true|false|0|1)$

# Số thập phân dương (giá tiền, số lượng, tỷ lệ)
^\d{1,10}(?:\.\d{1,4})?$

# Số thập phân có dấu âm (tọa độ, chênh lệch)
^-?\d{1,10}(?:\.\d{1,4})?$

# Mã ngôn ngữ / locale (chống LFI qua ?lang=vi / en-US)
^[a-z]{2}(?:-[A-Z]{2})?$

# Biểu thức số học an toàn (chống Code Injection eval trên route máy tính)
^[0-9+\-*/().\s]{1,128}$

# Đường dẫn file tương đối có thư mục con (cho phép 2026/a.pdf, cấm .. và /)
^(?!.*\.\.)[A-Za-z0-9_-]+(?:/[A-Za-z0-9._-]+){0,4}\.(?:pdf|png|jpe?g|gif|txt|csv)$

# HTTP Method chuẩn (chống Verb Tampering)
^(?:GET|POST|PUT|PATCH|DELETE|HEAD|OPTIONS)$

Lưu ý: - $ trong PCRE có thể khớp trước newline cuối. Nếu cần chặt tuyệt đối, dùng \z thay cho $ (PCRE hỗ trợ), nhưng đa số rule ModSecurity dùng $ là đủ. - Regex tên file ở trên vẫn cho shell.php.jpg (vì phần tên được phép chứa dấu chấm). Phải dùng thêm rule 20411 chặn double-extension, hoặc siết regex thành ^[A-Za-z0-9_-]{1,64}\.(?:pdf|png|jpe?g|gif|txt|csv)$ nếu app không cần tên file có dấu chấm.

2. Detection patterns (dùng với @rx)

# SQLi auth cơ bản (' OR 1=1--, " OR 1=1--) — dùng \x22 thay " để không vỡ chuỗi "@rx ..."
(?i)(?:'\s*(?:or|and)\s*'?\d+'?\s*=\s*'?\d+|\x22\s*(?:or|and)\s*\x22?\d+\x22?\s*=\s*\x22?\d+|'\s*or\s+1\s*=\s*1|--\s|#\s)

# SQLi keyword / time-based (giới hạn độ dài để tránh ReDoS)
(?i)\b(?:union\s+(?:all\s+)?select|select\s+[^;]{0,200}\s+from|insert\s+into|update\s+[^;]{0,200}\s+set|delete\s+from|drop\s+table|sleep\s*\(|benchmark\s*\(|pg_sleep\s*\(|waitfor\s+delay|load_file\s*\(|into\s+outfile)

# Time-based / file SQLi
(?i)\b(?:(?:sleep|benchmark|pg_sleep|extractvalue|updatexml|load_file)\s*\(|waitfor\s+delay\b|into\s+(?:out|dump)file\b)

# NoSQL operator trong tên biến (json.password.$ne, password[$ne], $where)
(?i)(?:^\$|\.\$|\$(?:ne|eq|gt|gte|lt|lte|in|nin|where|regex|exists|or|and|not|nor|expr|jsonSchema|mod|type)\b)

# XSS pattern (sau khi decode URL/HTML/JS)
(?i)(?:<\s*script\b|javascript\s*:|vbscript\s*:|data\s*:\s*text/html|\bon(?:error|load|click|mouseover|mouseout|mouseenter|mouseleave|focus|blur|submit|change|input|keyup|keydown|keypress|toggle|animationstart|transitionend|pointerover)\s*=|<svg\b|<iframe\b|<object\b|<embed\b|srcdoc\s*=|formaction\s*=)

# SSTI (Jinja2/Twig/Spring/Freemarker/ERB)
(?i)(?:\{\{[^}]{0,300}(?:__class__|__mro__|__subclasses__|__globals__|__builtins__|__import__|config|request|self|lipsum|cycler|joiner|namespace|popen|system|7\s*\*\s*7)[^}]{0,300}\}\}|\$\{[^}]{0,300}(?:T\s*\(|Runtime|getClass|forName|exec|7\s*\*\s*7)[^}]{0,300}\}|<%=?[\s\S]{0,300}?%>|#set\s*\(|#assign\s+|\?new\s*\(|\{php\})

# LFI / Path Traversal / wrapper
(?i)(?:(?:\.\.|%2e%2e|%252e%252e|%c0%ae%c0%ae)(?:[/\x5c]|%2f|%5c|%252f|%255c)|(?:php|phar|zip|data|expect|glob|file)://|^(?:/etc/|/proc/|/var/|/home/|/root/|[A-Za-z]:\x5c))

# Shell metacharacter
[;&|`\r\n<>]|\$\(|\$\{|\|\||&&|\x00

# Code execution pattern (PHP/Java/Python/Node)
(?i)(?:\b(?:system|exec|shell_exec|passthru|popen|proc_open|pcntl_exec)\s*\(|\b(?:eval|assert|create_function)\s*\(|\b(?:include|require)(?:_once)?\s*\(|\b(?:base64_decode|gzinflate|str_rot13|convert_uudecode)\s*\(|java\.lang\.(?:Runtime|ProcessBuilder)|getRuntime\s*\(\s*\)\s*\.\s*exec|ProcessBuilder\s*\(|jndi\s*:\s*(?:ldap|rmi|dns|iiop)|InitialContext|lookup\s*\(\s*[\x22\x27](?:ldap|rmi)://)

# SSRF vào localhost/private/metadata
(?i)^(?:https?|ftp)://(?:[^/@]*@)?(?:localhost|127(?:\.\d{1,3}){0,3}|0(?:\.0){0,3}|\[?::1\]?|\[?::ffff:(?:127(?:\.\d{1,3}){1,3}|7f00:[0-9a-f]+)\]?|10(?:\.\d{1,3}){3}|192\.168(?:\.\d{1,3}){2}|172\.(?:1[6-9]|2\d|3[01])(?:\.\d{1,3}){2}|169\.254(?:\.\d{1,3}){2}|100\.100\.100\.200|metadata\.google\.internal)(?::\d+)?(?:/|$)

# SSRF IP obfuscated (decimal/hex/octal)
(?i)^(?:https?|ftp)://(?:[^/@]*@)?(?:0x[0-9a-f]+|\d{8,10}|0[0-7]+(?:\.[0-7]+){0,3})(?::\d+)?(?:/|$)

# SSRF scheme nguy hiểm
(?i)^(?:file|gopher|dict|jar|ldap|ldaps|rmi|tftp|php|expect)://

# XXE
(?i)(<!ENTITY|<!DOCTYPE[^>]*\[|SYSTEM\s+[\x22\x27]|PUBLIC\s+[\x22\x27]|file://|php://|expect://|jar:|gopher://)

(?i)(?:__proto__|constructor\s*(?:\[|\.)\s*[\x22\x27]?prototype|prototype\s*(?:\[|\.)\s*[\x22\x27]?(?:isAdmin|admin|role|polluted))

# Log4Shell / JNDI
(?i)(?:\$\{[^}]{0,200}(?:jndi|ldap|rmi|dns|env|sys|java|lower|upper|date|::-))|(?:jndi\s*:\s*(?:ldap|rmi|dns|iiop))

# Flag (Phase 4)
FHACKER(?:2026)?\{[0-9a-fA-F]{64}\}

# Lộ stack trace / private key / passwd trong response
(?i)(?:root:x:0:0:|SQL syntax|mysql_fetch|ORA-\d{5}|Traceback \(most recent call last\)|java\.lang\.[A-Za-z.]+Exception|BEGIN (?:RSA |EC |OPENSSH )?PRIVATE KEY|AWS_SECRET_ACCESS_KEY|Warning: mysqli?)

# Recon: tệp ẩn / repo / cấu hình (.env, .git, .svn, .htaccess, .DS_Store)
(?i)(?:^|/)\.(?:git|svn|hg|env|htaccess|htpasswd|DS_Store|ssh|aws)(?:/|\.|$)

# Recon: tệp backup / dump DB / swap editor
(?i)\.(?:bak|backup|old|orig|save|swp|swo|sql|sqlite|sqlite3|db|tar\.gz|tgz|zip|7z|rar|dist|inc)$

# File Upload: đuôi thực thi & double extension (shell.php.jpg, .phtml, .jsp, .svg)
(?i)\.(?:php\d?|phtml|phar|pht|shtml|htaccess|htpasswd|jsp|jspx|asp|aspx|py|pl|rb|sh|cgi|exe|svg|html?)(?:\.|$)

# File Upload: mã thực thi nhúng trong multipart body (polyglot webshell)
(?i)(?:<\?(?:php|=)|<script\b|<%[\s=@]|Runtime\.getRuntime|ProcessBuilder|/bin/(?:ba)?sh)

# Code Injection: Python & Node.js eval/exec
(?i)(?:__import__|__builtins__|__globals__|__subclasses__|os\.(?:system|popen)|subprocess\.(?:Popen|run|check_output)|\brequire\s*\(|child_process|mainModule|global\.process|constructor\s*\[\s*[\x22\x27]constructor[\x22\x27]\s*\])

# XXE XInclude (bypass không cần DOCTYPE)
(?i)(?:xmlns:xi\s*=|<\s*xi:include\b)

# JWT: tiêm khóa ngoài (jku/x5u/jwk/x5c) hoặc injection trong kid (dùng sau t:base64Decode)
(?i)(?:\x22(?:jku|x5u|jwk|x5c)\x22\s*:|\x22kid\x22\s*:\s*\x22[^\x22]{0,120}(?:\.\.|/|\x5c|\x27|--|;|\||`|\$\())

# GraphQL: Introspection (__schema / __type)
(?i)\b__(?:schema|type)\b

# Mass Assignment: tên trường đặc quyền (dùng với ARGS_NAMES)
(?i)(?:^|[.\[])(?:role|roles|is_?admin|admin|balance|credit|permissions?|verified|is_?staff|is_?superuser|group_?id)(?:\]|\.array_\d+|$)

# PHP Type Juggling: truyền mảng password[] (dùng với ARGS_NAMES)
(?i)^(?:username|user|email|password|pass|token|otp|pin|code|hash|sig)\[

# PHP Type Juggling: JSON truyền bool/null/number thay vì chuỗi cho password/token (REQUEST_BODY)
(?i)\x22(?:password|pass|token|secret|hash|sig)\x22\s*:\s*(?:true|false|null|\[|\{|-?\d+(?:\.\d+)?(?:\s*[,}]))

# PHP Type Juggling: Magic Hash (0e + toàn chữ số)
^0[eE][0-9]{4,}$

# Crypto: Hash Length Extension padding bytes (%80%00%00... hoặc \x80\x00\x00...)
(?:%80(?:%00){2,}|\x80\x00{2,})

# Crypto: Lộ thông báo lỗi Padding Oracle trong RESPONSE_BODY (Phase 4)
(?i)(?:BadPaddingException|Invalid\s+padding|padding\s+is\s+incorrect|PKCS7\s+padding|decryption\s+failed)

# WAF Bypass: Double URL-encoded metacharacter (%2527, %252e, %252f, %253c, %2500...)
(?i)%25(?:27|22|2e|2f|3c|3e|3b|00|0a|0d|5c)

(?i)^(?:X-Original-URL|X-Rewrite-URL|X-Override-URL|X-HTTP-Method-Override|X-Method-Override|X-Custom-IP-Authorization|X-Host|X-Forwarded-Server|X-Forwarded-Scheme)$

# Spring4Shell (CVE-2022-22965)
(?i)class\.module\.classLoader\.

3. Rule skeletons (copy trực tiếp, pipe thật)

3.1. Allowlist id (Form + JSON)

SecRule REQUEST_FILENAME "@rx (?i)^/api/product/?$" \
    "id:20100,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'Non-numeric product id',tag:'sqli',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"
    SecRule ARGS:id|ARGS:json.id "!@rx ^[0-9]{1,10}$" "t:none,t:urlDecodeUni,t:urlDecodeUni"

3.2. SQLi trên ô tìm kiếm

SecRule REQUEST_FILENAME "@rx (?i)^/api/search/?$" \
    "id:20101,phase:2,pass,log,t:none,t:normalizePath,chain,msg:'SQLi in search',tag:'sqli',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"
    SecRule ARGS:q|ARGS:json.q "@detectSQLi" "t:none,t:urlDecodeUni,t:urlDecodeUni"

3.3. SSRF trên tham số URL

SecRule ARGS:url|ARGS:uri|ARGS:link|ARGS:json.url|ARGS:json.uri|ARGS:json.link \
    "@rx (?i)^(?:https?|ftp)://(?:[^/@]*@)?(?:localhost|127(?:\.\d{1,3}){0,3}|10(?:\.\d{1,3}){3}|192\.168(?:\.\d{1,3}){2}|172\.(?:1[6-9]|2\d|3[01])(?:\.\d{1,3}){2}|169\.254(?:\.\d{1,3}){2}|metadata\.google\.internal)(?::\d+)?(?:/|$)" \
    "id:20500,phase:2,pass,log,t:none,t:urlDecodeUni,t:lowercase,msg:'SSRF internal host',tag:'ssrf',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

3.4. Flag leak Phase 4 (test pass,log trước)

SecRule REQUEST_FILENAME "!@rx (?i)^/(?:api/)?flag(?:/|$)" \
    "id:21201,phase:4,pass,log,t:none,t:normalizePath,chain,msg:'FLAG leak outside flag endpoint',tag:'flag-leak',logdata:'%{REQUEST_METHOD} %{REQUEST_URI}'"
    SecRule RESPONSE_BODY "@rx FHACKER(?:2026)?\{[0-9a-fA-F]{64}\}" "t:none"

Nhớ: đổi pass → deny,status:403 sau khi đã test 1 chu kỳ 30 giây và chắc chắn không cắt nhầm route cờ hợp lệ của bot.

4. Test regex bằng Python trước khi dán

import re

def check(pattern, samples, fullmatch=False):
    rx = re.compile(pattern)
    fn = rx.fullmatch if fullmatch else rx.search
    for s in samples:
        print("MATCH" if fn(s) else "MISS ", repr(s))

# Allowlist: phải fullmatch
check(r"^[0-9]{1,10}$", ["42", "1 OR 1=1", "", "12345678901"], fullmatch=True)

# XSS: search
check(r"(?i)(?:<\s*script\b|javascript\s*:|\bonerror\s*=)", [
    "<script>alert(1)</script>",
    "hello world",
    "onerror=alert(1)",
])

# SQLi: search
check(r"(?i)\b(?:union\s+(?:all\s+)?select|sleep\s*\(|benchmark\s*\()", [
    "1 UNION SELECT 1,2,3--",
    "hello",
    "1 AND SLEEP(3)--",
])

Python re gần giống PCRE nhưng không 100% (PCRE có \K, \R, possessive quantifier...). Với các regex trên, test Python là đủ để bắt lỗi cú pháp và logic cơ bản.

5. Checklist trước khi dán rule

  • [ ] Không còn \| do copy từ bảng Markdown (chỉ giữ \| nếu bạn cố ý muốn match literal pipe).
  • [ ] Không có comment # hoặc khoảng trắng sau dấu \ nối dòng.
  • [ ] t:none đứng đầu danh sách transform.
  • [ ] Đã thêm t:urlDecodeUni 2 lần nếu cần chống double-encode.
  • [ ] Đã thêm t:htmlEntityDecode,t:jsDecode nếu chống XSS/SSTI.
  • [ ] id mới nằm trong 20000–29999 và không trùng.
  • [ ] Rule mới bắt đầu pass,log, test 200/403, chờ 1 chu kỳ 30 giây rồi mới deny.
  • [ ] Với Phase 4: đã loại trừ đúng route cờ hợp lệ của bot.
  • [ ] Đã backup bản rule đang xanh trước khi Save.
