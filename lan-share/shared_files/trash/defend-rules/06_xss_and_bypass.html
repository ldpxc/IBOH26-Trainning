Mẫu Luật Phòng Thủ: XSS & Advanced Bypass (Admin Bot)

  • Nguồn tham chiếu: attack/xss_adminbot.html, attack/xss_advanced_bypass.html, attack/injection.html
  • Nhóm OWASP CRS liên quan: attack-xss (941xxx)
  • Dải Rule ID: 24600–24699 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Cao (cần chuẩn hóa nhiều lớp decode để chống bypass filter đơn giản).

1. Dấu hiệu tấn công chính cần chặn

  • Thẻ thực thi script/tải tài nguyên: <script>, <svg>, <iframe>, <object>, <embed>, <math>, <details>, <base>, <meta http-equiv="refresh">.
  • Thuộc tính event handler: onerror=, onload=, onfocus=, onmouseover=, ontoggle=, onanimationstart=, autofocus.
  • Scheme nguy hiểm & exfiltrate cho Admin Bot: javascript:, data:text/html, vbscript:, document.cookie, fetch(, navigator.sendBeacon(, location.href.
  • Kỹ thuật bypass: chèn lồng (<scr<script>ipt>), HTML entity (&#x3c;), JS unicode escape (\u003c), double URL-encode.

2. Bộ luật ModSecurity v3 mẫu

# [24601] Chặn thẻ HTML nguy hiểm sau khi giải mã nhiều lớp (URL + HTML Entity + JS Escape)
SecRule ARGS "@rx (?i)<\s*/?\s*(?:script|iframe|object|embed|svg|math|base|form|meta|link|style|applet|body|details)\b" \
    "id:24601,phase:2,pass,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:htmlEntityDecode,t:jsDecode,msg:'XSS: Dangerous HTML tag',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

# [24602] Chặn mọi thuộc tính event handler onXXXX=
SecRule ARGS "@rx (?i)(?:[\s/\"'>]|^)on[a-z]{3,20}\s*=" \
    "id:24602,phase:2,pass,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:htmlEntityDecode,t:jsDecode,msg:'XSS: Inline event handler attribute',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

# [24603] Chặn scheme javascript:/vbscript:/data:text/html (kể cả chèn tab/newline bên trong)
SecRule ARGS "@rx (?i)(?:javascript|vbscript)\s*:|data\s*:\s*text/html" \
    "id:24603,phase:2,pass,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:htmlEntityDecode,t:removeWhitespace,msg:'XSS: Dangerous URI scheme',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

# [24604] Chặn hành vi đánh cắp cookie / gọi ra ngoài trong bài XSS Admin Bot
SecRule ARGS "@rx (?i)(?:document\s*\.\s*(?:cookie|domain|location)|window\s*\.\s*location|navigator\s*\.\s*sendBeacon|\bfetch\s*\(|\bXMLHttpRequest\b|String\s*\.\s*fromCharCode)" \
    "id:24604,phase:2,pass,log,t:none,t:urlDecodeUni,t:htmlEntityDecode,t:jsDecode,msg:'XSS: Cookie/exfiltration JS primitive',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

# [24605] Bắt bổ sung bằng libinjection XSS cho các trường nội dung/comment
SecRule ARGS:comment|ARGS:json.comment|ARGS:bio|ARGS:json.bio|ARGS:message|ARGS:json.message "@detectXSS" \
    "id:24605,phase:2,pass,log,t:none,t:urlDecodeUni,t:htmlEntityDecode,msg:'XSS: libinjection match',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
24601 ARGS (t:urlDecodeUni ×2 + t:htmlEntityDecode + t:jsDecode) Chặn các thẻ HTML có khả năng chạy JS hoặc thay đổi DOM (script, svg, iframe, object, details, meta, base...) sau khi giải mã 4 lớp. Cao
24602 ARGS (giải mã 4 lớp) Chặn mọi thuộc tính sự kiện onXXXX= (onerror=, onload=, onfocus=, ontoggle=, onanimationstart=). Cao
24603 ARGS (t:urlDecodeUni ×2 + t:htmlEntityDecode + t:removeWhitespace) Chặn javascript:, vbscript:, data:text/html kể cả khi đối thủ chèn tab/xuống dòng (java\tscript:) để né filter. Rất cao
24604 ARGS (t:urlDecodeUni + t:htmlEntityDecode + t:jsDecode) Chặn các hàm JS chuyên dùng để ăn cắp cookie/exfiltrate dữ liệu khi bài có Admin Bot (document.cookie, fetch(, sendBeacon). Cao
24605 ARGS:comment\|bio\|message (cả json.*) Bắt bổ sung bằng engine libinjection (@detectXSS) trên các trường bình luận/tiểu sử. Trung bình (test với bot trước)

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Đối thủ tiêm XSS qua HTTP Header (Referer hoặc User-Agent) được admin panel hiển thị lại

Nếu trên Traffic log thấy đối thủ gửi User-Agent: <img src=x onerror=fetch(...)> vào trang báo cáo cho Admin Bot: - Cách sửa: Mở rộng biến ở 24601 và 24602 thêm REQUEST_HEADERS:User-Agent|REQUEST_HEADERS:Referer:

# Bản sửa thực tế từ [24602] để bắt thêm XSS trong User-Agent và Referer
SecRule ARGS|REQUEST_HEADERS:User-Agent|REQUEST_HEADERS:Referer "@rx (?i)(?:[\s/\"'>]|^)on[a-z]{3,20}\s*=" \
    "id:24602,phase:2,deny,status:403,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:htmlEntityDecode,t:jsDecode,msg:'XSS: Event handler in ARGS or headers',tag:'xss',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

Ví dụ 2: App có ô nhập liệu chứa từ tiếng Anh có on...= (ví dụ query string hoặc cấu hình)

Nếu 24602 bắt nhầm tham số hợp lệ như options=action=save (vì action= kết thúc bằng on= nếu regex quá rộng): - Lưu ý 24602 đã bắt đầu bằng ranh giới (?:[\s/"'>]|^)on[a-z]{3,20}\s*= nên action= không bị bắt; nếu vẫn có chữ tiếng Anh bắt đầu bằng on kèm dấu = (vd only=1 trong trường text), thu hẹp 24602 chỉ bắt khi có dấu < hoặc " ở gần, hoặc dùng danh sách event phổ biến (on(?:error|load|click|focus|blur|mouse\w+|key\w+|toggle|animation\w+|pointer\w+|input|submit)=).

5. Lưu ý tránh False Positive (SVC)

  • Nếu app có tính năng rich-text hợp lệ (cho phép <p>, <b>, <i>), bộ rule trên vẫn an toàn vì 24601 chỉ chặn thẻ thực thi/nhúng nguy hiểm.
  • Header Cookie và Authorization không nằm trong ARGS, nên không gây FP cho session token.
