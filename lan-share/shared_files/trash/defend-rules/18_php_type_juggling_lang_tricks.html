Mẫu Luật Phòng Thủ: PHP Type Juggling & Language Tricks

  • Nguồn tham chiếu: attack/php_type_juggling.html, attack/lang_tricks_misc.html
  • Nhóm OWASP CRS liên quan: attack-php (933xxx)
  • Dải Rule ID: 25800–25899 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Cao với kiểu mảng (password[]=1 làm strcmp/md5 trả NULL) và JSON boolean/number thay cho chuỗi ({"password": true} hoặc {"password": 0}); trung bình với Magic Hash (0e...).

1. Dấu hiệu tấn công chính cần chặn

  • Array Type Juggling (PHP): Gửi username[]=a&password[]=b để md5($_POST['password']) hoặc strcmp() trả về NULL → NULL == NULL là true.
  • JSON Type Juggling: Gửi {"password": true}, {"password": 0}, {"password": []} hoặc {"token": 0} vào endpoint so sánh lỏng ==.
  • Magic Hash: Gửi chuỗi dạng 0e\d+ (vd 0e215962017) hoặc chuỗi sinh ra MD5/SHA1 dạng 0e... (QNKCDZO, 240610708, s878926199a).

2. Bộ luật ModSecurity v3 mẫu

# [25801] Chặn truyền tham số dạng mảng ([]) vào các trường đăng nhập/xác thực (chống strcmp/md5 NULL)
SecRule ARGS_NAMES "@rx (?i)^(?:username|user|email|password|pass|token|otp|pin|code|hash|sig|signature)\[" \
    "id:25801,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'TypeJuggling: Array syntax on auth parameter',tag:'type-juggling',logdata:'%{MATCHED_VAR_NAME}'"

# [25802] Chặn JSON truyền boolean/null/number/array cho password hoặc token thay vì chuỗi "..."
SecRule REQUEST_HEADERS:Content-Type "@contains application/json" \
    "id:25802,phase:2,pass,log,t:none,t:lowercase,chain,msg:'TypeJuggling: Non-string JSON value for auth field',tag:'type-juggling',logdata:'%{MATCHED_VAR}'"
    SecRule REQUEST_BODY "@rx (?i)\"(?:password|pass|token|secret|otp|pin|hash|sig)\"\s*:\s*(?:true|false|null|\[|\{|-?\d+(?:\.\d+)?(?:\s*[,}]))" "t:none"

# [25803] Chặn giá trị Magic Hash (0e + toàn chữ số) trong các tham số hash/token/password
SecRule ARGS:hash|ARGS:json.hash|ARGS:token|ARGS:json.token|ARGS:password|ARGS:json.password|ARGS:sig|ARGS:json.sig "@rx ^0[eE][0-9]{4,}\z" \
    "id:25803,phase:2,pass,log,t:none,msg:'TypeJuggling: Magic hash 0e... pattern',tag:'type-juggling',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
25801 ARGS_NAMES (t:urlDecodeUni) Chặn kỹ thuật truyền mảng password[]=1 hoặc token[0]=a khiến các hàm PHP (strcmp, md5, sha1, hash_equals sai kiểu) trả NULL và vượt qua phép so sánh lỏng ==. Rất cao
25802 REQUEST_HEADERS:Content-Type + REQUEST_BODY Chặn JSON truyền kiểu không phải chuỗi (true, false, null, 0, [], {}) cho các trường password, token, secret, hash, sig (vì trong PHP 0 == "abc" hoặc true == "batky" là true). Cao (kiểm tra otp/pin có phải số không)
25803 ARGS:hash\|token\|password\|sig (cả json.*) Chặn chuỗi Magic Hash dạng 0e + chữ số (0e215962017) khi backend so sánh hash bằng ==. Rất cao

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Bot SVC gửi mã xác thực OTP dạng số nguyên JSON {"otp": 482910}

Nếu 25802 chặn nhầm vì có otp trong danh sách field bắt buộc phải là chuỗi "...": - Cách sửa 25802: Xóa otp|pin khỏi regex trong 25802, chỉ giữ các trường bắt buộc phải là chuỗi (password, pass, token, secret, hash, sig):

# Bản sửa thực tế từ [25802] khi otp/pin hợp lệ là số JSON
SecRule REQUEST_HEADERS:Content-Type "@contains application/json" \
    "id:25802,phase:2,deny,status:403,log,t:none,t:lowercase,chain,msg:'TypeJuggling: Non-string JSON auth value',tag:'type-juggling',logdata:'%{MATCHED_VAR}'"
    SecRule REQUEST_BODY "@rx (?i)\"(?:password|pass|token|secret|hash|sig)\"\s*:\s*(?:true|false|null|\[|\{|-?\d+(?:\.\d+)?(?:\s*[,}]))" "t:none"

Ví dụ 2: App PHP kiểm tra in_array($input, ['admin', 'mod']) không có strict = true

Nếu đối thủ gửi role=0 (dạng số trong JSON hoặc chuỗi 0 trên PHP < 8), thêm Allowlist chặt theo danh sách chuỗi hợp lệ (!@rx ^(?:user|guest)\z) cho tham số đó.

5. Lưu ý tránh False Positive (SVC)

  • Nếu app hợp lệ có trường otp hoặc pin dạng số JSON ({"pin": 123456} không có dấu ngoặc kép), áp dụng Ví dụ 1 ngay để không chặn nhầm bot SVC.
