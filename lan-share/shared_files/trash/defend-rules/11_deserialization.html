Mẫu Luật Phòng Thủ: Insecure Deserialization

  • Nguồn tham chiếu: attack/deserialization.html, attack/access.html
  • Nhóm OWASP CRS liên quan: attack-rce / attack-java / attack-php (933xxx / 944xxx)
  • Dải Rule ID: 25100–25199 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Cao với định dạng chuẩn (Java serialized, PHP O:..., Python Pickle, YAML unsafe tags) kể cả khi mã hóa Base64.

1. Dấu hiệu tấn công chính cần chặn

  • Java (ysoserial): Magic bytes rO0AB (Base64 của AC ED 00 05), H4sI (gzip + serialized), chuỗi gadget CommonsCollections, Runtime.getRuntime, ProcessBuilder, AnnotationInvocationHandler, TemplatesImpl.
  • PHP (phpggc): Chuỗi serialize object O:<len>:"<Class>": hoặc C:<len>:"<Class>": (kể cả sau Base64 Tzo).
  • Python (pickle / PyYAML): Opcode pickle Base64 (gASV, Y29z, Y3Bvc2l4) hoặc tag YAML !!python/object, !!python/object/apply, !!python/object/new.
  • Node.js (node-serialize): Chuỗi _$$ND_FUNC$$_.

2. Bộ luật ModSecurity v3 mẫu

# [25101] Chặn Java Serialized Object (raw & Base64 rO0AB) trong ARGS, Cookie, Body
SecRule ARGS|REQUEST_COOKIES|REQUEST_BODY "@rx (?:rO0AB[A-Za-z0-9+/=_-]{4,}|\xac\xed\x00\x05)" \
    "id:25101,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'Deser: Java serialized object detected',tag:'deserialization',logdata:'%{MATCHED_VAR_NAME}'"

# [25102] Chặn PHP Object Injection (O:n:"Class": hoặc C:n:"Class":) cả dạng thường và Base64
SecRule ARGS|REQUEST_COOKIES|REQUEST_BODY "@rx (?:[OC]:\+?\d{1,4}:\"[A-Za-z_\\][A-Za-z0-9_\\]{0,80}\":\d{1,4}:\{)" \
    "id:25102,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'Deser: PHP serialized object detected',tag:'deserialization',logdata:'%{MATCHED_VAR_NAME}=%{MATCHED_VAR}'"

# [25103] Chặn PHP Object Injection đã mã hóa Base64 trong tham số/cookie
SecRule ARGS|REQUEST_COOKIES "@rx (?:[OC]:\+?\d{1,4}:\"[A-Za-z_\\][A-Za-z0-9_\\]{0,80}\":\d{1,4}:\{)" \
    "id:25103,phase:2,pass,log,t:none,t:urlDecodeUni,t:base64Decode,msg:'Deser: Base64-encoded PHP serialized object',tag:'deserialization',logdata:'%{MATCHED_VAR_NAME}'"

# [25104] Chặn Python Pickle (Base64 header gASV/Y29z/Y3Bvc2l4) và PyYAML unsafe tags
SecRule ARGS|REQUEST_COOKIES|REQUEST_BODY "@rx (?i)(?:!!python/object(?:/(?:apply|new))?|\b(?:cposix|cos)\nsystem\b|_?\$\$ND_FUNC\$\$_|\bgASV[A-Za-z0-9+/=_-]{8,})" \
    "id:25104,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'Deser: Python Pickle/YAML or NodeJS serialize gadget',tag:'deserialization',logdata:'%{MATCHED_VAR_NAME}'"

# [25105] Chặn tên class gadget Java phổ biến sau khi decode Base64
SecRule ARGS|REQUEST_COOKIES "@rx (?i)(?:CommonsCollections|InvokerTransformer|ChainedTransformer|TemplatesImpl|AnnotationInvocationHandler|ProcessBuilder|javax\.script\.ScriptEngineManager)" \
    "id:25105,phase:2,pass,log,t:none,t:urlDecodeUni,t:base64Decode,msg:'Deser: Known Java gadget chain class',tag:'deserialization',logdata:'%{MATCHED_VAR_NAME}'"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
25101 ARGS\|REQUEST_COOKIES\|REQUEST_BODY Chặn chữ ký Java Serialized Object (rO0AB dạng Base64 và magic bytes \xac\xed\x00\x05). Rất cao (trừ khi app dùng cookie Java serialized)
25102 ARGS\|REQUEST_COOKIES\|REQUEST_BODY Chặn PHP Object Injection dạng thô (O:4:"User":1:{...} hoặc C:...), kể cả biến thể PHP cũ O:+4:.... Cao
25103 ARGS\|REQUEST_COOKIES (t:urlDecodeUni, t:base64Decode) Giải mã Base64 trước rồi mới soi chuỗi O:n:"Class": — bắt được payload phpggc -b gửi trong cookie/param. Cao
25104 ARGS\|REQUEST_COOKIES\|REQUEST_BODY Chặn Python Pickle Base64 (gASV...), PyYAML unsafe tags (!!python/object/apply) và node-serialize (_$$ND_FUNC$$_). Rất cao
25105 ARGS\|REQUEST_COOKIES (t:base64Decode) Chặn tên các class gadget phổ biến của ysoserial (CommonsCollections, TemplatesImpl, ProcessBuilder...) sau khi giải mã Base64. Rất cao (an toàn kể cả khi app có dùng Java serialize hợp lệ)

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: App dùng cookie prefs dạng Base64 PHP serialize hợp lệ (O:5:"Prefs":1:{...})

Nếu bạn bật deny cho 25103 ngay lập tức, cookie prefs hợp lệ của bot SVC sẽ bị chặn (rớt SVC)! - Cách sửa: Không chặn mọi O:... trên cookie prefs, mà chỉ chặn khi cookie prefs (sau t:base64Decode) chứa class khác Prefs hoặc chứa gadget nguy hiểm (Guzzle, Monolog, Symfony, Laravel, SoapClient, system, exec):

# Bản sửa thực tế thay cho [25103] khi app vốn dùng cookie PHP serialize lớp Prefs hợp lệ
SecRule REQUEST_COOKIES:prefs "@rx (?i)(?:O:\+?\d+:\"(?!Prefs\")[A-Za-z_\\][A-Za-z0-9_\\]{0,80}\"|Guzzle|Monolog|Symfony|Laravel|SoapClient|system|shell_exec|passthru)" \
    "id:25103,phase:2,deny,status:403,log,t:none,t:urlDecodeUni,t:base64Decode,msg:'Deser: Unauthorized PHP class in prefs cookie',tag:'deserialization',logdata:'Cookie=prefs'"

Ví dụ 2: App dùng Python Pickle trong cookie session_data nhưng chỉ chứa dict/str bình thường

Thay vì chặn tiền tố gASV ở 25104, chỉ chặn các module/hàm thực thi lệnh sau khi t:base64Decode (posix, nt, os, subprocess, builtins, eval, exec, system, popen).

5. Lưu ý tránh False Positive (SVC)

  • Nếu app vốn dùng cookie dạng PHP serialize hoặc Pickle cho người dùng bình thường (bài cố tình thiết kế lỗi), không chặn toàn bộ O: hoặc gASV mà chỉ chặn tên class/gadget nguy hiểm (25105 hoặc ví dụ sửa ở trên) để không làm hỏng phiên đăng nhập của bot SVC!
