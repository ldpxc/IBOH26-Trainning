Vá Binary (Patch)

Bài này nói về cái gì?

Patch = ghi đè byte trong file nhị phân để đổi hành vi, không cần mã nguồn. Hai mục đích: (1) Attack-Defense — vá lỗ hổng service của đội mình (gets→fgets, thu nhỏ buffer) mà vẫn giữ chức năng; (2) Reverse — vô hiệu kiểm tra (lật if, NOP call).

4 loại vá, dễ→khó: (a) đổi 1 hằng số (thu nhỏ size đọc); (b) lật/ép nhảy có điều kiện (1 byte); (c) NOP một lệnh (ghi 90); (d) code cave trampoline (vá lớn như gets→fgets).

IDA: Edit → Patch Program → … rồi BẮT BUỘC Apply patches to input file để lưu ra file thật.

Nếu chỉ nhớ một điều: Patch xong trong IDA phải "Apply patches to input file" — không thì file trên đĩa KHÔNG đổi.

01 / NỀN TẢNG BẮT BUỘC

Lệnh máy = byte. Sửa byte = sửa lệnh

CPU không hiểu "if/for" — nó chỉ chạy một dãy opcode (mã lệnh dạng byte). Ví dụ byte 90 là lệnh nop ("không làm gì"), C3 là ret ("trả về"). Patch (vá) là mở file nhị phân ra, tìm đúng byte của lệnh muốn đổi, rồi ghi đè byte khác — chương trình chạy theo lệnh mới. Không cần mã nguồn, không cần biên dịch lại.

Mỗi lệnh dài 1–15 byte. Khi vá, phải giữ nguyên tổng độ dài (không chèn thêm byte giữa chừng, vì sẽ xô lệch mọi lệnh phía sau). Nếu lệnh mới NGẮN hơn chỗ cũ → lấp phần thừa bằng 90 (nop). Nếu mới DÀI hơn → không ghi tại chỗ được, phải dùng code cave (mục 10).

Định nghĩa nhanh

opcode

Byte mã lệnh CPU (90=nop...).

patch / vá

Ghi đè byte để đổi hành vi.

VA

Virtual Address — địa chỉ IDA hiện.

file offset

Vị trí byte trong file (cho hex editor).

NOP

Lệnh không làm gì (90), dùng để xóa.

code cave

Vùng byte trống chạy được để chèn lệnh.

02 / VÌ SAO CÓ KỸ THUẬT

Attack-Defense: vá nhưng đừng làm hỏng

Trong Attack-Defense CTF, mỗi đội chạy cùng một service có lỗ hổng. Bạn phải: (1) khai thác service đội khác để lấy flag, và (2) vá service của mình để đội khác không khai thác được — nhưng service vẫn phải chạy đúng chức năng (checker của ban tổ chức sẽ kiểm, vá hỏng = mất điểm SLA). Bạn thường không có mã nguồn, chỉ có file binary → phải vá byte trực tiếp. Vá tối thiểu, chính xác, giữ hành vi hợp lệ là nghệ thuật sống còn. Trong reverse, patch dùng để bỏ qua check bản quyền/anti-debug để hiểu hoặc chạy chương trình.

03 / BẢNG OPCODE SỐNG CÒN · THUỘC LÒNG

Nhảy có điều kiện (jcc) — quan trọng nhất

Nhảy có điều kiện dạng ngắn (short, nhảy gần) là 2 byte: opcode + khoảng cách. Opcode đi theo cặp lật nhau ở bit thấp nhất (LSB) — muốn đảo điều kiện, chỉ cần XOR byte opcode với 01 (hoặc +1 nếu nó chẵn, −1 nếu lẻ).

3 thao tác với jcc 1. Đảo điều kiện (chạy nhánh ngược): byte 74 → 75 (XOR 01).
2. Ép LUÔN nhảy (bỏ qua check): đổi 7x → EB (jmp short), giữ nguyên byte khoảng cách.
3. Ép KHÔNG BAO GIỜ nhảy (đi thẳng): NOP cả 2 byte → 90 90.

Nhảy điều kiện DÀI (near, 6 byte)

Khi đích xa, jcc là 6 byte: 0F 8x + 4 byte khoảng cách. Bảng 8x y hệt trên nhưng cộng 80: 0F 84=je, 0F 85=jne, 0F 8C=jl... Đảo: XOR byte thứ hai với 01 (0F 84→0F 85). Ép luôn nhảy: đổi thành E9+4byte (jmp near, 5 byte) rồi thêm 90 cho đủ 6. Ép không nhảy: 6 × 90.

07 / CÔNG THỨC VÁ CỤ THỂ (byte thật)

Case thường gặp — làm theo từng byte

Thu nhỏ hằng số đọc (vá AN TOÀN nhất cho AD)

Rất nhiều lỗ hổng là đọc quá nhiều byte vào buffer nhỏ. Nếu code dùng read(0, buf, 0x100) mà buf chỉ 0x40 byte → đổi hằng 0x100 thành 0x40 là bịt tràn, service vẫn chạy.

; TRƯỚC — IDA hiện (đã bật số byte opcode):
.text:004011A0 BA 00 01 00 00    mov  edx, 100h    ; size đọc = 0x100
.text:004011A5 48 89 C6          mov  rsi, rax     ; buf
.text:004011A8 E8 ...            call read

; VÁ: đổi hằng 0x100 → 0x40. Byte 00 01 00 00 (little-endian) → 40 00 00 00
; IDA: bấm dòng 4011A0 → Edit→Patch Program→Change byte
;   Values: BA 40 00 00 00   (chỉ đổi byte thứ 2: 00→40)

; SAU:
.text:004011A0 BA 40 00 00 00    mov  edx, 40h     ; size = 0x40, an toàn
Vì sao tốtChỉ đổi 1 byte, không xô lệch gì, service vẫn đọc input bình thường (chỉ ngắn hơn). Đây là vá AD "chuẩn mực" khi buffer overflow do size lớn. Áp dụng tương tự cho fgets(buf, SIZE, stdin), malloc(SIZE), vòng for i<N.

Lật hoặc ép lệnh if (reverse: bỏ qua check)

Ví dụ check mật khẩu: if (strcmp(input,pw)==0) win(); else fail();. Sau strcmp thường có test eax,eax ; jnz fail (strcmp==0 nghĩa là khớp → eax=0 → không nhảy → vào win). Muốn luôn vào win dù sai mật khẩu:

; TRƯỚC:
.text:00401200 E8 .. call strcmp
.text:00401205 85 C0            test eax, eax
.text:00401207 75 0A           jnz  short fail   ; nhảy đi fail nếu KHÁC 0
.text:00401209 ...              (win...)

; CÁCH 1 — ép KHÔNG BAO GIỜ nhảy (luôn vào win): NOP 2 byte
;   bấm 401207 → Change byte → Values: 90 90
.text:00401207 90 90           nop; nop

; CÁCH 2 — đảo điều kiện (nếu logic ngược): 75 → 74 (jnz→jz)
;   Values: 74 0A

; CÁCH 3 — ép LUÔN nhảy tới đích khác: 75 → EB (jmp short), giữ 0A
;   Values: EB 0A
Phân biệtNOP jcc = luôn đi thẳng (fall-through). jcc→jmp (EB) = luôn nhảy. Đảo (XOR 01) = đổi điều kiện. Đọc kỹ nhánh nào là "thành công" rồi chọn. Nếu dùng Keypatch: gõ thẳng nop hoặc jmp <addr>.

Tắt một call (NOP cả 5 byte)

Khi muốn vô hiệu một hàm (anti-debug ptrace, log, hoặc hàm nguy hiểm không cần thiết), NOP toàn bộ lệnh call (5 byte E8 xx xx xx xx) → thành 5 × 90.

; TRƯỚC:
.text:00401150 E8 CB FE FF FF   call ptrace   ; anti-debug

; VÁ: bấm 401150 → Change byte → Values: 90 90 90 90 90
; SAU:
.text:00401150 90 90 90 90 90   nop (×5)
Lưu ý giá trị trả vềNếu code SAU đó dùng giá trị trả về của call (trong eax/rax), NOP không đặt eax → có thể sai. Khi cần "call trả về 0", thay bằng 31 C0 (xor eax,eax = 2 byte) + 90 90 90 (3 nop) cho đủ 5. Hoặc return 1: B8 01 00 00 00 (mov eax,1 = đúng 5 byte, khỏi nop).

Mẹo trả về đúng 5 byte:

return 0 : 31 C0 90 90 90        (xor eax,eax + 3 nop)
return 1 : B8 01 00 00 00        (mov eax, 1   — vừa 5 byte)
return N : B8 NN 00 00 00        (mov eax, N)

gets → fgets (vá AD kinh điển, cần code cave)

Vì sao KHÔNG đổi 1 byte được: gets(buf) chỉ 1 tham số (rdi=buf). fgets(buf, size, stdin) cần 3 tham số: rdi=buf, rsi=size, rdx=stdin. Không thể "đổi tên gọi" vì thiếu rsi/rdx. Phải chuyển hướng call gets sang một đoạn code nhỏ (trampoline) nằm trong code cave, đặt đủ tham số rồi gọi fgets.

; BƯỚC 1 — tìm call gets (X trên gets). Giả sử:
.text:00401233 48 8D 45 D0       lea  rax, [rbp-0x30]   ; buf
.text:00401237 48 89 C7          mov  rdi, rax
.text:0040123A E8 .. .. .. ..    call gets           ; ← đổi đích call này

; BƯỚC 2 — tìm code cave: vùng byte 00 chạy được (cuối .text).
;   readelf -S bin | grep .text  → biết biên .text
;   trong IDA kéo xuống cuối .text tìm dãy 'db 0' dài ≥ 30 byte.
;   Giả sử cave tại 0x401500 (trống).

; BƯỚC 3 — đổi 'call gets' thành 'call 0x401500' (vẫn 5 byte E8+rel32).
;   IDA: bấm 0x40123A → Edit→Patch Program→Assemble → gõ:  call 0x401500
;   (IDA tự tính E8 + rel32 mới)

; BƯỚC 4 — viết trampoline tại cave 0x401500 (Assemble từng dòng):
;   rdi đã = buf (giữ nguyên). Cần rsi=size, rdx=stdin, rồi call fgets, ret.
0x401500:  mov esi, 0x30                 ; size = 0x30 (bằng buffer)
0x401505:  mov rdx, cs:stdin            ; nạp con trỏ stdin (biến toàn cục)
           ;  nếu IDA assemble lỗi, dùng byte: 48 8B 15 xx xx xx xx (mov rdx,[rip+off])
0x40150C:  call fgets                    ; fgets(buf, 0x30, stdin)
0x401511:  ret                           ; quay về sau 'call 0x401500'

; BƯỚC 5 — Apply patches to input file. Xong: input bị giới hạn 0x30 byte.
Chi tiết sống còn • stdin là biến toàn cục trong IDA (double-click gets xref hoặc tìm symbol stdin). mov rdx, cs:stdin nạp giá trị con trỏ FILE.
• fgets phải có trong PLT. Nếu binary chưa import fgets, không gọi được tên → khi đó dùng read(0, buf, 0x30) thay (read thường luôn có): đặt xor edi,edi (fd=0), rsi=buf, edx=0x30, call read, ret. read bỏ ký tự thừa khác fgets đôi chút nhưng chặn tràn.
• Giữ 5 byte ở chỗ call gốc: call cave cũng là E8+rel32 = 5 byte, khớp hoàn hảo.
• Cave phải nằm trong đoạn có quyền X (execute) — .text đạt; .data/.bss thì KHÔNG chạy được.

Phương án đơn giản hơn (nếu chỉ cần CHẶN tràn, không cần fgets)

; Nếu buffer đủ lớn và chỉ cần không cho gets tràn vô hạn:
; thay 'call gets' bằng trampoline gọi read với size giới hạn (read luôn có sẵn).
cave:  xor edi, edi          ; 31 FF    → fd = 0 (stdin)
       ; rsi = buf (giữ từ rdi? không — read cần rsi=buf). Thêm:
       mov rsi, rdi          ; 48 89 FE → rsi = buf
       mov edx, 0x30         ; BA 30 00 00 00 → size
       call read             ; E8 ..
       ret                   ; C3
AD checklistSau vá gets: chạy service, gửi input dài > buffer → phải KHÔNG crash. Gửi input hợp lệ ngắn → chức năng vẫn đúng (checker pass). Nếu read làm input dính ký tự newline khác gets → kiểm logic parse phía sau.

08 / HEX EDITOR & RADARE2

Vá không cần IDA

Hex editor (HxD trên Windows, hexedit/wxHexEditor/Okteta trên Linux)

1

Lấy file offset

Hex editor làm việc theo file offset, không phải VA. Lấy offset từ IDA (hộp Change byte có dòng File offset), hoặc tính: offset = VA − base (non-PIE base 0x400000; PIE base 0 → offset=VA). Hoặc objdump -d rồi dùng công cụ ở mục 05.

2

Nhảy & sửa (HxD)

HxD: Ctrl+G (Goto) → gõ offset (hex) → con trỏ tới đó. Gõ đè byte hex mới (bên cột hex). Byte đổi hiện màu đỏ.

# hexedit (Linux): mở file
$ hexedit ./bin
# Ctrl+G  → gõ offset  → Enter
# gõ byte hex đè lên   (Tab chuyển hex/ascii)
# Ctrl+X → lưu & thoát (Y)
3

Hoặc sửa bằng dòng lệnh thuần

# printf + dd: ghi 1 byte 0x90 vào offset 0x1207
$ printf '\x90' | dd of=bin bs=1 seek=$((0x1207)) count=1 conv=notrunc
# nhiều byte: seek tới offset, count = số byte
$ printf '\x90\x90' | dd of=bin bs=1 seek=$((0x1207)) count=2 conv=notrunc
# conv=notrunc BẮT BUỘC — nếu không file bị cắt!

radare2 / rizin (miễn phí, rất mạnh — nên thuộc)

$ r2 -w ./bin            # -w = write mode (ghi thẳng file)
[0x00401040]> aaa        # phân tích (tìm hàm, nhãn)
[0x00401040]> s 0x401207 # seek tới địa chỉ (hoặc: s sym.main)
[0x00401207]> pd 3       # in 3 lệnh quanh đây để xem

# --- các lệnh ghi (write) ---
[0x..]> wao nop          # NOP lệnh tại con trỏ (tự đúng độ dài)
[0x..]> wao recj         # LẬT nhảy điều kiện (je↔jne, jl↔jge...)
[0x..]> wa jmp 0x401250  # ghi assembly (wa = write assembly)
[0x..]> wa nop           # ghi 1 nop
[0x..]> wx 9090          # ghi hex byte trực tiếp
[0x..]> wx 4000 @ 0x4011a1  # ghi byte tại địa chỉ khác (@ = tạm seek)
[0x..]> "wa mov esi, 0x30"  # lệnh có dấu cách → bọc nháy kép

# wao (write assembly op) các toán tử hữu dụng:
#   nop  | trap | ret0 | ret1 | jz | jnz | recj (reverse cond jump) | nocj

[0x..]> q                # thoát (đã ghi tự động vào file)
r2 tìm chỗ vá/ Access granted (tìm chuỗi) · axt @ sym.gets (xref tới gets) · afl (liệt kê hàm) · s sym.imp.gets rồi axt. r2 có sẵn trên hầu hết máy CTF, không cần license như IDA.

09 / GỠ LỖI

Khi vá hỏng

File không đổi

Quên "Apply patches to input file" (IDA). Hoặc dd thiếu conv=notrunc.

File bị cắt ngắn

dd không có notrunc → file hỏng. Luôn thêm conv=notrunc.

Crash sau vá

Lệnh mới dài hơn chỗ cũ → xô lệch. Giữ đúng độ dài, lấp 90.

Sai địa chỉ/offset

Nhầm VA với file offset. PIE: offset=VA; non-PIE: VA−0x400000.

eax sai sau NOP call

Code dùng giá trị trả về. Dùng B8 01000000 (return 1) thay.

Cave không chạy

Cave nằm vùng không X (.data/.bss). Dùng padding trong .text.

IDA Assemble báo lỗi

Engine yếu. Dùng Keypatch hoặc Change byte tay / r2 wa.

AD: checker fail

Vá làm hỏng chức năng. Vá tối thiểu hơn, test input hợp lệ.

Checksum/CRC chặn

Hiếm ở AD. Binary tự kiểm tra toàn vẹn → phải vá cả hàm check.

10 / CODE CAVE & VÁ LỚN

Khi lệnh mới dài hơn chỗ cũ

1

Tìm cave

Vùng byte 00 liên tục trong đoạn chạy được (X). Hay có ở cuối .text (padding trước .fini), hoặc giữa các hàm. IDA: kéo xuống cuối .text tìm align/db 0. r2: /x 0000000000000000 trong .text.

2

Trỏ tới cave

Tại chỗ cần vá, đặt call cave (5 byte) hoặc jmp cave (5 byte, E9). Nếu chỗ cũ <5 byte, mượn thêm byte lệnh kế rồi tái tạo lệnh đó trong cave ("stolen bytes").

3

Viết code trong cave

Assemble từng dòng tại địa chỉ cave. Kết thúc bằng ret (nếu dùng call) hoặc jmp về (nếu dùng jmp). Nhớ bảo toàn thanh ghi nếu cần (push/pop).

Không có cave đủ lớn?Cách nâng cao: thêm section mới có quyền X (dùng objcopy --add-section hoặc công cụ như LIEF), hoặc đổi quyền một section sang executable. Phức tạp hơn — chỉ dùng khi vá lớn và không còn chỗ trống. Với AD, đa số vá nhỏ (1 byte size / lật if / trampoline ngắn) nên cave sẵn trong .text là đủ.

Bảo toàn thanh ghi trong cave

cave:  push rdi          ; lưu thanh ghi sẽ dùng
       push rsi
       ...               ; việc của bạn
       pop  rsi          ; khôi phục (ngược thứ tự)
       pop  rdi
       ; tái tạo lệnh gốc bị "stolen" nếu có
       jmp  0x40123F     ; nhảy về sau chỗ đã vá
