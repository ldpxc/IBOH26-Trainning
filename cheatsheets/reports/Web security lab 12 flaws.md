# Dạy và vá 12 lỗi web

Bộ bài giảng web nên dạy mỗi lỗi qua cùng một vòng: **nhận ra data flow nguy hiểm trong source, chứng minh tác động bằng PoC vô hại trên lab, rồi vá đúng ranh giới cú pháp/quyền và kiểm tra lại invariant**. Tôi chuyển phần `web.md` hiện có thành Combat Card tra nhanh và ba bài sâu theo nhóm, giữ tinh thần chuẩn IBOH là đọc nhanh để xử lý tình huống rồi học sâu để hiểu vì sao. Bộ 12 lớp gồm SQLi, XSS, IDOR/BOLA, auth/session/JWT, CSRF, SSRF, path traversal/LFI, upload không an toàn, OS command injection, SSTI, XXE và insecure deserialization. OWASP Top 10:2025 xếp Broken Access Control ở A01 và Injection ở A05; API Security Top 10 được tài liệu nghiên cứu đối chiếu là bản 2023, nên các phiên bản được ghi riêng thay vì gộp thành một nhãn “hiện hành” duy nhất. ([OWASP Top 10:2025](https://top10.owasp.org/2025/0x00_2025-Introduction/), [OWASP API Security Top 10:2023](https://api-security.owasp.org/editions/2023/en/))

## Mười hai lỗi lộ ra khi lần theo source tới sink

Bản chất chung không phải “input xấu” mà là **dữ liệu do client kiểm soát được diễn giải thành cú pháp hoặc quyền**. Khi review, đánh dấu source (query/body/cookie/upload/token), các bước decode/format, sink (query engine, HTML DOM, shell, template engine, object lookup, filesystem, HTTP client, XML parser), rồi chỉ ra chính xác check nào chạy ngay trước sink. Tên hàm khả nghi là manh mối, chưa tự chứng minh exploit: cần xác nhận framework/version, control flow, account privilege và policy thực tế. ([OWASP Secure Code Review](https://cheatsheetseries.owasp.org/cheatsheets/Secure_Code_Review_Cheat_Sheet.html), [OWASP Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Injection_Prevention_Cheat_Sheet.html))

| # | Lớp lỗi | Dấu hiệu review tiêu biểu | Bản vá đúng ranh giới |
|---|---|---|---|
| 1 | SQLi | request nối vào query string | prepared statement; allowlist cho identifier động |
| 2 | XSS | input vào HTML/DOM sink không encode | encode theo context; DOM safe API |
| 3 | IDOR/BOLA | object lookup theo ID thiếu quyền object-level | policy server-side trên từng object/action |
| 4 | Auth/session/JWT | claims dùng trước verify; verifier lỏng; session không xoay | fixed algorithm/key/claims; quản lý vòng đời credential |
| 5 | CSRF | cookie-auth state change không yêu cầu proof | CSRF middleware/token; SameSite/Origin là lớp phụ |
| 6 | SSRF | URL request đi vào HTTP client phía server | service allowlist và egress controls |
| 7 | Path traversal/LFI | user path đến filesystem/include | opaque key → server-owned path; containment |
| 8 | Upload | tin MIME/extension/name, lưu vào webroot | decode/validate server-side, tên ngẫu nhiên, storage riêng |
| 9 | Command injection | input tới shell/process | bỏ subprocess hoặc argv cố định, shell tắt, input validation |
| 10 | SSTI | input được compile thành template source | template cố định, input chỉ truyền làm data |
| 11 | XXE | parser cho phép DTD/external entity | reject DTD, disable external resolution, fail closed |
| 12 | Deserialization | untrusted bytes vào pickle/unserialize/readObject | data-only format, schema/size limits |

Ma trận này là **khung dạy**, không khẳng định mọi code smell đều khai thác được. Ví dụ, parameterized SQL không thay thế allowlist cho tên cột; HTML escaping phải đúng context; bỏ `shell=True` vẫn cần tránh option injection; UUID không thay authorization. ([OWASP SQLi Prevention](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html), [OWASP XSS Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html), [OWASP OS Command Injection](https://cheatsheetseries.owasp.org/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.html), [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html))

## PoC hiệu quả chỉ cần chứng minh đúng một ranh giới

Trong lớp học, dùng một app cố ý lỗi, hai user giả (Alice/Bob), dữ liệu seed, marker và service bind `127.0.0.1`. PoC SQLi chỉ truy vấn các hàng giả; XSS chỉ đặt marker DOM; SSTI chỉ tính `{{7*7}}`; command injection chỉ in `POC_OK`; IDOR chỉ đọc object giả của Bob; CSRF chỉ đổi email `.test`; SSRF gọi một marker server loopback; traversal/XXE chỉ chạm fixture do lab tạo; upload kiểm tra MIME giả với bytes vô hại; deserialization chỉ gọi `print` trong tiến trình lab. Các ví dụ nằm trực tiếp trong ba bài con để người học thấy request, code sink và kết quả mong đợi cùng một chỗ. OWASP WSTG khuyến nghị xác định input và quan sát tác động trong luồng test có thẩm quyền; điều kiện loopback/fixture là giới hạn vận hành được đặt cho bộ lab này. ([OWASP WSTG SQL Injection](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Injection/05-SQL_Injection/), [OWASP WSTG XXE](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Injection/07-XML_Injection/))

Không nên biến bài học thành một payload “vạn năng”. **Proof tốt nhất là nhỏ và có expected result**: trước vá query trả thêm row; sau vá marker thành giá trị literal. Trước vá input vào template thành 49; sau vá hiện nguyên văn. Trước vá JWT không ký được route local chấp nhận; sau vá verifier từ chối. Trước vá Alice lấy hóa đơn giả Bob; sau vá không có response/state change. Điều này dạy cách phân biệt một lỗi code thật với status code lạ hay false positive.

## Bản vá phải đóng đường đến sink, rồi hồi quy đúng invariant

Các lớp SQLi, XSS, command injection và SSTI cùng là lỗi ranh giới parser nhưng cần API chuyên dụng: bind SQL values; encode output đúng context/use safe DOM APIs; tránh shell và gọi thư viện; không biên dịch template do user tạo. Với phân quyền, lấy principal từ session/token đã verify và ràng buộc query với owner/tenant/policy trên từng hành động. Với JWT, cấu hình algorithm allowlist, key, issuer/audience và claim bắt buộc ở server; với session, xoay ID sau login/privilege change và invalidate ID cũ. Với CSRF, framework token middleware bảo vệ unsafe methods; `SameSite` không phải thay thế phổ quát. ([Python sqlite3](https://docs.python.org/3/library/sqlite3.html), [Flask templating](https://flask.palletsprojects.com/en/stable/templating/), [PyJWT API](https://pyjwt.readthedocs.io/en/stable/api.html), [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html), [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html))

Với file/protocol, không nhận path/URL/filetype do client quyết định đích cuối: dùng object key map sang path, xử lý upload bằng parser định dạng giới hạn rồi lưu ngoài webroot, map service key sang network destination, và tắt DTD/external entity trên **từng** XML parser. Với object serialization, chuyển sang JSON/data-only DTO cùng schema/size checks; Python khẳng định pickle không an toàn cho dữ liệu không tin cậy. Với SSRF, allowlist ở ứng dụng phải đi cùng outbound network restrictions; với XML, parser hardening không tự giải quyết mọi denial-of-service nên giới hạn byte/resource riêng. ([OWASP Path Traversal](https://cheatsheetseries.owasp.org/cheatsheets/Path_Traversal_Prevention_Cheat_Sheet.html), [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html), [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [OWASP XXE](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html), [Python pickle](https://docs.python.org/3/library/pickle.html))

Hồi quy cần test cả response lẫn side effect: DB không sửa; file fixture ngoài root không xuất hiện; request redirect không đi tới đích cấm; parser không trả sentinel; token/cookie cũ không còn dùng; object khác chủ không bị đọc hoặc sửa. PoC `curl` không mô phỏng trình duyệt CSRF, source scan không chứng minh runtime parser, và code smell không chứng minh quyền khai thác. Các bài con ghi rõ giới hạn này để người học không suy rộng hơn bằng chứng. ([OWASP WSTG Upload](https://owasp.org/www-project-web-security-testing-guide/latest/14-Business_Logic/08-Upload_of_Unexpected_File_Types/), [OWASP WSTG SSRF](https://owasp.org/www-project-web-security-testing-guide/latest/4-Web_Application_Security_Testing/07-Injection/18-Server-Side_Request_Forgery/))

## Dùng ba bài con như giáo trình Combat rồi học sâu

[web.md](../web.md) là mục lục/combat card; [Injection](../web/injection.md) gom SQLi, XSS, command injection, SSTI; [Access](../web/access.md) gom IDOR/BOLA, auth/session/JWT, CSRF, deserialization; [Files and protocols](../web/files_protocol.md) gom traversal/LFI, upload, SSRF, XXE. Mỗi bài dùng thứ tự nhận diện 30 giây → code lỗi và dấu hiệu → PoC local → bản vá → lý do → hồi quy, phù hợp nguyên tắc hai lớp trong [_CHUAN_VIET_BAIGIANG.html](../_CHUAN_VIET_BAIGIANG.html). Code hiện là ví dụ minh họa chưa chạy; không nên đưa vào production hoặc coi chúng là runnable challenge trước khi có lab/dependencies tương ứng.

Các nguồn chính trong quá trình tổng hợp là OWASP Cheat Sheet Series, OWASP WSTG, OWASP Top 10:2025, OWASP API Security Top 10:2023 và tài liệu official của Python, Flask/Jinja, PyJWT, Flask-WTF, `defusedxml`. Phạm vi framework trong code tập trung vào Python/Flask (XXE có thêm Java JAXP); cần chuyển API nếu lớp học dùng PHP, Node, Java/Spring hay .NET. Bản tổng hợp không khẳng định mọi parser/version có cùng mặc định, và không có ứng dụng mục tiêu cụ thể để xác nhận exploitability ngoài lab mẫu.

## Kết luận

Một giáo trình web hữu dụng cho CTF và vá lỗi không chỉ dạy payload: nó giúp học viên nối input tới sink, gọi đúng API an toàn và viết một kiểm chứng trước/sau có kết quả rõ. Chuẩn hóa mỗi bài theo vòng này khiến 12 nhóm lỗi khác cơ chế vẫn có chung quy trình review, nhưng giữ được khác biệt quan trọng ở cách encoding, quyền, filesystem, network và parser hoạt động.

Ba bài con đã đặt đường dẫn cụ thể giữa lỗi và bản vá, đồng thời giới hạn PoC vào loopback và fixture giả. Bước tiếp theo để biến tài liệu thành challenge chạy được là thêm một app lab cô lập với dependency pinning, data seed và test tự động; hiện tài liệu không tuyên bố các ví dụ đã chạy.
