Mẫu Luật Phòng Thủ: XML External Entity (XXE)

  • Nguồn tham chiếu: attack/xxe.html, attack/files_protocol.html
  • Nhóm OWASP CRS liên quan: attack-generic / attack-lfi (920xxx / 930xxx)
  • Dải Rule ID: 24900–24999 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Rất cao (chặn <!DOCTYPE và <!ENTITY ngay ở tầng HTTP body).

1. Dấu hiệu tấn công chính cần chặn

  • Khai báo DTD/Entity trong XML, SVG upload, SOAP hoặc tham số chứa XML: <!DOCTYPE, <!ENTITY, SYSTEM, PUBLIC, PARAMETER ENTITY (<!ENTITY %).
  • Chèn XInclude (xi:include, xmlns:xi) để đọc file mà không cần <!DOCTYPE.
  • Lưu ý quan trọng với ModSecurity v3: khi Content-Type là application/xml hoặc text/xml, ModSecurity chuyển sang XML parser nên muốn soi raw REQUEST_BODY cần kiểm tra thêm ở REQUEST_BODY hoặc chuyển body processor nếu cần.

2. Bộ luật ModSecurity v3 mẫu

# [24901] Chặn khai báo DOCTYPE và ENTITY trong mọi REQUEST_BODY và ARGS
SecRule REQUEST_BODY|ARGS "@rx (?i)<!\s*(?:DOCTYPE|ENTITY)\b" \
    "id:24901,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'XXE: DOCTYPE or ENTITY declaration blocked',tag:'xxe',logdata:'%{MATCHED_VAR}'"

# [24902] Chặn từ khóa SYSTEM/PUBLIC đi kèm URI scheme đọc file hoặc gọi ngoài
SecRule REQUEST_BODY|ARGS "@rx (?i)\b(?:SYSTEM|PUBLIC)\s+['\"][^'\"]{0,120}(?:file|http|https|ftp|php|expect|gopher)://" \
    "id:24902,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'XXE: External SYSTEM/PUBLIC resource',tag:'xxe',logdata:'%{MATCHED_VAR}'"

# [24903] Chặn XInclude bypass (không cần DOCTYPE)
SecRule REQUEST_BODY|ARGS "@rx (?i)(?:xmlns:xi\s*=|<\s*xi:include\b)" \
    "id:24903,phase:2,pass,log,t:none,t:urlDecodeUni,msg:'XXE: XInclude injection detected',tag:'xxe',logdata:'%{MATCHED_VAR}'"

# [24904] Bắt buộc bật đọc body thô cho XML nếu app nhận application/xml hoặc text/xml
SecRule REQUEST_HEADERS:Content-Type "@rx (?i)^(?:application|text)/xml" \
    "id:24904,phase:1,pass,nolog,t:none,ctl:requestBodyProcessor=URLENCODED"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
24901 REQUEST_BODY\|ARGS (t:urlDecodeUni) Chặn mọi khai báo <!DOCTYPE và <!ENTITY — điều kiện bắt buộc của hầu hết payload XXE cổ điển & Blind XXE. Rất cao (trừ khi app upload SVG có DOCTYPE)
24902 REQUEST_BODY\|ARGS (t:urlDecodeUni) Chặn từ khóa SYSTEM / PUBLIC kèm URI scheme (file://, http://, php://, expect://, gopher://). Rất cao
24903 REQUEST_BODY\|ARGS (t:urlDecodeUni) Chặn kỹ thuật XInclude (xmlns:xi= và <xi:include) vốn không cần dùng <!DOCTYPE. Rất cao
24904 REQUEST_HEADERS:Content-Type (Phase 1) Chuyển body processor của request application/xml hoặc text/xml sang URLENCODED để ModSecurity nạp raw XML vào biến REQUEST_BODY cho 24901–24903 soi được. Cao (chỉ bật nếu app nhận XML thô)

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: App nhận upload file .svg hợp lệ có dòng <!DOCTYPE svg PUBLIC ...> ở đầu

Nếu bot SVC upload logo .svg có sẵn dòng <!DOCTYPE svg ...> khiến 24901 chặn nhầm: - Cách sửa 24901: Chỉ chặn <!ENTITY (vì XXE bắt buộc phải định nghĩa entity), vẫn giữ 24902 chặn SYSTEM/PUBLIC kèm scheme nguy hiểm:

# Bản sửa thực tế từ [24901] khi app cho phép <!DOCTYPE svg> nhưng vẫn chặn XXE
SecRule REQUEST_BODY|ARGS "@rx (?i)<!\s*ENTITY\b" \
    "id:24901,phase:2,deny,status:403,log,t:none,t:urlDecodeUni,msg:'XXE: ENTITY declaration blocked',tag:'xxe',logdata:'%{MATCHED_VAR}'"

Ví dụ 2: App nhận XML nén trong tham số Base64 (?xml_data=PD94bWwg...)

Nếu đối thủ gửi XML mã hóa Base64 qua tham số xml_data: - Thêm 1 rule dùng t:base64Decode riêng cho tham số đó: - SecRule ARGS:xml_data|ARGS:json.xml_data "@rx (?i)<!\s*(?:DOCTYPE|ENTITY)\b" "id:24910,phase:2,deny,status:403,log,t:none,t:urlDecodeUni,t:base64Decode,msg:'XXE: Base64 XML entity',tag:'xxe'"

5. Lưu ý tránh False Positive (SVC)

  • Rule 24904 chỉ nên bật khi bạn thấy 24901 không bắt được payload XML có Content-Type: application/xml (vì XML body processor không đưa raw text vào REQUEST_BODY).
  • Nếu app chỉ có 1 route XML cụ thể (vd /api/import-xml), gắn thêm chain kiểm tra REQUEST_FILENAME cho 24904 để không ảnh hưởng route khác.
