Mẫu Luật Phòng Thủ: Prototype Pollution (JavaScript / Node.js)

  • Nguồn tham chiếu: attack/prototype_pollution.html
  • Nhóm OWASP CRS liên quan: attack-nodejs (934100)
  • Dải Rule ID: 25700–25799 (Config Type: MODSEC)
  • Khả năng vá bằng WAF: Rất cao (chặn tuyệt đối các key __proto__, constructor.prototype, prototype trong cả query, form, JSON body và URL).

1. Dấu hiệu tấn công chính cần chặn

  • Key đặc biệt trong JSON body: {"__proto__": {"isAdmin": true}}, {"constructor": {"prototype": {"shell": "/bin/sh"}}}.
  • Key dạng query string/form: ?__proto__[isAdmin]=true, ?__proto__.isAdmin=true, ?constructor[prototype][polluted]=1.
  • Biến thể né lọc bằng Unicode escape trong JSON (\u005f\u005fproto\u005f\u005f) hoặc double URL-encode.

2. Bộ luật ModSecurity v3 mẫu

# [25701] Chặn __proto__ trong tên tham số, giá trị, URI và body thô (gồm JS/Unicode decode)
SecRule REQUEST_URI|ARGS_NAMES|ARGS|REQUEST_BODY "@rx (?i)__proto__" \
    "id:25701,phase:2,pass,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:jsDecode,msg:'ProtoPollution: __proto__ key detected',tag:'prototype-pollution',logdata:'%{MATCHED_VAR_NAME}'"

# [25702] Chặn constructor.prototype hoặc constructor[prototype]
SecRule REQUEST_URI|ARGS_NAMES|REQUEST_BODY "@rx (?i)\bconstructor\b.{0,10}\bprototype\b" \
    "id:25702,phase:2,pass,log,t:none,t:urlDecodeUni,t:urlDecodeUni,t:jsDecode,msg:'ProtoPollution: constructor.prototype detected',tag:'prototype-pollution',logdata:'%{MATCHED_VAR_NAME}'"

# [25703] Chặn key JSON "prototype" dùng trong payload pollution lồng nhau
SecRule REQUEST_HEADERS:Content-Type "@contains application/json" \
    "id:25703,phase:2,pass,log,t:none,t:lowercase,chain,msg:'ProtoPollution: prototype key in JSON body',tag:'prototype-pollution'"
    SecRule REQUEST_BODY "@rx (?i)\"(?:__proto__|prototype)\"\s*:\s*\{" "t:none,t:jsDecode"

3. Giải thích chi tiết từng luật

Rule ID Biến & Transform Cơ chế hoạt động Mức độ an toàn bật deny
25701 REQUEST_URI\|ARGS_NAMES\|ARGS\|REQUEST_BODY (t:urlDecodeUni ×2 + t:jsDecode) Chặn mọi xuất hiện của __proto__ ở bất kỳ vị trí nào (query string, tên tham số, giá trị, JSON body thô), kể cả khi bị mã hóa Unicode \u005f\u005fproto\u005f\u005f. Rất cao
25702 REQUEST_URI\|ARGS_NAMES\|REQUEST_BODY (t:urlDecodeUni ×2 + t:jsDecode) Chặn chuỗi constructor.prototype và constructor[prototype] (khoảng cách tối đa 10 ký tự giữa 2 từ để tránh ReDoS). Rất cao
25703 REQUEST_HEADERS:Content-Type + REQUEST_BODY (t:jsDecode) Chặn riêng cấu trúc JSON "prototype": { ... } lồng object trong request application/json. Rất cao

4. Cách sửa khi gặp trường hợp thực tế (Ví dụ)

Ví dụ 1: Đối thủ gửi JSON nhưng giả mạo Content-Type: text/plain để lách 25703

Lưu ý 25701 và 25702 không phụ thuộc Content-Type nên đã tự bắt được ngay cả khi đối thủ đổi Content-Type: text/plain. Nếu muốn 25703 cũng bắt không cần Content-Type, bỏ dòng chain kiểm tra Content-Type và chỉ giữ dòng kiểm tra REQUEST_BODY:

# Bản sửa thực tế từ [25703] bắt luôn cả khi đối thủ đổi Content-Type: text/plain
SecRule REQUEST_BODY "@rx (?i)\"(?:__proto__|prototype)\"\s*:\s*\{" \
    "id:25703,phase:2,deny,status:403,log,t:none,t:jsDecode,msg:'ProtoPollution: prototype object in body',tag:'prototype-pollution'"

Ví dụ 2: App Node.js dùng cookie JSON có lỗ hổng lodash.merge

Nếu dữ liệu bẩn đi vào qua Cookie (không phải ARGS/REQUEST_BODY), thêm |REQUEST_COOKIES vào đầu biến của 25701: - SecRule REQUEST_URI|ARGS_NAMES|ARGS|REQUEST_BODY|REQUEST_COOKIES "@rx (?i)__proto__" ...

5. Lưu ý tránh False Positive (SVC)

  • __proto__ và constructor.prototype gần như không bao giờ xuất hiện trong traffic bình thường của người dùng hoặc bot SVC — đây là nhóm rule an toàn nhất để bật deny,status:403,log sớm.
