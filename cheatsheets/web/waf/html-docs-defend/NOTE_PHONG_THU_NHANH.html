NOTE PHÒNG THỦ NHANH — F-HACKER 2026 (BẢNG C)

Tờ ghi chú 1 trang mở sẵn trong phòng thi — tổng hợp quy trình đầu trận, thứ tự nạp rule, gỡ FP CRS, xóa header lộ cờ, dải Rule ID và cấp cứu SVC.

1. Quy trình 3 phút đầu trận (Làm đúng thứ tự)

  1. Giữ DetectionOnly, mở Traffic log → bật Live 5s.
  2. Nạp ngay 6 file an toàn (Nhóm 1) từ rules/ (Service: Global, Config Type: MODSEC): - 00_disable_fp_crs.conf (nạp đầu tiên — tắt 920350 Host IP & gỡ FP cookie/JWT) - 01_200xx_recon.conf, 06_205xx_ssrf.conf, 07_206xx_xxe.conf, 08_207xx_deserialization.conf, 09_208xx_crlf_jwt_jndi_proto.conf - Thêm 21200 + 21202 (pass,log) trong 12_212xx_flag_data_leak.conf (tạm comment 21201).
  3. Nhận diện Bot SVC (quan sát 2 chu kỳ = 60 giây): - Nhịp đều ~30 giây/lần, cùng thứ tự endpoint, cùng User-Agent, cột WAF sạch (—), trả 200/302. - Gõ "FHACKER2026{" vào ô tìm kiếm Traffic log → ghi lại route trả cờ hợp lệ của bot. - Ghi lại danh sách route + tên param + định dạng sạch (số/UUID/chuỗi) của bot.
  4. Sửa route & nạp Nhóm 2 (02_201xx, 03_202xx, 04_203xx, 05_204xx, mở lại 21201 sau khi điền đúng route cờ hợp lệ).
  5. Bật chặn: Vào Home → Bật chặn (hoặc Global Settings → ModSecurity → SecRuleEngine = On → Save).
  6. Mốc Round 4 (Mở Level 2 — thêm cờ mới): Tạm đổi 21201 về pass,log trong 2 phút, xem route mới của bot rồi cập nhật lại !@rx trước khi bật deny.

3. Cứu hỏa & Gỡ False Positive CRS (9xxxxx) trong 30 giây

  • Cấp cứu 10 giây khi SVC báo đỏ hàng loạt:
  • Nếu vừa sửa 1 rule → tắt/chuyển rule đó về pass,log → Save.
  • Nếu CRS chặn nhầm chưa rõ rule nào → chuyển tạm SecRuleEngine về DetectionOnly → Save → điều tra status:403 trên Traffic log rồi bật lại On.
  • Gỡ FP CRS (bỏ qua 949110, lấy ID rule ngay phía trên nó): ```apache # Cách 1 — Hẹp nhất: gỡ đúng 1 field trên 1 route (đặt ở Config Type: MODSEC_CRS) SecRule REQUEST_FILENAME "@rx (?i)^/api/notes/?$" \ "id:22000,phase:1,pass,nolog,t:none,t:normalizePath,\ ctl:ruleRemoveTargetById=942100;ARGS:content,\ ctl:ruleRemoveTargetById=942100;ARGS:json.content"

# Cách 2 — Gỡ 1 cookie/header trên toàn site (đặt ở Config Type: MODSEC) SecRuleUpdateTargetById 942440 "!REQUEST_COOKIES:session"

# Cách 3 — Tắt hẳn 1 rule CRS hay báo nhầm (đặt ở Config Type: MODSEC) SecRuleRemoveById 920350 `` - **Xóa Header Debug lộ Flag nhưng giữ nguyên chức năng (302/cookie):** - Tạo config **Config Type: SERVER_HTTP** → dán:proxy_hide_header X-Theme-Debug;→ **Save** → testcurl -i`.

6. 6 bẫy ModSecurity v3 tuyệt đối tránh

  1. JSON có tiền tố json.: Luôn viết ARGS:id|ARGS:json.id (mảng là json.id.array_0).
  2. Không dùng | trong regex tên biến: Viết ARGS:a|ARGS:b, cấm viết ARGS:/a|b/.
  3. Không có # hoặc khoảng trắng sau dấu \ nối dòng.
  4. Dòng con của chain KHÔNG được có id:, phase:, deny, msg:.
  5. Thứ tự transform chuẩn: t:none,t:urlDecodeUni,t:normalizePath (decode trước, normalize sau; không dùng t:normalizePath cho rule tìm ../ trên ARGS).
  6. Không bật tính năng chặn/rate-limit theo IP (vì bot SVC và đối thủ đi chung 1 IP proxy của BTC) và không bật SecTmpSaveUploadedFiles On.
