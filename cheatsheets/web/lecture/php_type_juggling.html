PHP Type Juggling

PHP tự động "ép kiểu" khi so sánh 2 giá trị khác kiểu dữ liệu (chuỗi với số, chuỗi với boolean). Nếu code dùng phép so sánh "lỏng" (== thay vì ===), bạn có thể lợi dụng quy tắc ép kiểu kỳ lạ của PHP để qua được kiểm tra mật khẩu/token/chữ ký mà không cần biết giá trị thật.

Type Juggling là gì, để làm gì?

PHP có 2 kiểu dấu so sánh: == ("lỏng" — tự ép kiểu trước khi so sánh) và === ("chặt" — phải đúng cả giá trị lẫn kiểu dữ liệu). Khi code dùng == để so sánh mật khẩu/token/hash, PHP sẽ tự ý "biến đổi" 2 giá trị khác kiểu để so sánh — và có những quy tắc ép kiểu rất phản trực giác khiến 2 giá trị trông hoàn toàn khác nhau lại được PHP coi là bằng nhau. Bạn lợi dụng điều này để qua xác thực mà không cần biết bí mật thật.

Nếu chỉ nhớ một điều Chuỗi hash dạng 0e123... (toàn chữ số sau 0e) được PHP hiểu là số khoa học (0 × 10^123 = 0), nên MỌI chuỗi 0e-toàn-số khác cũng bằng 0 theo == — 2 hash hoàn toàn khác nhau nhưng cùng dạng "magic hash" này sẽ được PHP coi là bằng nhau.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

So sánh lỏng (==) vs chặt (===) — == cho phép PHP tự "ép kiểu" (type juggling) một hoặc cả hai vế trước khi so sánh (vd chuỗi "ép" thành số). === yêu cầu cả giá trị lẫn kiểu dữ liệu phải giống hệt, không ép kiểu gì cả.
Ký hiệu khoa học (scientific notation) — cách viết số rất lớn/nhỏ, dạng 0e123 nghĩa là 0 × 10^123 = 0. PHP tự nhận ra chuỗi có đúng dạng này (bắt đầu 0e, theo sau toàn chữ số) và coi nó là kiểu số khi so sánh lỏng.
Magic hash — các chuỗi input mà khi hash ra (MD5/SHA1) lại tình cờ có dạng 0e-toàn-số. Ví dụ nổi tiếng: md5("240610708") = 0e462097431906509019562988736854.

Code hay viết (xác thực bằng so sánh lỏng):

// PHP — kiểm tra mật khẩu bằng so sánh hash, dùng ==
$input_hash = md5($_POST['password']);
if ($input_hash == $stored_hash_from_db) {
    // đăng nhập thành công
}
02 / VÌ SAO LỖ HỔNG TỒN TẠI

PHP "thông minh quá mức" khi so sánh khác kiểu

PHP (đặc biệt các bản trước PHP 8) có quy tắc ép kiểu khi gặp == giữa chuỗi và chuỗi trông giống số: nếu cả 2 chuỗi đều được PHP nhận dạng là "số dạng khoa học hợp lệ" (0e<chỉ-toàn-chữ-số>), nó chuyển cả 2 sang kiểu số để so sánh — và vì 0 × 10^bất_kỳ = 0, mọi chuỗi dạng này đều "bằng" nhau khi so sánh lỏng, dù nội dung chuỗi (dãy số sau 0e) hoàn toàn khác nhau.

Tương tự, hàm strcmp($a, $b) (so sánh chuỗi) nếu được gọi với 1 tham số là mảng (PHP <8, hoặc PHP mới không bật error reporting nghiêm) sẽ trả về NULL thay vì ném lỗi dừng chương trình — và NULL == 0 luôn true trong so sánh lỏng, nên if (strcmp($input, $correct) == 0) bị bypass hoàn toàn chỉ bằng cách gửi password[]=x thay vì password=x trong form.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Theo dõi từng bước: vì sao 2 hash khác nhau lại "bằng nhau"

Giải thích chi tiết bằng số thật:

if (md5($_POST['password']) == $stored_hash) { /* login OK */ }
Giả sử $stored_hash trong database là 0e462097431906509019562988736854 (đây là hash THẬT của mật khẩu, bạn không biết mật khẩu gốc).
Bạn gửi password = QNKCDZO. PHP tính md5("QNKCDZO") = 0e830400451993494058024219903391 — một chuỗi hoàn toàn khác, NHƯNG cũng đúng dạng 0e-toàn-số.
Khi so sánh ==, PHP thấy cả 2 vế đều "nhìn giống số khoa học hợp lệ" → tự động chuyển cả 2 sang kiểu float trước khi so → cả 2 đều ra giá trị số 0 → 0 == 0 → true.
Kết quả: đăng nhập thành công dù QNKCDZO không phải mật khẩu thật — chỉ vì hash của nó TÌNH CỜ cùng dạng 0e-toàn-số với hash thật.

C. Tự tính magic hash khi bảng có sẵn không khớp

import hashlib

def find_magic_hash(algo="md5", max_tries=2_000_000):
    """Brute-force tìm input mà hash ra dạng 0e-toàn-số (hiếm khi cần, các input mẫu mục 06 thường đủ dùng)."""
    h = getattr(hashlib, algo)
    for i in range(max_tries):
        s = str(i).encode()
        digest = h(s).hexdigest()
        if digest[:2] == "0e" and digest[2:].isdigit():
            print(f"Tìm thấy: input={i} -> {algo}={digest}")
            return i
    return None

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅Code PHP dùng == (không phải ===) để so sánh hash/token/mật khẩu, hoặc gọi strcmp()/md5() trực tiếp lên input chưa ép kiểu.
