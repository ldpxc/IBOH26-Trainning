Mass Assignment & HTTP Parameter Pollution

Khi server nhận 1 object từ request (form đăng ký, cập nhật hồ sơ) và gán TẤT CẢ field gửi lên thẳng vào bản ghi database — bạn có thể tự thêm field server không mong đợi (như isAdmin: true) để tự nâng quyền. HTTP Parameter Pollution (HPP) là một biến thể: gửi trùng tên tham số nhiều lần để lợi dụng việc các tầng xử lý (WAF, app) đọc giá trị khác nhau.

Mass Assignment & HPP là gì, để làm gì?

Mass Assignment: nhiều framework hiện đại (đặc biệt ORM) có tiện ích "nhận cả object JSON/form rồi tự gán hết vào model" cho nhanh, thay vì lập trình viên tự chỉ định từng field một. Nếu lập trình viên không giới hạn field nào được phép, bạn gửi kèm 1 field "lạ" (không hiện trên giao diện) và nó vẫn được gán thẳng vào bản ghi — kể cả field nhạy cảm như quyền hạn. HTTP Parameter Pollution: gửi cùng 1 tên tham số 2 lần trong 1 request — các thành phần khác nhau (WAF, load balancer, app server) có thể mỗi bên lấy giá trị KHÁC NHAU (cái đầu tiên hay cái cuối cùng), tạo ra khoảng trống để lách luật.

Nếu chỉ nhớ một điều Luôn thử gửi kèm field isAdmin/is_admin/role/admin trong body của BẤT KỲ request tạo/sửa dữ liệu nào (đăng ký, cập nhật hồ sơ) — kể cả khi giao diện không có ô nào cho field đó. Chi phí thử gần như bằng 0, nhiều app dính lỗi này.

⚡ MASS ASSIGNMENT / HPP
🚩 Nhận ra trong 30 giây Có form đăng ký/sửa hồ sơ gửi JSON hoặc form-data. Thêm field "isAdmin": true (JSON) hoặc role=admin (form) vào body → nếu account được tạo/sửa với quyền admin ⟹ Mass Assignment xác nhận.
✅ Tiền đề cần có Có 1 request tạo/sửa bản ghi (đăng ký, cập nhật profile, tạo order). Biết hoặc đoán được tên field nhạy cảm (xem response trả về — thường trả lại nguyên object, lộ tên field thật).
🔍 Dò nhanh bằng Burp Repeater: thêm field nghi ngờ vào body, Send, kiểm tra Response (object trả về) có field đó không và giá trị có đúng như bạn gửi không.
💥 Payload dán-chạy-ngay 
// 1. Mass Assignment qua JSON (thêm field server không mong đợi)

# 2. HTTP Parameter Pollution (gửi trùng tên tham số)

# 3. Mass Assignment lồng (nested, khi server dùng ORM tự động sâu hơn)
{"username":"x","profile":{"role":"admin"}}

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Model / ORM — lớp code đại diện cho 1 bảng database (vd model User có các field username, password, is_admin). ORM (Object-Relational Mapping) là thư viện giúp thao tác database thông qua object thay vì viết SQL tay.
Mass assignment (gán hàng loạt) — tính năng tiện lợi của nhiều ORM: nhận 1 dict/object rồi tự gán mọi key khớp tên field vào model cùng lúc, ví dụ Python User(**request.json) hoặc một số ORM có hàm update_from_dict().
HTTP Parameter Pollution (HPP) — gửi cùng 1 tên tham số nhiều lần trong URL/body (?role=user&role=admin). Mỗi ngôn ngữ/framework có quy tắc khác nhau khi gặp trường hợp này: một số lấy giá trị đầu tiên, số khác lấy cuối cùng, số khác gộp thành mảng.

Code hay viết (tiện lợi nhưng nguy hiểm):

# Python/Flask — nhận toàn bộ JSON rồi tạo user, KHÔNG lọc field nào được phép
data = request.get_json()
user = User(**data)   # nếu data có "is_admin": true, field này cũng được gán!
db.session.add(user)
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Tiện lợi cho lập trình viên = nguy hiểm cho bảo mật

Viết User(**data) nhanh gọn hơn nhiều so với liệt kê tay từng field (User(username=data['username'], password=data['password'])) — nhất là khi model có nhiều field. Lập trình viên (đặc biệt làm nhanh cho demo/CTF) hay chọn cách viết tắt này mà quên rằng object request hoàn toàn do người dùng kiểm soát — họ có thể gửi bất kỳ key nào, không chỉ những key có ô nhập trên giao diện.

Với HPP, nguyên nhân là không có chuẩn thống nhất trong đặc tả HTTP về việc tham số trùng tên nên xử lý thế nào — mỗi ngôn ngữ/framework tự quyết định, dẫn tới việc 2 tầng xử lý khác nhau trong cùng hệ thống (vd WAF kiểm tra giá trị đầu, app thực sự dùng giá trị cuối) có thể "nhìn thấy" 2 giá trị khác nhau của cùng 1 tham số.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Thêm 1 field lạ, server tự gán vào database

Điểm quan trọng: bạn không cần biết tên field chính xác 100% ngay từ đầu — Response của request tạo/sửa thường trả lại nguyên object vừa tạo (kể cả field bạn không gửi), giúp bạn "nhìn trộm" được tên field thật để thử lại chính xác ở request tiếp theo. Đây là kỹ thuật dò field bằng chính response của app, không cần công cụ ngoài.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Bước 1-2 — bắt request đăng ký, thêm field
  1. Burp bắt request đăng ký/sửa hồ sơ bình thường.
  2. Send to Repeater, thêm field nghi ngờ vào JSON body: "isAdmin": true (lưu ý: phải đúng cú pháp JSON hợp lệ — thêm dấu phẩy đúng chỗ).
  3. Send, đọc Response — xem field đó có xuất hiện trong object trả về với đúng giá trị true không.
Thử HPP Trong Repeater, thêm tham số trùng tên: role=user&role=admin — Send, kiểm tra kết quả. Thử luôn thứ tự ngược lại (role=admin&role=user) vì có framework lấy giá trị đầu, có framework lấy giá trị cuối.

(B) Bản gọn chắc — thử nhiều tên field, trích thẳng flag

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
FIELD_NAMES = ["isAdmin", "is_admin", "admin", "role"]

def exploit_mass_assignment(host):
    for field in FIELD_NAMES:
        data = {"username": f"pwn_{field}", "password": "pwn123", field: True if field != "role" else "admin"}
        r = requests.post(f"http://{host}/register", json=data, timeout=5)
        # đăng nhập lại ngay, xem trang admin có hiện flag không
        s = requests.Session()
        s.post(f"http://{host}/login", json={"username": data["username"], "password": "pwn123"}, timeout=5)
        check = s.get(f"http://{host}/admin", timeout=5)
        m = FLAG_RE.search(check.text)
        if m:
            return m.group()
    return None

print("FLAG:", exploit_mass_assignment("TARGET_IP"))

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App dùng ORM mass-assign trực tiếp từ request (Model(**data), Model.update(request.json)) không lọc field.

13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng ví dụ mục 09 bằng tay trên Burp, từ đăng ký thường tới khi tạo được tài khoản admin.

Gợi ý nếu kẹtNhớ đọc kỹ Response của lần đăng ký ĐẦU TIÊN (chưa thêm field lạ) để tìm tên field thật trước khi đoán mò.

⭐⭐ Đổi 1 biến: field is_admin ở cấp top-level bị chặn (request báo lỗi). Thử Mass Assignment lồng qua object profile.

Gợi ý nếu kẹt{"username":"x","password":"y","profile":{"is_admin":true}} — nhiều ORM chỉ validate field cấp 1, bỏ qua field bên trong object lồng.

⭐⭐⭐⭐ Tự nghĩ: endpoint có WAF chặn chuỗi "is_admin" trong body. Nghĩ 2 cách khác nhau để vẫn gán được quyền admin mà không gửi đúng nguyên văn chuỗi đó.

Gợi ý nếu kẹt(1) Thử tên field khác có cùng tác dụng (role, permissions); (2) thử Unicode/case khác nếu WAF so khớp chữ thường tuyệt đối ("Is_Admin", dù ORM có thể không phân biệt hoa thường tùy ngôn ngữ).
