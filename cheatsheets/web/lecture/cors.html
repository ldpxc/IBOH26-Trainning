CORS Misconfiguration

CORS là cơ chế cho phép 1 trang web xin phép đọc dữ liệu từ domain khác. Khi server cấu hình sai — phản chiếu lại origin bất kỳ kèm cho phép gửi cookie — trang độc của bạn có thể đọc được dữ liệu riêng tư của nạn nhân từ domain đích, điều mà CSRF (chỉ gửi, không đọc được) không làm được.

CORS Misconfiguration là gì, để làm gì?

Mặc định, trình duyệt chặn JavaScript của 1 trang đọc response từ domain khác (Same-Origin Policy). CORS (Cross-Origin Resource Sharing) là cơ chế để server chủ động nới lỏng quy tắc này cho những domain được tin cậy, qua header Access-Control-Allow-Origin. Nếu server cấu hình sai — phản chiếu lại bất kỳ origin nào gửi lên thay vì so khớp 1 danh sách cố định, VÀ kèm Access-Control-Allow-Credentials: true — trang của bạn (origin bất kỳ) có thể gửi request kèm cookie nạn nhân và đọc được response, không chỉ gửi mù như CSRF.

Nếu chỉ nhớ một điều Luôn gửi header Origin: https://evil.com (domain bất kỳ, không liên quan) tới API đích, xem response có header Access-Control-Allow-Origin: https://evil.com (phản chiếu lại đúng y hệt domain giả bạn gửi) không — nếu có, kèm thêm Access-Control-Allow-Credentials: true ⟹ lỗ hổng xác nhận.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Same-Origin Policy (SOP) — quy tắc mặc định của trình duyệt: JavaScript của trang A chỉ đọc được response/dữ liệu của chính domain A, không đọc được của domain B — dù vẫn GỬI được request tới B (đây là điều CSRF lợi dụng, còn CORS misconfig lợi dụng việc ĐỌC được).
CORS (Cross-Origin Resource Sharing) — cơ chế HTTP header để server B "cấp phép" cho 1 số domain cụ thể được phép đọc response của nó, vượt qua SOP mặc định.
Access-Control-Allow-Origin (ACAO) — header server trả về, liệt kê domain nào được phép đọc response này. Giá trị * (mọi domain) KHÔNG cho phép gửi kèm credentials (trình duyệt tự chặn kết hợp này) — vì vậy lỗ hổng thật sự nguy hiểm là khi server phản chiếu (reflect) đúng giá trị Origin người gửi thay vì để * hay 1 domain cố định.
Access-Control-Allow-Credentials (ACAC) — header true/false, quyết định trình duyệt có gửi kèm cookie/session khi thực hiện request cross-origin hay không.

Code hay viết sai:

// Node/Express -- phản chiếu MỌI origin gửi lên, không so khớp whitelist
app.use((req, res, next) => {
  res.header('Access-Control-Allow-Origin', req.headers.origin);   // !! lấy thẳng từ request
  res.header('Access-Control-Allow-Credentials', 'true');
  next();
});
02 / VÌ SAO LỖ HỔNG TỒN TẠI

Lập trình viên "tiện tay" phản chiếu origin thay vì whitelist

Khi app cần hỗ trợ CORS cho nhiều domain khác nhau (vd app có nhiều subdomain, hoặc muốn hỗ trợ cả localhost lúc dev), cách viết đúng là so khớp origin gửi lên với 1 danh sách cố định rồi mới set ACAO bằng đúng giá trị đó nếu khớp. Cách viết sai nhưng nhanh gọn (hay gặp ở code dựng vội) là lấy thẳng req.headers.origin rồi set lại y hệt — "coi như luôn khớp" — khiến MỌI domain, kể cả domain của kẻ tấn công, đều được chấp nhận là "đã whitelist".

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

So sánh: CSRF (chỉ gửi) vs CORS misconfig (gửi VÀ đọc được)

Khác biệt cốt lõi so với CSRF: CSRF chỉ hữu dụng với hành động GHI (đổi mật khẩu, chuyển tiền) vì bạn không cần biết kết quả, chỉ cần request được thực thi. CORS misconfig mở ra khả năng ĐỌC dữ liệu — lấy được thông tin cá nhân, token, hay chính flag nếu nó nằm trong response của 1 API riêng tư nào đó.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Dò phản chiếu Origin trong Repeater
  1. Bắt request API trả dữ liệu nhạy cảm, Send to Repeater.
  2. Thêm/sửa header Origin: https://subdomain-test-12345.com (domain lạ, dễ nhận ra trong response).
  3. Send, xem Response Headers: nếu Access-Control-Allow-Origin trả về đúng y hệt chuỗi lạ đó ⟹ xác nhận phản chiếu.
  4. Kiểm tra tiếp có Access-Control-Allow-Credentials: true không — thiếu dòng này thì không khai thác được (trình duyệt tự chặn gửi cookie dù ACAO hợp lệ).
06 / PAYLOAD ĐẦY ĐỦ THEO BIẾN THỂ

Các kiểu cấu hình sai hay gặp

A. Phản chiếu origin bất kỳ (phổ biến nhất)

Origin: https://anything-at-all.com
# -> Response: Access-Control-Allow-Origin: https://anything-at-all.com

B. Whitelist lỏng lẻo theo string match

App check (sai)Bypass bằng
origin.endsWith('target.com')https://evil-target.com (kết thúc đúng chuỗi nhưng là domain khác)
origin.includes('target.com')https://target.com.evil.com hoặc https://evil.com/target.com
origin.startsWith('https://target.com')https://target.com.evil.com

C. Chấp nhận null origin

Một số app coi origin null (xảy ra khi request tới từ iframe sandbox, file file:// local, hoặc redirect) là hợp lệ — tạo trang PoC trong iframe có sandbox attribute để trình duyệt tự gửi Origin: null:

10 / PHÒNG THỦ: VIẾT WAF RULE

Khó áp dụng — đây là lỗi ở RESPONSE header, không phải request

Giới hạn đặc thùHầu hết WAF hoạt động theo mô hình kiểm tra request đi vào, không kiểm tra/sửa response đi ra. CORS misconfig nằm ở lỗi logic server tự set sai header response — WAF đứng trước app khó can thiệp vào bước này trừ khi nó hỗ trợ sửa response (reverse proxy có thể làm, tùy nền tảng WAF của BTC).

Nếu UI WAF hỗ trợ sửa/chặn response: cân nhắc rule chặn (hoặc ghi đè) response có Access-Control-Allow-Origin khác với domain cố định hợp lệ của chính service. Nếu không hỗ trợ, nhóm lỗ hổng này gần như không phòng thủ được trong khuôn khổ A/D (giống IDOR, Race Condition).

12 / NHẬN DIỆN & GIỚI HẠN

Khi nào ĐƯỢC / KHÔNG dùng

Tình huống
✅Server phản chiếu Origin (hoặc whitelist lỏng lẻo) VÀ Access-Control-Allow-Credentials: true VÀ endpoint trả dữ liệu nhạy cảm cần auth.
❌ACAO là wildcard * thật (không kèm credentials được theo chuẩn).
❌Server dùng whitelist domain nghiêm ngặt, so khớp đúng (parse domain thật, không phải string match lỏng).
❌Endpoint không cần cookie/session để trả dữ liệu (vốn đã public, không có gì để "đánh cắp" thêm).

Thuật ngữ

CORSCross-Origin Resource Sharing — cơ chế header cho phép JS đọc response cross-origin có kiểm soát.
ACAO / ACACAccess-Control-Allow-Origin / Access-Control-Allow-Credentials — 2 header quyết định origin nào được đọc response, có kèm cookie hay không.
Reflect originLỗi cấu hình: server lấy thẳng giá trị Origin request gửi lên rồi gán lại y hệt vào ACAO.
Null originGiá trị Origin đặc biệt khi request tới từ ngữ cảnh "không origin rõ ràng" (sandboxed iframe, file local).
