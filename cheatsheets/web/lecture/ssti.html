Server-Side Template Injection (SSTI)

Khi trang web dùng "template" (khuôn mẫu HTML có chỗ trống để điền dữ liệu) và lỡ coi dữ liệu bạn gõ vào như một phần của chính khuôn mẫu đó — bạn có thể viết code vào chỗ lẽ ra chỉ là text, và server sẽ "biên dịch" code đó, có thể dẫn tới chạy lệnh tùy ý trên máy chủ.

00 / TÓM TẮT 1 PHÚT

SSTI là gì, để làm gì?

Nhiều framework web (Flask, Django, Spring...) dùng template engine để dựng trang HTML: viết sẵn một "khuôn" với chỗ trống {{ }}, rồi điền dữ liệu thật vào chỗ trống đó lúc chạy. Nếu server lỡ lấy chữ bạn gõ ghép thẳng vào chính cái khuôn (thay vì chỉ điền vào chỗ trống), template engine sẽ coi chữ bạn gõ là một phần của khuôn — và "biên dịch" (compile) nó như code thật. Với nhiều engine, từ đó leo thang được tới chạy lệnh hệ thống tùy ý.

Nếu chỉ nhớ một điều Dấu hiệu nhận biết kinh điển: gõ {{7*7}} vào ô input, nếu trang hiện ra số 49 (thay vì in nguyên văn {{7*7}}) — nghĩa là server đã tính toán chữ bạn gõ như code, không chỉ hiển thị như text. Đó chính là SSTI.
⚡ COMBAT CARD — đọc trước, đủ để khai thác ngay
⚡ SERVER-SIDE TEMPLATE INJECTION
🚩 Nhận ra trong 30 giây Gõ {{7*7}} vào ô input bất kỳ (tên, bio, tìm kiếm...) → trang hiện 49 thay vì {{7*7}} ⟹ chắc chắn SSTI. Thử thêm ${7*7}, #{7*7}, <%= 7*7 %> nếu cú pháp {{ }} không ăn (engine khác).
✅ Tiền đề cần có Input của bạn được đưa thẳng vào template string (không phải chỉ vào biến dữ liệu). Biết được server chạy ngôn ngữ/framework nào (xem header Server, cookie, trang lỗi — xem bài recon).
🔍 Dò engine bằng Burp Repeater, gửi lần lượt payload dò ở mục 04. Payload nào ra kết quả đúng công thức toán học (hoặc ra lỗi đặc trưng) sẽ lộ chính xác engine đang chạy.

01 / NỀN TẢNG BẮT BUỘC

Những thứ cần hiểu trước

Template (khuôn mẫu) — một file HTML có sẵn "chỗ trống" để điền dữ liệu, ví dụ: <h1>Xin chào, {{ ten }}!</h1>. Khi chạy, server thay {{ ten }} bằng giá trị thật (vd "Nam") để ra <h1>Xin chào, Nam!</h1>.
Template engine — chương trình đọc file template, tìm các chỗ {{ }}, và "biên dịch" (compile) những gì bên trong như một đoạn code thật của ngôn ngữ đó (không chỉ thay chuỗi đơn giản) — ví dụ Jinja2 (Python/Flask) cho phép viết cả phép tính, gọi hàm, truy cập thuộc tính object bên trong {{ }}.
RCE (Remote Code Execution) — chạy được lệnh hệ thống tùy ý từ xa. Vì template engine vốn được phép chạy code Python/Java/PHP thật bên trong {{ }}, nếu kiểm soát được nội dung đó, ta kiểm soát luôn code chạy trên server.

Ví dụ: trang web có chức năng chào hỏi theo tên, code phía sau (kiểu hay gặp trong challenge) ghép input thẳng vào chuỗi template trước khi đưa cho engine xử lý:

# Python/Flask
name = request.args.get("name")
return render_template_string(f"<h1>Xin chào, {name}!</h1>")

Cách làm đúng (an toàn) là truyền name như một biến dữ liệu cho template cố định sẵn (render_template_string("Xin chào, {{ name }}!", name=name)) — lúc đó name chỉ được thay thế, không bao giờ được biên dịch. Challenge CTF thường cố ý viết sai như ví dụ trên để tạo lỗ hổng.

02 / VÌ SAO LỖ HỔNG TỒN TẠI

Template string không phân biệt được "dữ liệu" với "code của khuôn"

Khi dòng code f"<h1>Xin chào, {name}!</h1>" chạy, Python ghép name (giả sử bạn gửi {{7*7}}) vào, ra chuỗi:

<h1>Xin chào, {{7*7}}!</h1>

Chuỗi HTML này sau đó mới được đưa cho Jinja2 xử lý qua render_template_string(). Jinja2 không hề biết {{7*7}} này vốn là dữ liệu người dùng gửi — với nó, mọi {{ }} trong chuỗi đều là chỗ cần tính toán/biên dịch. Nó thấy {{7*7}}, hiểu đó là phép nhân, tính ra 49, rồi thay vào. Kết quả trang hiện "Xin chào, 49!".

Vì Jinja2 cho phép bên trong {{ }} không chỉ phép tính mà còn truy cập thuộc tính Python (như object.__class__) và gọi hàm, nếu bạn viết đúng chuỗi, bạn có thể "đi" từ một con số vô hại tới tận object os của Python và gọi os.popen() — y hệt việc viết code Python thật.

03 / CƠ CHẾ HOẠT ĐỘNG ← MỤC LÕI

Từ 7*7 tới RCE: "đi bộ" qua object Python

Giải thích từng mảnh của payload (ví dụ Jinja2):

{{ ''.__class__.__mro__[1].__subclasses__() }}
'' — một chuỗi rỗng bất kỳ, chỉ dùng làm "bàn đạp" để lấy kiểu dữ liệu str (có thể thay bằng bất kỳ giá trị nào luôn tồn tại trong template, như số 7).
.__class__ — thuộc tính có trên mọi object Python, cho biết object đó thuộc lớp (class) nào. ''.__class__ là <class 'str'>.
.__mro__ — danh sách các lớp cha mà str kế thừa (Method Resolution Order). Phần tử [1] luôn là lớp object — lớp gốc của mọi class trong Python.
.__subclasses__() — gọi trên object sẽ liệt kê mọi lớp con đã được nạp vào bộ nhớ của chương trình — trong đó có rất nhiều lớp hữu ích như subprocess.Popen, os._wrap_close.
Response mong đợi: một danh sách rất dài các class, dạng [<class 'type'>, <class 'weakref'>, ..., <class 'subprocess.Popen'>, ...] — bạn cần đếm vị trí (index) của subprocess.Popen trong danh sách đó để dùng ở bước tiếp theo.

Bước tiếp theo — gọi thẳng class đó với lệnh muốn chạy (giả sử tìm được nó ở index 396, số này khác nhau tùy phiên bản Python/thư viện đã load, phải tự đếm lại mỗi lần):

{{ ''.__class__.__mro__[1].__subclasses__()[396]('cat flag.txt', shell=True, stdout=-1).communicate() }}
Thành thật về giới hạnChỉ số [396] KHÔNG cố định — nó phụ thuộc bản Python, các thư viện đã import trong app đó. Luôn phải tự dò lại bằng cách in danh sách __subclasses__() ra trước rồi đếm, hoặc dùng payload ngắn hơn ở mục 06 (qua cycler/ lipsum) để khỏi phải đếm index.

05 / KHAI THÁC BẰNG BURP SUITE

Bấm gì (từng bước)

Bước 1 — bắt request, thử payload dò
  1. Burp Proxy bật Intercept, dùng chức năng (form nhập tên/bio/comment) với giá trị thường.
  2. Chuột phải request → Send to Repeater.
  3. Sửa giá trị tham số thành {{7*7}}, Send, đọc Response: thấy 49 xuất hiện đúng vị trí tên bạn gõ ⟹ xác nhận SSTI.
Bước 2 — leo thang dần, không nhảy thẳng payload dài
  1. Thử {{7*'7'}} để xác định chính xác Jinja2 hay Twig.
  2. Thử {{ ''.__class__ }} — nếu Response hiện <class 'str'>, bạn biết chuỗi __class__ không bị lọc, có thể đi tiếp.
  3. Thử {{ ''.__class__.__mro__ }}, rồi .__subclasses__() — mỗi bước Send và đọc kỹ Response trước khi thêm bước tiếp, để biết chính xác chỗ nào bị chặn nếu có lỗi.
Vì sao làm từng bước: payload RCE đầy đủ rất dài, nếu 1 ký tự bị lọc/sai mà bạn gửi nguyên cục, bạn không biết lỗi nằm ở đâu. Build dần trong Repeater giúp cô lập đúng chỗ hỏng.
