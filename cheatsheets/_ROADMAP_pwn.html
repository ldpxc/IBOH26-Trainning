Kiến trúc & ABI

Cùng kỹ thuật, khác chi tiết theo kiến trúc

Mọi kỹ thuật trong roadmap đều áp dụng được cho nhiều kiến trúc — nhưng bốn thứ thay đổi: (1) tham số hàm truyền ở đâu, (2) cách gọi syscall + số hiệu, (3) kích thước con trỏ & endianness (chọn p32 hay p64), (4) gadget. Học x86-64 trước, rồi ánh xạ sang kiến trúc khác bằng bảng này.

Mẹo công cụ: đặt context.arch='aarch64' / 'arm' / 'mips' / 'i386' trong pwntools là tự đổi p32/p64, shellcraft, assembler. Chạy binary khác kiến trúc bằng qemu-user + gdb-multiarch.

Kết hợp kỹ thuật (combos)

Trái tim của pwn thực chiến

Một challenge khó hiếm khi là một kỹ thuật đơn. Nó là một chuỗi: lỗi → primitive (đọc/ghi) → leak → điều khiển luồng → RCE. Dưới đây là các chuỗi kinh điển bạn phải thuộc như phản xạ.

1 · Có leak → ret2libc (nền tảng)

overflow → leak libc (puts@plt(puts@got)) → tính base → ret: system("/bin/sh") / one_gadget

Combo đầu tiên mọi người học. Khóa học: Phase 2.

2 · Không có leak → ret2dlresolve hoặc ret2csu→leak

overflow → stage1 read khối giả vào .bss → ret2dlresolve → system  |  hoặc ret2csu set rdi/rsi/rdx → leak → ret2libc

Khi binary câm, không in gì để leak. Phase 2.

3 · Overflow nhỏ → stack pivot → ROP dài

overflow chỉ đủ 2–3 gadget → pivot (leave;ret / pop rsp) về .bss/heap đã nạp sẵn → chạy ROP chain dài

Khi không gian tràn hẹp. Phase 2 (+ setcontext để pivot mạnh hơn).

4 · Format string → leak tất + ghi

%p/%s leak canary + libc + PIE cùng lúc → %n ghi GOT / return addr / fini_array → RCE

Fmt vừa là mắt đọc vừa là tay ghi. Phase 3.

5 · Heap cổ điển (có hook, ≤2.33) → tcache poison → hook

UAF/overflow → tcache poisoning ghi fd → malloc trả về __free_hook → đặt system → free("/bin/sh")

Đường nhanh trên glibc cũ. Phase 4D.

6 · Heap hiện đại (hookless, 2.34+) → FSOP

UAF → leak libc (unsorted bin) → tcache poison _IO_2_1_stdout_ → House of Apple 2 (FSOP) → system

Khi __free_hook/__malloc_hook đã bị xóa. Phase 4F–4G. Đây là combo "mặc định" của CTF hiện đại.

7 · Leakless heap (không leak nổi)

House of Water / Tangerine khống chế tcache_perthread_struct → bypass safe-linking → FSOP không cần leak

Khi binary không cho leak bất cứ gì. Phase 4H — đỉnh của heap.

8 · Dưới seccomp → ORW

RCE nhưng bị chặn execve → ROP/heap → mprotect vùng shellcode → open/read/write flag (ORW)

Đọc filter bằng seccomp-tools trước. Phase 5.

9 · Blind (không có binary)

BROP: brute canary → tìm stop/brop gadget → leak .text → dump binary remote → ret2libc

Chỉ có service remote, không file. Phase 5.

10 · Kernel: UAF → cross-cache → đối tượng mạnh → root

UAF slab → cross-cache reclaim thành pipe_buffer / msg_msg → arbitrary RW → ghi modprobe_path / đổi cred → root

Mẫu kernel CTF hiện đại. Phase 6.
